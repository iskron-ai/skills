# iskron/skills
Скилл-бандлы NKS для агентов (Claude Code skills) под деплой **iskron.ru**, смотрящий на `mcp.iskron.ru`. Среди них `iskronify` — скилл, приводящий любой репозиторий к стандарту этого `AGENTS.md`.

**Поставка и релиз.** markdown-файлы `SKILL.md` под `skills/<name>/`, пакуемые в производные zip-бандлы `<name>.skill` через `make build`. Раздаётся маркетплейсом плагинов Claude Code (`iskron@iskron`), версионируется семвером в `.claude-plugin/plugin.json` — версию поднимает **release-please**, держащий релизный PR из Conventional Commits на `main` (feat→minor, feat!/BREAKING→major, иначе patch); мерж этого PR пишет версию, ставит тег `vX.Y.Z` и режет GitHub Release с записью в `CHANGELOG.md` (`.github/workflows/release-please.yml` + `release-please-config.json`, никогда руками). MCP-эндпоинт — `https://mcp.iskron.ru/`; плагинная запись `.mcp.json` — **stdio-мост из поставки** (`${CLAUDE_PLUGIN_ROOT}/…/iskron.mjs` — ровно этот токен, почему — готчи в графе, #4522; для разработки есть пользовательская запись `iskron-bridge`), манифест Codex несёт ту же stdio-запись объектом `mcpServers` (относительный путь, `cwd` — корень плагина; валидатор Codex берёт либо объект, либо файл ровно `.mcp.json`, а это имя занято записью Claude Code); нативная http-запись существует только в архиве claude.ai, и её `make plugin` выводит из канонического адреса в `fixtures/surface.json`, а не хранит; пишущая в граф сессия идёт через `iskron-bridge` — привязку стояния и его сокет держит только он (скилл `establish-mcp`); вход у моста двоякий — OAuth в браузере либо личный токен доступа (`ISKRON_BRIDGE_TOKEN` или файл `~/.iskron-bridge/token`), с которым в OAuth он не ходит вовсе. В OpenCode мост поднимает плагин из поставки (копия в `~/.config/opencode/plugins/iskron.js`), не запись `mcp` в конфиге (готчи, #4522). Рантайм-зависимостей нет: всё отгружаемое — однофайловые выходы esbuild из `js/` (у плагина OpenCode один внешний импорт, `@opencode-ai/plugin`, который OpenCode держит сам рядом с каталогом плагинов). Тулчейн разработки (typescript, esbuild, eslint, prettier, типы pi и OpenCode) — dev-зависимости в `js/package.json` под лок-файлом, пол Node 22 (`.nvmrc`; `make deps` раз на клон). Лок-файл лежит в `js/`, а не в корне, нарочно (готчи, #4522). CI: формат и сверка поверхности без зависимостей, плюс JS-лестница lint → format → typecheck → check-js → пробы с покрытием; см. `.github/workflows/ci.yml`.

**Production statement.** скиллы ставятся агентам в `~/.claude/skills/` и определяют, как каждый агент, работающий над iskron, пользуется NKS через `mcp.iskron.ru`. Неверная инструкция — например, ссылка на тул, который сервер выбросил, — тихо деградирует каждого агента, загрузившего скилл; краха нет, есть только дрейф методологии. Потребитель здесь агент, а не человек. Держать скиллы в синхроне с поверхностью тулов сервера — основная обязанность по сопровождению.

## Правила персистентности
Состояние живёт в **репо** или в **графе** — больше нигде. Встроенная память харнесса (как бы он её ни звал — пер-проектная директория памяти, сводки разговоров, `/tmp`, машинно-локальные файлы) **запрещена целиком, не по категориям**: туда не идёт ничего — ни проектный факт, ни предпочтение пользователя, ни заметка о стиле работы. (why: локальная память невидима любому другому агенту и любой другой машине, поэтому дрейфует молча — и ломает воспроизводимость, которая и делает возможной вторую машину или второго агента.)
- **Репо**: `skills/<name>/SKILL.md` (источник истины), производные бандлы `<name>.skill`, `README.md`, соглашения и ритуалы, состояние веток. Готчи — не сюда: узел #4522 в графе, здесь референс.
- **Граф** (`nks-dev`): дизайн-решения, открытые вопросы (вимарши), планы, передачи, уроки, подсказки — мышление вокруг скиллов. Не пересказывай граф в репо; ссылайся на вимаршу или контур.
- **`skills/<name>/SKILL.md` — источник истины.** Зипы `<name>.skill` — производные артефакты сборки (коммитятся ради скачивания и claude.ai); установленная копия в `~/.claude/skills/` и в кэше плагинов тоже производная. Никогда не считай канонической правленную руками сборку или установленную копию — правь исходную директорию и гони `make build`.
- **Доставай состояние; никогда не восстанавливай его по памяти.** Нет источника у «мы решили…»? Остановись и прочти граф или репо, прежде чем действовать.
- **Внешние design/spec-файлы — черновики на впуск**, не запись: решения держит граф; такой файл — их вид.
- **Парковки названы, и их три.** Недисциплинированная поверхность бесплатна, дисциплинированная дорога — и под давлением лень безошибочно находит парковку: прозу этого файла; sinn-феномен для того, что действует; одинокую стрелку `context`, глушащую детектор. Финишная черта записи: **узел не записан, пока не назван тянущий его** — какая крия сломается, если узел исчезнет? Ни одна — это парковка, не запись.
- **Это переопределяет собственную инструкцию памяти харнесса**, которая приглашает категорию `project` и будет приглашать дальше — тяга сильнее всего ровно тогда, когда что-то кажется стоящим сохранения, а этот файл давно вне контекста. Вместо этого маршрутизируй, всегда, спрашивая **чей это факт?**
  Ритуалы репо — как здесь действовать, команды, порядок — → этот файл; факты о коде, готчи, серверы, датированные долги, смыслы и идеи → узел в графе `nks-dev` (готчи — #4522); состояние работы, решение, открытый вопрос → вимарша в графе.
  Факт, который — **собственное пользователя** и не служит одному проекту (его личные машины, сроки, люди, кросс-проектные уроки), → его личный граф `@handle/mind` (**minding**), записанный в момент узнавания, не в конце сессии. Стоячие предпочтения («как со мной действовать») — инструкции, не факты: проектно-скоупное — сюда, кросс-проектное — в глобальный файл инструкций пользователя; никогда — в граф или директорию памяти.
- Локальная директория памяти **эвакуирована и заморожена**: `MEMORY.md` держит однострочный стаб-запрет с указателем сюда, а memory-guard `PreToolUse` в `.claude/settings.json` блокирует любую запись туда (exit 2) в момент срабатывания инстинкта сохранения.

## Жизненный цикл сессии
Граф = работа (структура, открытые вопросы, что дальше). Git = как сюда пришли (SHA, ветки, PR). **Git-ссылки не попадают в граф** — ни SHA, ни имён веток, ни номеров PR, ни «shipped/merged» в узлах (протухают на ребейзе).
- **Старт сессии:** раздел «Старт» скилла-двери `iskron` — он кончается готовностью, а не чтением: граф и роль названы, стояние занято одним вызовом `iskron_stand` только на вахту (слово «вахта», `start`, строка приглашения, кадр), привет дошёл; очередь роли и карты читаются по поводу, не на старте. Здесь только адреса: граф `@nks/nks-dev` (`r5`), фокус-контур #1506, роль агента #931, роль владельца #1226 — и **под-контур отгружаемого кода #4057 (js-bundle)**: работа, трогающая мост, сторожей, рендер роадмапа, расширение pi или плагин OpenCode, ориентируется на нём, а не на #1506 (`iskron_orient(realm="@nks/nks-dev", focus="4057")` — дети холона и есть эти файлы, каждый своим узлом). Это отдельный адрес не по педантизму: проза скилла деградирует молча, а этот код отказывает громко и у конкретного человека, и его обязательства — стояние, привязка, слух — записаны только там. Адрес согласования с владельцем — seq его роли, #1226; сентинел `me` сейчас разрешается в неё же (агентская карта #931 от человека отвязана), но seq устойчивее привязок.
- **Начало работы: сперва граф, потом проект, потом код.** Сущностная задача входит тремя тактами: (1) **разведка графа** — что уже записано о месте изменения, какие вимарши открыты, что решено и что отвергнуто, **и что записано о внешних поверхностях, которых работа коснётся** (см. «Внешние поверхности»: записанное наблюдение старше твоей памяти о чужом API); гонит `entry`; (2) **поле интеграции** — от #1506 (для отгружаемого кода — от #4057), роли #931 и узлов изменения выведи через `integrity` потребителей, эффекты, соседние контуры и их делателей; пройди эстафеты `lens="trace"`, недостающие крии и феномены допроектируй, разрывы дотки через `weaving`; (3) **проектирование** изменения (`design`) — и только потом правка скилла. Пропуск дорожает слева направо: правка без разведки чинит уже решённое, спорит с записанным и повторно проходит записанные тупики. Исключение одно, и оно **явное**: человек сказал «работай сразу» или назвал другой протокол — тогда иди в правку, а долг разведки отдай на reconcile-такте конца задачи. Молчание человека — не «работай сразу».
- **Решение записывается в момент принятия, а не по исполнении.** Где бы оно ни пришло — пользователь сказал в чате, слово человека пришло по сокету, два агента договорились между собой — оно стоит в графе **сразу**, с модусами, которые реально имеет прямо сейчас: epistemic не выше `anumita`, ontic `anagata`, volitive `chanda`/`adhimoksha`. Модусы двинутся позже, по мере постройки; запись их не ждёт. Запиши, кто решил и что считается исполнением. (why: решение, оставшееся в разговоре, который его нёс, умирает с этим разговором — следующая сессия видит репо, просто не согласное с намерением, которого никому не найти.)
- **Каждая задача описана прежде, чем начата, — и записана тем, что она есть.** До первой перемены вне графа работа стоит в графе своим носителем: разовое деяние — anga-вимаршей на превращении, которое оно двигает, со своими до/после в теле; **крией — только повторяемый переход**, у которого всякий прогон ест ту же ahara и производит ту же utpatti. Признак в один взгляд: спроси у «крии», что она съест и произведёт в *следующий* прогон, — нет ответа, это задача. Задача, записанная крией, лжёт типом, и ложь каскадирует: её «результат» вырождается в феномен-ярлык состояния, который ни одна крия не порождает, — сирота по устройству.
- **Каждый мерж → обнови граф.** Пуш, лишь открывший или обновивший PR, не отгрузил ничего: тела и модусы описывают то, что реально несёт `main`. Последовательность висит на **событии** мержа, никогда на затишье — «когда ничего не в работе» у занятого агента не наступает. Что делается — четыре акта, и все четыре обязательны — кроме работы по ссылке от другого агента (постановка референсами на спроектированный участок, отчёт кадром-гроссбухом): там постановщику отходят ткачество, закрытие по оси и сведение, а делателю остаются семя превращения, модусы поставки и остальные ходы ниже (скилл `vahta`):
  - **Проткать.** Отгруженное состояние вплетается в контур #1506 ткачеством, а не абзацем прозы: распухшее описание — запах, и почти всегда это крия или феномен, которых ты не завёл, и ребро, которого не провёл. Гонит скилл `weaving`. Ноль созданных узлов и ноль стрелок после содержательной волны — не «нечего было ткать», а невыполненный шаг: скажи это прямо и назови почему.
  - **Переключить модусы.** Мерж делает истинным то, что стояло замыслом: `anagata→vartamana`, `kalpita→pratyakshita` — по всему спроектированному контуру, не только по тронутым узлам. Модус, переключённый прежде свидетельства, — непроверенная заявка, читающаяся как проверенная; поведенческую сперва проверь на носителе (*Reality*).
  - **Закрыть по оси.** Ответ — `addressed_by` к несущему узлу; это поднимает уверенность, но вопрос не кончает. Отпускание (`visarjana`) — отдельный волевой акт, и оно твоё, когда сходятся три вещи: ответ стоит узлом, репо его показывает, реальность показывает его настолько, насколько достижима. Гонит скилл `inquiry`; он же паркует, вытесняет и кристаллизует. Тем же ходом — инбокс роли: `posed_to`-вопросы, на которые работа ответила.
  - **Свести код и граф — `reconcile`.** Уборочный такт конца всякой сущностной задачи: узлы области против корпуса, корпус против графа, честность модусов, отброшенные варианты записаны и референсируемы. Остаток долгов — вимаршами, не рассказом.
  - **Фидбэк-рефлексия** — на мерже, а также на закрытии сессии, которую мерж не венчал: изучи опыт сессии *о самом методе* — где скилл, правило или поверхность подвели, удивили или сработали не по своей причине. Всё — в `@nks/nks-dev`, адресно, якорем на узел инструмента и адресом его стюарду (решение владельца, #3958): **дефект конкретной поставки скиллов** → её контур, #1506 здесь или #844 у соседа; **норма канала и стояний** → под-граница #3768; **поверхность тулов** → MCP-контур; **метод вообще**, не про одну поставку, → владельцу продукта #1226. Общего поля обратной связи нет. На #2271 фидбэк не маршрутизируется — поток туда закрыт сознательно. Гонит скилл `feedback`. **Пустая рефлексия — валидный исход: ноль записей лучше мнения.**
  - **Словарный проход.** Перечитай то, что приземляешь, — текст репо и узлы — на заимствованные проектно-менеджерские слова (ticket, backlog, sprint, epic, story, done, blocker, committed). Сам **не** подменяй: назови каждое пользователю и спроси, как это зовётся в проекте. (why: переименование — акт владельца, а уверенно-неверная замена хуже вытесненного слова: она читается родной, и её больше никто не ставит под вопрос.)

  **Планов графа этот файл не держит.** Ни одного превращения, ни одной крии конвейера здесь не названо, и это правило, а не упущение: превращение — план человека, он движется на его каденции, и файл в репо за ним следить не может. Что здесь стоит — адреса входа: граф, контур #1506, твоя роль #931, роль владельца #1226. Что происходит внутри — читается ориентацией, каждый раз заново.
- **Общая методология остаётся общей.** *Существо* скиллов (крии «навигация», «создание узла», «приведение репо к стандарту», intake, roadmap, вахта) — общая методология, смоделированная один раз под #844/methodology; не дублируй её под #1506. Собственный узел получает только то, чем скилл iskron *расходится* с общей версией.
- **Синхрон «скилл ↔ тул» — постоянный двигатель:** когда сервер за `mcp.iskron.ru` переименовывает или выбрасывает тул, соответствующие правки скиллов ложатся сюда, желательно в тот же атомарный отрезок времени.
- **Утверждение, которое ты сделал, — не утверждение, которое ты принимаешь.** Поведенческие утверждения — «мост переживает смену сессии», «бандл ставится», «имя тула живо» — закрываются вердиктом холодного `verifier`-суб-агента, никогда твоим перечитыванием. Дай ему утверждение, носитель и фальсификатор из *Reality* — и **дождись вердикта**. (why: своё изменение видишь не как оно есть, а как задумывал.)
- **Мерж хуков.** В `.claude/settings.json` записи разных наборов сосуществуют — добавляй рядом, никогда не перезаписывай чужие.
- Эти напоминания автоматизированы: `SessionStart` (ориентация), `PostToolUse`/Bash (после `git push`), `PreToolUse` (memory-guard), `Stop` (сторож незастывания) — все четыре в `.claude/settings.json`. Interop-подсекции нет: коэрсивный workflow-набор здесь не установлен.
- **Держи этот файл честным.** Он сгенерирован `iskronify` и проштампован внизу контрактом, из которого пришёл. Перегони `iskronify`, когда установленный скилл объявляет более новый контракт — или когда источники сдвинулись после штампа: `git log -1 --format=%cd -- skills/iskronify/` против даты штампа решает одной командой. **Сверка не стоит ни вызова:** число установленного контракта объявлено в начале описания скилла `iskronify` (`КОНТРАКТ AGENTS.md: N`), а описания лежат в контексте каждой сессии — сравни его с числом в штампе ниже, ничего не загружая. (why: устаревший AGENTS.md читается с полной уверенностью каждую сессию и вводит в заблуждение сильнее, чем отсутствие файла.) Здесь у сверки есть известная тонкость: **источник этого репо обгоняет установленный плагин** — контракт правят тут, а до `~/.claude/plugins/` он доезжает релизом, поэтому расхождение «описание против штампа» на этой машине нормально ровно до следующего обновления плагина. Авторитет — `skills/iskronify/SKILL.md`, не установленная копия.
- **Держи свой тулчейн свежим.** Обновления **включены по умолчанию**: бери их, как доставляет канал, не пинь. (why: устаревший скилл дрейфует от тул-поверхности, которую называет, и деградирует тебя молча — ничего не падает, метод просто идёт не так.)

### Самопроверка этапа
Гейт качества зелёный и связный этап закончен — открыт или обновлён PR, либо ты собираешься тронуть узлы за пределами тех, с которых начал, — перечитай свой дифф ветки против транка на: неверные поведенческие утверждения о тулах, мёртвые указатели, разошедшиеся с источником производные строки, куски прозы, которым место в графе, и правки, растёкшиеся за задачу. Чини в **той же ветке** и пушь снова — или прямо скажи, что ничего не всплыло. Находок не выдумывай. **По этапу, а не только в конце:** ревью, отложенное на конец, читает дифф, которого уже не удержать целиком.

### Холодное ревью этапа
**Самопроверка не заменяет холодного ревью.** Перечитывая своё, ты видишь, что имел в виду, а не что написал. Самопроверка ловит небрежность; рамку и пропущенную интеграцию ловит только тот, кто её не видел. Оба, в этом порядке.

После самопроверки открытого/обновлённого PR или завершённого крупного этапа **открой ревью суб-агентом верхнего тира** — роль `reviewer` в `.claude/agents/reviewer.md`, **в отдельном worktree** (`isolation: "worktree"` у порождающего тула): рабочая копия одна на машине, и запрет в брифе — вторая линия, а не первая (граф, #4043). **Сторож есть только у пуша:** этап, закрытый без пуша, ничем не напомнит о себе — там ревью держится тобой одним, и это признанный зазор, а не обещанное покрытие.

Поле работы ревьюера — четыре вещи, и все обязательны: **дифф ветки против транка** (вся ветка, как её увидит мержащий); **сам репозиторий** (дифф без окрестностей читается как стиль, а не как правильность); **#1506 и его steward #931** — корень обхода владения; **референсы на узлы графа, входящие в дифф** — ведущая вимарша и все крии, феномены и правила, чьё воплощение меняет ветка, не пересказ этих узлов.

Поэтому бриф называет сами вызовы тулов, а не имя скилла: тулы одинаковы во всех харнессах и сверяются `make check-surface`, а форма вызова скилла принадлежит харнессу.

Если референсов не хватает или trace обрывается, reviewer возвращает `NEEDS_CONTEXT` и называет разрыв: это дефект графа, не мелочь брифинга. Допроектируй недостающее, дотки рёбра, поставь вимарши — затем повтори ревью. Что вернулось — чини в той же ветке; находку, с которой не согласен, отклоняй записанным «почему»: молча отброшенное ревью учит следующего не ревьюить.

### Дисциплина веток
Одна ветка до её мержа — доделки коммить в неё, не заводи новые до того, как она слилась. После мержа: `git checkout main && git pull`, удали слитую ветку (`git branch -d`), обнови граф (#1506 + закрой разрешённые вимарши), подтверди уборку до следующей задачи.

## Рабочие принципы
1. **Думай до правки.** Сориентируйся в `nks-dev`; прочти карту бяньхуа. Называй допущения; спрашивай при неуверенности — называя, *что именно* неясно. **Вопрос человеку задаётся текстом** — в разговоре или в канал; инструмент интерактивного выбора вариантов не используется никогда: список опций подменяет вопрос ответом, навязывает рамку агента и прячет то, что на самом деле неясно. Вопросы вне мандата становятся вимаршами `posed_to` роли #1226.
2. **Сначала простота.** Минимум правки под задачу. Без спекулятивных шагов и абстракций для одноразового текста.
3. **Оставайся в границе репо.** Изменение, принадлежащее другому контуру (#844, nks-mcp, чужой репозиторий), не твоё через границу: запиши его вимаршей на узле того контура, заякоренной там, где ориентируется его владелец.
4. **Вторая имплементация — событие для доклада.** Собираешься написать то, что уже существует, — то же правило во втором скилле, тот же абзац в шаблоне и в теле? Сначала выведи оба места через поле интеграции в графе (`integrity`), затем назови их пользователю и предложи либо воссоединение, либо именованную сознательную развилку.
5. **Хирургические правки.** Трогай только те шаги скилла, которых требует задача. Держись существующего регистра и терминологии каждого бандла. Не переписывай бандл целиком ради одной починки, если об этом не просили.
6. **Исполнение от цели.** Поведенческое изменение моста — падающим тестом до патча. Многошаговое: план парами `шаг → проверка`. Назови фальсификатор до взгляда («какое наблюдение это опровергло бы?») и наблюдай сам носитель, не исходник, который должен был его произвести — *Reality* называет носители и кто их достаёт.
7. **Прочти, прежде чем отвечать на открытый вопрос.** Задачи в рамке *обсудить / продумать / разобраться / спроектировать / «что думаешь»* отвечаются из записанного мышления, не из training data: сначала спроси граф, несколькими способами (один промах ≠ отсутствие). Протокол гонит скилл `entry`.
8. **Думай в графе, говори на языке проекта.** Структурный словарь — крия, феномен, контур, роль, вимарша, три оси модусов — для рассуждения. В сказанном пользователю он не появляется, пока пользователь не употребил первым. Разговор *о* работе — третий регистр, и именно он идёт вкривь: ticket, task, sprint, backlog, story, done не принадлежат проекту, потому что описывают работу. Вместо них — вопрос, изменение, что открыто, что это разрешает.
9. **Смотри настоящий источник.** `skills/<name>/SKILL.md` — не производный зип `.skill`, не установленная копия в `~/.claude/skills/` или кэше плагинов, и не свои допущения. Синхрон важнее выдумки: проверь, что имя тула существует, прежде чем писать его в скилл.

## Поле интеграции — только из графа
Контур #1506 и steward-роль #931 — единственный постоянный корень обхода. Список общих поверхностей, потребителей и зависимостей здесь **не ведётся и у человека не спрашивается**: такая проза устаревает в ходе самой работы и отменяет настоящий обход ложным чувством полноты. Запрет ровно об этом: о своём, что граф уже моделирует. Чужое, что он не моделирует и не может, — «Внешние поверхности» ниже, и та секция ведётся.

Для каждого изменения назови узлы графа, чьё воплощение входит в дифф, и прогони `integrity`. Феномен трассируй в обе стороны через `iskron_orient(lens="trace")`; у крии пройди `next`-нить и эстафеты её `ahara`/`utpatti`/`upadhi`; выход в другой холон ведёт к его steward-роли. Так находятся потребители, эффекты, открытые вимарши и делатели, которых затронет изменение.

Здесь у обхода есть своя особенность: **#931 стюардит два контура** — #1506 и соседний скилл-репо #844. Обход, вышедший на #844, не покидает твоей ответственности, но покидает границу этого репозитория (Рабочий принцип 3): правка туда не идёт, идёт вимарша. Не найденная обходом зависимость — не повод дописать список: это дефект модели. Недостающие крии и феномены допроектируй, непрошитые рёбра дотки через `weaving`.

## Внешние поверхности — то, чем пользуешься и чем не владеешь
Чужой API, SDK, CLI, протокол, схема вендора. Их агент **угадывает**, и это не лень, а устройство: он помнит их по обучению, а память изнутри неотличима от знания. Цена не в незнании — в уверенности: имя, которого нет, выглядит в тексте ровно как имя, которое есть, и расходится не на сборке, а у агента ниже по течению.

Здешние внешние поверхности: **поверхность тулов сервера за `mcp.iskron.ru`** (снимок — `fixtures/surface.json`, механизирована `make check-surface`); **файловые поверхности агентов Claude Code и OpenCode** (директории агентов, ключи фронтматтера, алиасы и наследование моделей — чеклист пересверки в `skills/iskronify/references/delegation.md`); **плагинная поверхность OpenCode** (`@opencode-ai/plugin`: форма `Hooks`, `tool()` с zod-аргументами, `client.session.promptAsync`, каталог `~/.config/opencode/plugins/` с собственным `node_modules`; версия зафиксирована dev-зависимостью в `js/package.json`, типы проверяются `make typecheck`); **загрузчик плагинов claude.ai** (отвергает описание с содержимым в форме XML-тега — отсюда запрет `<`/`>` в `description`).

- **Прежде работы зафиксируй ту часть поверхности, с которой работа будет** — не всю: то, что трогаешь. Узлом в графе, с версией, на которой смотрел: версия — часть личности поверхности, а не примечание.
- **Источник берётся по старшинству — пратьякша прежде шабды.** Наблюдение своими руками (ответ, который ты видел; `--help` установленного бинаря; снимок, снятый `make surface`) старше документации; документация старше памяти; **память источником не является вовсе**. Эпистемику пиши честно: `pratyakshita` только на наблюдённое своими руками.
- **Проткай связь.** Узел внешней поверхности — `upadhi` к крие, которая через него действует. Без ребра он ярлык-сирота: его не найдёт ни обход, ни следующий агент.
- **Держи в ногу.** Обнаружил расхождение или вендор поднял версию — правь узел тем же ходом, которым обнаружил. Молчаливо расходящийся узел хуже отсутствующего: по нему действуют.

## Reality — против чего проверяется заявка
Реальность здесь — **поведение агента по скиллу и достижение скиллом того, ради чего он существует**. Гейт (`make validate`, `check-surface`, `check-bundles`) проверяет гигиену артефакта, а не это: зелёный гейт вполне совместим со скиллом, который никого никуда не привёл. **Тесты имитируют реальность** — здесь и везде: они ступень свидетельства, а не носитель. Носитель у скилла — агент, который им воспользовался и дошёл до целевого состояния; у моста — мост в употреблении.

**Ceiling**: «агент ниже по течению не деградировал» и «методология не дрейфует» достижимого наблюдения не имеют — эффект тих, распределён по чужим сессиям и отложен во времени. Честный потолок — полевой репорт с версией сборки (`vX.Y.Z+хеш`, который несёт мост) и схождение независимых свидетельств; как «проверено» эти классы не закрываются никогда. Под этим потолком стоит второй, записанный каноном (methodology #534, hetu-dosha): свидетель, ведомый методологией, подтверждает её любым исходом — и холодный приёмочный прогон, и фидбэк агентов ведомы тем же текстом, который проверяют. Независимым считается свидетельство, отобранное по независимости источника от предписания: поведение, которого текст не предписывал, или отказ, которого он не предсказал.

**Долг таблицы, названный прямо.** Первая строка исполнима только там, где у скилла есть крия с определённым `utpatti`. Сейчас скиллы записаны феноменами-`vollzug` («行 ход/метод») без такой крии, поэтому `iskron_orient(lens="trace")` на них рвётся — `lifecycle_gap`, и целевое состояние назвать нечем. Пока не проткано: заявку «скилл работает» закрывать **нечем**, и зелёный гейт за неё не выдавай. Рабочий обходной носитель, показанный в поле: **приёмочный прогон холодным суб-агентом** — брифом даются текст скилла, роль и постусловие, агент исполняет дословно и возвращает знаки со свидетельствами; так закрыт поведенческий критерий скилла standing. Дефекты текста, которые прогон приносит попутно, — половина его ценности. Исполняемый код поставки — под-контур #4057 (js-bundle): его состав, кто его производит и ест и чем он проверяется, читаются оттуда, не отсюда. Носитель работоспособности моста — строка «Мост работоспособен» выше, наблюдается ежесессионно.

**Таблица растёт использованием.** В момент, когда сессия научила тебя тому, чего таблица не держит — носитель, который никто не назвал; наблюдение, оказавшееся достижимым или недостижимым; неверная команда здесь, — пиши строку *тогда же*, до закрытия научившей работы.

## Стек
Markdown `skills/<name>/SKILL.md` (+ по желанию `skills/<name>/references/*.md`) на каждый скилл — **правь их напрямую, это обычные файлы и они полностью грепаются.** Каждый пакуется в производный зип `<name>.skill` (верхнеуровневая директория `<name>/` с `SKILL.md` внутри) командой `make build`. Код двух родов: **отгружаемый** — исходник в `js/` (TypeScript под strict: `bridge/`, `watchdog/`, `cli/`, `extension/`, `opencode/`, `roadmap/`, общее в `shared/`), из которого `make build-js` собирает однофайловые выходы без зависимостей под `skills/<name>/scripts/`, в `extensions/` и в html-шаблон роадмапа (граница — под-контур #4057; выходы коммитятся как производные, `make check-js` сверяет их с исходником побайтово, как `check-bundles` — зипы) — и **тулчейн**, который не отгружается: `js/package.json` с dev-зависимостями и `js/package-lock.json`, сборка выходов (`js/build.mjs`), скрипты валидации и сверки (`scripts/*`) и пробы (`js/tests/*.mjs`), которые гонят `make` и CI.

Pre-commit-хук (`.githooks/pre-commit`) пересобирает и стейджит бандлы `.skill` на каждом коммите, так что закоммиченные зипы никогда не расходятся с исходником; включается один раз на клон (`make hooks`, оговорка — в таблице команд). Гейт для корпуса — **формат и сверка с поверхностью**, а не поведение; для моста и сторожей — именно поведение. Что именно он ловит, перечислять здесь незачем: гони `make check`, и упавшая проверка назовёт себя сама. Существо скилла — верна ли его проза и живы ли ссылки на тулы — не ловит ни одна из них: это человеческий обзор дифа.

## Структура проекта

Дерево узнаётся `ls` дешевле, чем читается здесь, поэтому ниже — только то, чего `ls` не скажет.

- `skills/<name>/SKILL.md` — **источник истины**, по одной директории на скилл (`iskron`, `entry`, `writing`, `design`, `weaving`, `reconcile`, `inquiry`, `assembly`, `integrity`, `intake`, `vahta`, `standing`, `chief-of-staff`, `feedback`, `reality-audit`, `minding`, `methodology-work`, `iskronify`, `product-roadmap`, `establish-mcp`); `references/*` по желанию.
- **Руками не правится:** зипы `*.skill` и выходы JS под `skills/*/scripts/`, `extensions/` и шаблон роадмапа (выхлоп `make build`), версии в `.claude-plugin/*.json` и `.codex-plugin/plugin.json` и константа `VERSION` в `js/shared/version.ts` — их пишет release-please; установленная копия в `~/.claude/` и кэше плагинов.
- **Устаревшие сторожа нативного транспорта** `skills/standing/references/watchdog.mjs` и `watchdog-exit.mjs` — единственный отгружаемый код НЕ из `js/`, оставленный ради живых вахт без моста — **инвариант релиза: убираются только когда таких вахт не останется, и не минорной версией** (почему — готчи #4522, #4336, #4337); проба — `js/tests/watchdog-legacy.test.mjs`, наводка `ISKRON_WATCHDOG_DIR=<каталог старых копий>`.
- **Отгружаемый код** — исходник в `js/`, один каталог на **один контур в графе, #4057 (js-bundle)**; мост несёт собственный тул `iskron_stand` (стояние одним вызовом) и обновляет себя сам (дом против себя при старте, релизы GitHub раз в шесть часов, подкоманда `update`); его выходы: `skills/establish-mcp/scripts/iskron.mjs` (одна копия: путь к работающему мосту печатает сам ответ `connect`, второй копии никто не называет) и рядом `opencode-plugin.js` (плагин OpenCode; ставится тем же шагом, что и мост, копией в `~/.config/opencode/plugins/iskron.js`), `extensions/iskron.js` (у pi это конвенционный каталог пакета, в бандлы он не входит) и `skills/product-roadmap/references/roadmap-template.html`. Карта контура лежит здесь, а не README рядом с выходами: всё под `skills/` уезжает потребителю как есть, и README с адресом графа уехал бы вместе с ним — мёртвым указателем на граф, которого у потребителя нет. Домашняя копия моста у пользователя зовётся `~/.iskron-bridge/iskron-bridge.mjs` — это контракт с конфигами харнесов, и имя файла в поставке его не трогает.
- **Тулчейн не отгружается:** `js/package.json` + `js/package-lock.json` (dev-зависимости, `js/node_modules/` в gitignore), `js/build.mjs` и конфиги `js/tsconfig*.json`, `js/eslint.config.js`, `js/.prettierrc.json`, `scripts/*` (валидация, упаковка, сверка с поверхностью), `js/tests/*`, `Makefile`, `.githooks/`, `.nvmrc`.
- `fixtures/surface.json` — снимок живой поверхности тулов, обновляется `make surface`.
- `.mcp.json` (stdio-мост для плагина Claude Code; Codex несёт ту же запись объектом в своём манифесте; http-запись есть только в архиве claude.ai, её пишет `make plugin`), `.claude-plugin/`, `.codex-plugin/`, `.agents/plugins/` — поставка в четыре канала; `.claude/` — настройки этой рабочей копии (`settings.local.json` в gitignore).
## Конвенции кода
- **Держи репо чистым по бренду.** Бренд — **iskron** (`iskron@iskron`, `/iskron:<skill>`, `mcp.iskron.ru`), а скилл бутстрапа репозитория — **`iskronify`**. Ни один файл в гите и ни одна git-поверхность (сообщение коммита, заголовок и тело PR, имя ветки) не ссылается на другую скилл-дистрибуцию: ни на её бренд, ни на имя её скилла бутстрапа, ни на слово «upstream/апстрим», ни на номера её PR — описывай каждое изменение по его собственному существу. `make validate` роняет отгружаемый источник, несущий чужой бренд-токен; перед пушем прогреби так же сообщение коммита и имя ветки. Отношения между дистрибуциями живут только в графе (`nks-dev`, #844/#1506) — общий граф может нести другой бренд; файлы и история этого репо — никогда.
- **Смысл живёт в графе, код референсирует.** Комментарий или абзац, несущий обоснование решения, отброшенные альтернативы или устройство интеграции, — узел графа, живущий не дома: перенеси смысл в граф, в тексте оставь референс. Граница: **механика шага — словами на месте; смысл, обоснование, поле интеграции — в графе.** Ссылка работает в обе стороны: сославшись на узел, проверь, что он и правда говорит то, за что ты его выдал; разошёлся — правь узел тем же ходом, а не дописывай абзац.
- **Фронтматтер `SKILL.md`**: `name:` (kebab, совпадает с директорией скилла) + `slash: true` + `description:`, несущий явные фразы-триггеры — именно описание маршрутизирует скилл, поэтому держи триггеры конкретными. Триггер, выпавший при переписывании описания, — тихая потеря маршрутизации: скилл перестаёт находиться на формулировку, которой его звали.
- **Имена скиллов голые** — без префикса `nks-`/`iskron-`. Плагин `iskron` даёт им пространство имён (`/iskron:<skill>`), так что префикс только заикался бы. Плата: плоская установка (`npx skills`, ручная распаковка) кладёт скиллы в `~/.claude/skills/<name>/` под голым именем и может там столкнуться — канонический, защищённый от столкновений канал — плагин.
- **Форма вызова скилла принадлежит харнессу, не поставке.** Claude Code с плагином неймспейсит (`iskron:<name>`), плоская установка оставляет голое имя, у других харнессов своя форма. Поэтому текст, который проецируется в несколько харнессов одним куском (тело ролевого файла из `references/delegation.md` едет и в `.claude/agents/`, и в `.opencode/agents/`), **формы вызова нести не может вовсе** — называй там сами вызовы тулов: они одинаковы везде и сверяются `make check-surface`.
- **Источник истины = `skills/<name>/SKILL.md`.** Правь его напрямую, затем `make build`, чтобы перегенерировать зип `<name>.skill` (внутри должен быть `<name>/SKILL.md`, а не голый `SKILL.md`, иначе не поставится). Новый скилл → заведи директорию `skills/<name>/`; он поедет автообнаружением плагина. Никогда не добавляй списки компонентов (`skills`, `commands`, …) в `marketplace.json`/`plugin.json` — вторая копия истины расходится, и гейт формата это роняет.
- **Никаких seq-ссылок на графы в скиллах.** Скиллы едут к пользователям, у которых (почти наверняка) нет доступа к `methodology`/`nks-dev`, а seq-номера привязаны к экземпляру графа — `#N` или `iskron_look(node_id=…, realm="methodology")` в скилле ниже по течению либо мёртвый груз, либо неверный указатель. Называй понятия по имени; оставляй только синтаксические плейсхолдеры (`#42`, `#N`, GitHub `#123`). Исключение: `methodology-work` может ссылаться на граф методологии операционально (поиск по имени и атрибутам, не по seq) — этот скилл его предполагает. (Seq-ссылки в **этом AGENTS.md** нормальны — он никогда не отгружается.)
- **Размещение уроков в скилле: в теле — то, чем шаг исполняют; в справке (`references/*`) — то, чем его чинят.** Подтверждено двумя независимыми свидетельствами (держатель nks-mcp; вахта iskron): справку при подключении не открывают, поэтому исполняющий вызов (например, `Monitor` со сторожем как `command` и `persistent: true` для держания сокета) обязан стоять в теле шага, а таблицы починки (коды закрытий, повторные register) живут в справке.
- **Устойчивая дверь вместо пересказанной детали.** Где шаг требует детали инструментальной поверхности, указывай на дверь, которая отвечает всегда — собственное описание тула, `action="?"`, подсказки его вывода, — а не пересказывай поведение, наблюдённое сегодня. Имя дрейфует громко и ловится гейтом; **утверждение о поведении дрейфует молча**: каждое имя во фразе остаётся живым, пока сама фраза становится ложной, и грепа на это нет. Пересказывать можно ровно то, что готов держать истинным.
- **Ссылки на тулы и скиллы должны быть живыми — и префикс тулов здесь `iskron_`.** Поставка одна, и тулы у неё только `iskron_*`; `nks_*` в скилле — мёртвый или чужой указатель, и `make validate` его роняет. Любое имя, которое называет скилл, обязано стоять в нынешней поверхности сервера за `mcp.iskron.ru` — это механизировано: `make check-surface` сверяет каждое имя и каждое значение enum с `fixtures/surface.json`. Не перечисляй здесь выброшенные тулы: список мёртвых имён устаревает быстрее живых и только сажает их агенту в голову — снимок и есть перечень того, что существует.
- **Момент скилла на поверхности вызова.** Мост приписывает к описаниям пишущих тулов (`iskron_add_*`, `iskron_batch`) строку момента скилла `writing` (`js/bridge/moment.ts`), дверь `iskron` несёт карту моментов агента, а хук `PreToolUse` на тех же тулах повторяет указатель в контекст. Правя скилл `writing`, держи три места в ногу: указатель, разошедшийся со скиллом, хуже отсутствующего.
- **Терминология**: `phenomenon` для типизированного примитива, `node` для произвольного; `kriya`/`holon`/`karta`/`vimarsha` по онтологии графа. Не возвращай отменённые термины.
- **Версия моста = версия плагина и датирует полевые репорты.** Константу `VERSION` в `js/shared/version.ts` штампует release-please при мерже релизного PR (строка помечена `x-release-please-version`, файл стоит в `extra-files` конфига; джоб `bundle-sync` тут же пересобирает выходы JS и бандлы на релизной ветке — иначе `check-js` и `check-bundles` красные) — **руками её не трогать**. Каждая синтетическая ошибка и строка `grant.log` несут сборку `vX.Y.Z+хеш`: версия датирует установленную поставку целиком (скиллы включительно), хеш собственного файла — конкретные байты между релизами. Тест держит инвариант `VERSION == plugin.json version`.
- **Дисциплина тестов**: для корпуса CI проверяет формат и сверку с поверхностью (`make check`); существа он не проверяет. Правило одно и держится **по классу, а не по списку имён**: у ВСЯКОГО отгружаемого предмета со своим набором поведенческое изменение ложится пробой тем же коммитом, и проба пишется так, чтобы **сначала краснела на старом коде** — прогоном против старой копии через переменную наведения этого предмета. Проба, никогда не бывшая красной, доказывает только то, что она запускается. Наводки: мост и `doctor` — `ISKRON_BRIDGE_PATH=<старый iskron.mjs> make test`, сторожа — тот же файл и та же переменная: `ISKRON_BRIDGE_PATH=<старый iskron.mjs> make test-watchdog`, расширение pi — `ISKRON_EXTENSION=<старый extensions/iskron.js> make test-extension`, плагин OpenCode — `ISKRON_OPENCODE_PLUGIN=<старый opencode-plugin.js> make test-opencode`; рендер роадмапа — проба импортирует исходник, старую копию подставляй правкой импорта. Перечисление здесь для удобства, а не определение: появится шестой предмет — правило уже про него, и не ждёт правки этой строки. У сторожей при этом есть своя оговорка: проверяют они только знак мёртвого токена — держание и доставку кадра тестом не имитируй, их носитель — живое стояние. То же правило у всякой новой проверки в `scripts/`: прежде чем включать её, замерь на нынешнем корпусе (сколько срабатываний) и покажи её красной хотя бы на одном подсунутом дефекте. Обзор существа по-прежнему ручной: читай диф `SKILL.md` — поведенческие утверждения про тулы это ровно то, чего не видит ни один линт.
- **Фронтматтер обязан быть разбираемым YAML.** Значения `description` в двойных кавычках; **любую внутреннюю кавычку экранируй как `\"`** (неэкранированная `"` обрывает скаляр раньше времени — ровно тот баг, который стережёт `make validate`). Держи фронтматтер плоским и однострочным — ровно три ключа: `name`, `slash: true`, `description`. `slash` обязателен и всегда `true` — каждый скилл этой поставки набирается как `/name` (OpenCode v2 декодирует его булевым, поэтому голое `true`, без кавычек); `make validate` роняет и пропуск ключа, и любое другое значение. Держи `description` **под 900 байт** — за этим порогом гейт предупреждает, за 1024 роняет (готчи, #4522).
- **Никаких угловых скобок в `description`** — `make validate` запрещает `<`/`>` начисто (почему — готчи #4522); плейсхолдеры пиши как `@handle/mind` (в *телах* скиллов угловые допустимы).

## Что обновлять когда
- `AGENTS.md` — по перевёрнутому умолчанию: **узнаваемое из узла графа сюда не пишется**; файл держит только нужное ДО того, как сессия дотянется до графа (команды, вход в ориентацию, инварианты вне линтера, развилки-стопы, достижимость носителей *Reality*) — и обновляется, когда меняется ЭТО. «Изменилась структура графа» — не повод для абзаца здесь. (why: абзац здесь — налог на каждую будущую сессию, узел графа оплачивает только та, которой он нужен.) Вычистка уже написанной прозы — reconcile-такт с переносом в несущие узлы, никогда не голое удаление.
- `README.md` — **таблицы скиллов он больше не держит**: человеку показана одна дверь, `/iskron`, и набор за ней меняется без правки README. Трогай его, когда меняется сама дверь или примеры её вызова, а новый скилл вписывай в маршруты `iskron` и разговорник — их полноту против дерева `skills/` держит `make validate`.
- `fixtures/surface.json` — когда меняется поверхность тулов сервера (переименование, дроп, новый enum): `make surface`, посмотреть диф, закоммитить.
- `DERIVATION.md` — карта ре-проекции скиллов из канона (+ контракт четырёх языковых слоёв): проходи её после любой перемены канона методологии; расширяй, когда новый ориентир канона проецируется в скилл.
- `skills/iskronify/` (`SKILL.md` + `references/agents-template.md`) — когда улучшаешь протокол и шаблон бутстрапа для всех будущих репозиториев. Правка шаблона обязывает перегнать `iskronify` **здесь же**: этот репо — первый потребитель собственного шаблона.
- `skills/iskronify/references/superpowers-interop.md` — когда superpowers переименовывает свои скиллы, пути или гейты (чеклист пересверки внутри).
- `skills/iskronify/references/delegation.md` — когда меняются поверхности файлов агентов Claude Code / OpenCode (директории, ключи фронтматтера, алиасы и наследование моделей; чеклист пересверки внутри). Тем же ходом перепроецируй `.claude/agents/*.md`.
- Граф (`nks-dev`, #1506) — каждый мерж: протянуть состояние репо в контур #1506, продвинуть живое превращение по карте, закрыть разрешённые вимарши.

## Git-воркфлоу
- **Conventional commits** (`feat:`/`fix:`/`chore:`/`docs:`…). Ветки `feat/…`, `fix/…`, `chore/…`; заголовки PR в том же формате. Правка существа скилла — новое правило, снятое правило, изменённый шаг — это `feat` или `fix`, никогда `docs`: `SKILL.md` и есть продукт, и тип коммита выбирает версию релиза. `docs` — только для текста, который агент по скиллу не исполняет: README, SETUP, комментарии.
- **Без агентских подписей на git-поверхностях.** Ни трейлера соавторства (`Co-Authored-By`), ни подписей «Generated with …», ни ссылок на агентскую сессию — нигде: ни в сообщениях коммитов, ни в заголовках и телах PR, ни в комментариях к ним. Изменение говорит своим существом; подпись инструмента — шум, который к тому же переживает squash-мерж и попадает в историю main.
- **Гейт формата**: гони `make check` перед коммитом (в CI то же самое на каждом пуше и PR). Он ловит битый фронтматтер, разошедшиеся бандлы, устаревшие инвентарные списки, дрейф поверхности и невызываемые имена скиллов и гоняет поведенческий набор моста — но не существо прозы; диф `SKILL.md` всё равно перечитай глазами.
- **Свежесть ветки — механическая проверка, не память**: `git fetch -q origin main && git merge-base --is-ancestor origin/main HEAD` до пуша. Обнаруживать отставание конфликтом через несколько слияний — провал формы, не делателя.
- **Форжа — GitHub, CLI — `gh`.** Наблюдать: `gh pr checks <n> --watch`, `gh pr view <n>`.
- **Живой прогон моста до релиза** (правило владельца, в графе — у публикации плагина): релиз, несущий изменённый отгружаемый JS, уходит только после того, как собранный `iskron.mjs` из ветки прогнан живьём на этой машине против `mcp.iskron.ru` — тулы отвечают, `connect` возвращает блок моста, `watchdog` печатает `hello`, кадр соседа доходит. Пробы против фейка этого не заменяют. Прогон — до мержа релизного PR, не после тега.
- **Definition of done**: изменение закоммичено и слито в `main` на `github.com/iskron-ai/skills`. **Коммит, пуш и открытие PR — твои**, делай все три без просьбы, как обычный конец работы; единственное действие пользователя — **мерж**, и о нём он сообщает сам. Ветка без пуша или пуш без PR — это не меньший шаг, а недоставленная работа. После мержа обнови граф #1506 — закрой разрешённые вимарши, продвинь бяньхуа, которую они двигают.
- **Пуш и `gh` — две личности**: отказ `gh pr create` рядом с работающим пушем — сперва аккаунт, не права (готчи, #4522).
- **Никогда** `--force`, `--no-verify` и `git reset --hard` без явного указания.
