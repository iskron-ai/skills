# iskron/skills
Скилл-бандлы NKS для агентов (Claude Code skills) под деплой **iskron.ru**, смотрящий на `mcp.iskron.ru`. Среди них `iskronify` — скилл, приводящий любой репозиторий к стандарту этого `AGENTS.md`.

**Поставка и релиз.** Раздаётся маркетплейсом плагинов Claude Code (`iskron@iskron`), семвер в `.claude-plugin/plugin.json` поднимает **release-please** из Conventional Commits на `main` (feat→minor, feat!/BREAKING→major, иначе patch): мерж релизного PR пишет версию, тег `vX.Y.Z`, GitHub Release и `CHANGELOG.md` (`.github/workflows/release-please.yml` + `release-please-config.json`, никогда руками). MCP — `https://mcp.iskron.ru/`; `.mcp.json` плагина — **stdio-мост из поставки** (`${CLAUDE_PLUGIN_ROOT}/…/iskron.mjs` — ровно этот токен, готчи #4522; для разработки — пользовательская запись `iskron-bridge`); манифест Codex несёт ту же запись объектом `mcpServers` (относительный путь, `cwd` — корень плагина; валидатор Codex берёт либо объект, либо файл ровно `.mcp.json`, а это имя занято записью Claude Code); http-записи к серверу в поставке нет нигде — путь к графу один, мост (слово владельца к #6728; `make validate` роняет отгружаемую запись не stdio). Пишущая в граф сессия идёт через `iskron-bridge` — привязку стояния и сокет держит только он (скилл `establish-mcp`); вход — OAuth в браузере либо личный токен (`ISKRON_BRIDGE_TOKEN` или `~/.iskron-bridge/token`, тогда без OAuth). В OpenCode мост поднимает плагин поставки (копия в `~/.config/opencode/plugins/iskron.js`), не запись `mcp` (готчи #4522). CI: формат, сверка поверхности и джоб `widgets-in-sync` (скилл виджетов против снимка) без зависимостей плюс JS-лестница lint → format → typecheck → check-js → пробы с покрытием (`.github/workflows/ci.yml`).

**Production statement.** Скиллы определяют, как каждый агент над iskron пользуется NKS через `mcp.iskron.ru`. Неверная инструкция (например, тул, который сервер выбросил) тихо деградирует каждого агента, загрузившего скилл: краха нет, есть дрейф методологии; потребитель — агент. Синхрон скиллов с поверхностью тулов — основная обязанность.

## Правила персистентности
Состояние живёт в **репо** или в **графе** — больше нигде. Встроенная память харнесса (директория памяти, сводки разговоров, `/tmp`, машинно-локальные файлы) **запрещена целиком, не по категориям**; временный каталог — только скретч сессии, и она его убирает.
- **Репо**: `skills/<name>/SKILL.md` (источник истины), производные бандлы, `README.md`, `REALITY.md`, соглашения и ритуалы, состояние веток.
- **Граф** (`nks-dev`): решения, вопросы по сути (вимарши), планы (карта превращений), уроки, подсказки. Граф в репо не пересказывай — ссылайся.
- **Дело** (разговор на узле графа): постановка, вопрос, договорённость, приём; ход работы и её состояние в нём не ведутся — они в графе (#6717).
- **Источник истины — `skills/<name>/SKILL.md`**; зипы `<name>.skill`, установленная копия в `~/.claude/skills/` и кэше плагинов — производные: правь исходник, гони `make build`.
- **Доставай состояние, не вспоминай.** Нет источника у «мы решили…» — прочти граф или репо до действия.
- **Внешние design/spec-файлы — черновики на впуск**: решения держит граф.
- **Узел не записан, пока не назван тянущий его** — какая крия сломается, если он исчезнет? Укрытия три: проза этого файла; sinn-феномен для того, что действует; одинокая стрелка `context`. Дверь входит в граф местом, где делатель действует, — upadhi при крие.
- **Чей это факт?** — спрашивай всегда, поверх инструкции памяти харнесса; прежде чем закончить, проверь, что каждый долгий факт из разговора персистирован. Ритуалы, команды, порядок репо → этот файл; факты о коде, готчи, серверы, датированные долги (дата — в `attrs` узла) → узел в `nks-dev` (готчи — #4522); смысл кода (решения, основания, связи) → граф всегда (#6412); навигация по файлам — по слоту «Раскладка»; решение → узел сразу; вопрос по сути, обязательство → вимарша; разовая задача, вопрос, договорённость → слово в деле (дело — разговор); ход и состояние работы → граф, модусы узлов. Собственное пользователя вне проекта (машины, сроки, люди, кросс-проектные уроки) → `@handle/mind` (**minding**) в момент узнавания; о другом проекте → граф того проекта. Предпочтение «как со мной говорить» → `@handle/mind`; влияющее на процесс и результат → сюда или в граф проекта. Правила проекта в чужой граф не ложатся.
- **Поведение агента настраивают только коммитящиеся файлы рабочего дерева (AGENTS.md, файл хуков) и граф проекта** — никогда глобальный файл инструкций (`~/.claude/CLAUDE.md`, `~/.config/opencode/AGENTS.md`…), память харнесса, пользовательские хуки. Установка поставки (мост, его дом, плагин) — доставка, не настройка.
- Директория памяти **эвакуирована и заморожена**: `MEMORY.md` — стаб-запрет со ссылкой сюда; memory-guard `PreToolUse` в `.claude/settings.json` блокирует запись туда (exit 2).

## Жизненный цикл сессии
Список правил — по строке на правило; полная норма — «Сквозные нормы» скилла `iskron`.
- **Граф — работа, git — как пришли.** SHA, ветки, номера PR, «merged» в граф не пишутся (тела, имена, атрибуты узлов и стрелок); провенанс — в `reasoning` записи. В деле SHA, ветки, PR, теги, версии и кто сказал когда пишутся свободно.
- **Старт сессии** — раздел «Старт» скилла `iskron`, до действий; кончается готовностью (граф и роль названы, привет дошёл), не чтением; очередь роли и карты — по поводу. Стояние — только на вахту (слово «вахта», `start`, адрес места из окна, кадр), одним `iskron_stand`. `start <граф> <роль> <дело №N>` — вход в это дело, первое слово — пересказ постановки. У субагента свой мост-спутник (`iskron_stand` с `satellite_of`, `join`, `leave` — на нём); на мосту запустившего запуск не допускается — субагент без своего моста в граф не пишет и говорит это первой строкой итога.
- **Ремесло графа — сам** (#6717): чтение, запись, ткачество, интеграция — у того, кто решает («Ремесло графа» в «Сквозных нормах» скилла `iskron`); субагентам — объёмное: код, гейт, ревью, проверка; их совет — только сверкой с окрестностью узла.
- **Адреса**: граф `@nks/nks-dev` (`r5`), фокус-контур #1506, роль агента #931, роль владельца #1226 (seq, не `me`). Работа над мостом, сторожами, рендером роадмапа, расширением pi или плагином OpenCode ориентируется на под-контуре **#4057** (`iskron_orient(realm="@nks/nks-dev", focus="4057")` — дети холона и есть эти файлы): обязательства кода — стояние, привязка, слух — записаны только там.
- **Начало работы: граф, потом проект, потом код.** (1) разведка графа (`entry`): записанное о месте изменения, открытые вимарши, решённое и отвергнутое, записанное о внешних поверхностях; (2) поле интеграции от #1506 (для кода — от #4057), #931 и узлов изменения (`integrity`, раздел ниже); (3) проектирование (`design`), затем правка. Пропуск — только по явному «работай сразу» или другому названному протоколу, долг разведки — на reconcile; молчание человека — не разрешение. Работа мимо графа — худший провал агента (#6409).
- **Решение — в граф в момент принятия**, откуда бы ни пришло (чат, сокет, договор агентов): epistemic не выше `anumita`, ontic `anagata`, volitive `chanda`/`adhimoksha`; кто решил и что считается исполнением. Изменившаяся ситуация — так же сразу.
- **Задача описана до начала — тем, что она есть.** Разовая — словом в деле: постановка, пересказ, исход — словом в то же дело; пришла без дела — открой дело (`open_room` на узле предмета либо `iskron_case(action="talk", about=<предмет>)`) до первой перемены снаружи. В граф — переходы, которые она меняет (в модусах замысла; крупное — превращением), и решения. Вимарша — только вопрос по сути или обязательство; крия — только повторяемый переход: спроси, что она съест и произведёт в следующий прогон, — нет ответа, это задача.
- **Работа идёт в графе** (#6717). Вопрос соседу, ожидание, обязательство — вимарша `posed_to` с «Отвечено, когда»; решение — узел; передача — эстафета и модусы; после события работы (мерж, выкат, решение) граф догоняет тем же ходом — легло, сдвинулось, отпущено. Дело — разговор, не журнал: строк на каждое действие нет. Слово агенту — в дело; канал — только человеку без места в деле. Отказ от поручения — словом; от вимарши — её правкой. Уходя — сдача семенем превращения и словом в деле, ведение — уговором (скилл `architect`).
- **Мерж → граф.** Пуш, открывший или обновивший PR, не отгрузил ничего: тела и модусы описывают то, что несёт `main`. Последовательность висит на событии мержа, не на затишье. Все акты обязательны — кроме работы по ссылке от агента (постановка референсами, отчёт в деле): там ткачество, закрытие по оси и сведение — постановщику, делателю — семя превращения и модусы поставки (скилл `vahta`):
  - **Проткать** (`weaving`): отгруженное — в контур #1506 узлами и рёбрами, не абзацем; механика репо остаётся в git. Ноль узлов и стрелок после содержательной волны — скажи прямо, почему.
  - **Продвинь карту**: открытая работа — `anga` к превращению; семя `genre=hint` одно на превращение — только важное после сессии, живые дела по строке.
  - **Переключи модусы** (`anagata→vartamana`, `kalpita→pratyakshita`) по всему спроектированному контуру — после свидетельства на носителе (`REALITY.md`, **reality-audit**).
  - **Закрой по оси** (`inquiry`): `addressed_by` к несущему узлу; `visarjana` — твоя, когда ответ стоит узлом, репо его показывает и реальность показывает, насколько достижима (где нет — слово пользователя); иначе предъяви владельцу; другие концы — оставить, вытеснить, кристаллизовать. Тем же ходом — инбокс `posed_to` (прочие не суди по возрасту, будит перемена у якоря), `propose_close` со свидетельством (скилл `architect`).
  - **Сведи — `reconcile`**: узлы области против корпуса, корпус против графа, честность модусов, отброшенное записано и референсируемо; остаток — вимаршами.
  - **Фидбэк-рефлексия** — на мерже и на закрытии сессии без мержа: опыт *о методе* (скилл, правило, поверхность подвели, удивили, сработали не по своей причине) — случаем, не мнением, после проверки на сказанное, в `@nks/nks-dev` якорем на узел инструмента, адресом его стюарду (#3958): дефект поставки скиллов → её контур (#1506 или #844); норма канала и стояний → #3768; поверхность тулов → MCP-контур; метод вообще → #1226. Общего поля нет; на #2271 не маршрутизируется. Скилл `feedback`. Ноль записей — валидный исход.
  - **Словарный проход**: заимствованные слова (ticket, backlog, sprint, epic, story, done, blocker, committed) в приземляемом тексте и узлах назови человеку и спроси, как это зовётся в проекте; сам не подменяй.
- **Дизайн не готов, пока решения, риски и жизненный цикл не в графе** — каким бы скиллом ни элиситирован; design/spec-файл другого набора впусти в той же сессии. Без владельца: решения и риски — сейчас, превращение — с телосом на подтверждение.
- **Наборы исполнения ведут исполнение** (план, TDD, отладка, ревью); граф несёт память и дизайн. Решения и риски исполнения — в граф до конца сессии.
- **Планов графа этот файл не держит**: превращения движутся на каденции человека и читаются ориентацией каждый раз заново.
- **Общая методология остаётся общей**: существо скиллов (навигация, создание узла, приведение репо к стандарту, intake, roadmap, вахта) смоделировано под #844/methodology — не дублируй под #1506; свой узел — только расхождение iskron с общей версией.
- **Синхрон «скилл ↔ тул» — постоянный двигатель**: сервер за `mcp.iskron.ru` переименовал или выбросил тул — правки скиллов ложатся сюда, в тот же отрезок.
- **Утверждение, которое ты сделал, — не утверждение, которое ты принимаешь.** Поведенческое («мост переживает смену сессии», «бандл ставится», «имя тула живо») закрывает холодный `verifier`: бриф — утверждение, носитель и фальсификатор из `REALITY.md`; дождись вердикта.
- **Мерж хуков**: в `.claude/settings.json` записи разных наборов сосуществуют — добавляй рядом, чужие не перезаписывай.
- Хуки прошиты в `.claude/settings.json`, одной строкой каждый: `SessionStart` (старт), `PostToolUse`/Bash на пуше (словарный проход и холодное ревью) и на мерже (акты после мержа), `PreToolUse` (memory-guard). Interop-подсекции нет.
- **Держи этот файл честным.** Число контракта — первое слово описания `iskronify` (`КОНТРАКТ AGENTS.md: N`), описания в контексте каждой сессии: сравни со штампом внизу, ничего не загружая. Выше штампа или источники сдвинулись после его даты (`git log -1 --format=%cd -- skills/iskronify/`) — прогони `iskronify` первым ходом, в чистом дереве и ветке работы, по правилу «Кто исполняет прогон»: граф прогона — сам, объёмную проекцию файлов — роль `designer`, без субагентов или роли — тоже сам. ### Дисциплина веток
Одна ветка до её мержа — доделки в неё. **Ветка — в своём рабочем дереве** (`git worktree add <каталог> -b <ветка> origin/main`), не в основной копии: её делят сессии, и `checkout` там сносит чужую работу. После мержа: `git worktree remove` своего дерева, удали слитую ветку (`git branch -d`) и прочие, уже попавшие в `main`, свои временные файлы; `git pull` в основной копии; чужие рабочие деревья не трогай; вплети отгруженное в граф (#1506, закрой разрешённые вимарши); следующую ветку — от свежего `origin/main`; подтверди уборку до следующей задачи.

## Рабочие принципы
1. **Думай до правки.** Сориентируйся в `nks-dev`, прочти карту превращений. Называй допущения; при неуверенности спрашивай, *что именно* неясно. **Вопрос человеку — текстом** (разговор, дело, пока нет места в деле — его стояние-мост); инструмент выбора вариантов — никогда: он подменяет вопрос ответом. Возражай, видя более простой ход или ложную посылку. Тронь живую систему, прежде чем верить типу, имени, доке. Вне мандата — вимарша `posed_to` #1226.
2. **Сначала простота.** Минимум правки; без спекулятивных шагов и абстракций для одноразового текста.
3. **Оставайся в границе репо.** Правки — только в рабочей директории; вне неё — чтение носителей (кэши харнессов, `~/.config/opencode` и т.п.), временный каталог сессии и дом поставки `~/.iskron-bridge` (обновление моста, живой прогон). Чужой контур (#844, nks-mcp, чужой репозиторий) — вимарша на его узле (`anga` к превращению) и слово его стюарду в деле (`iskron_case(action="talk", about=<предмет>)`). **Чужой код в контекст не бери** (#6699): в репозитории вне мандата не ходи — ни чтением, ни клоном, ни разведкой субагента; нужное для интеграции и исследования — из графа (контур того репо, его феномены, эстафеты, вопрошания) или словом его стюарду, а чего нет ни там, ни в ответе — вимаршей `posed_to` ему.
4. **Вторая имплементация — событие для доклада.** То же правило во втором скилле, тот же абзац в шаблоне и в теле — выведи оба места через `integrity`, назови человеку, предложи воссоединение или названную развилку; новый потребитель встаёт рёбрами тем же ходом.
5. **Хирургические правки.** Трогай нужные шаги; не переформатируй и не рефактори соседнее; держи регистр и терминологию бандла; не переписывай бандл ради одной починки без просьбы; чужое мёртвое флагуй, не удаляй. **Файлы правь инструментами редактирования харнесса** (чтение, правка, запись), не `sed`/`perl`/`python`/heredoc (слово владельца): правка инструментом видна диффом, требует прочтения и проходит хуки `PreToolUse`. Исключение — производные файлы, которые пишет `make`.
6. **Исполнение от цели.** Поведенческое изменение моста — падающим тестом до патча. Многошаговое — пары `шаг → проверка`. Рантайм — в реальном окружении. Фальсификатор — до взгляда; наблюдай носитель (`REALITY.md`), не исходник.
7. **Прочти, прежде чем отвечать на открытый вопрос.** Обсудить, продумать, спроектировать, «что думаешь» — из записанного, не из training data: граф несколькими способами (скилл `entry`). Выдача поиска — зацепка, не данные: структура и связи — только `iskron_look`, `iskron_orient` и линзы; субагенту — объёмная разведка кода и файлов, чтение графа для решения — твоё (#6414).
8. **Думай в графе, говори на языке проекта.** Словарь графа — для рассуждения; человеку — слова проекта, пока он не употребил первым. О работе — без ticket, task, sprint, backlog, story, done: вопрос, изменение, что открыто, что это разрешает.
9. **Смотри настоящий источник**: `skills/<name>/SKILL.md`, не зип, не установленная копия, не допущение. Имя тула проверь в поверхности, прежде чем писать его в скилл.

## Конвенции кода
- **Бренд чистый.** Бренд — **iskron** (`iskron@iskron`, `/iskron:<skill>`, `mcp.iskron.ru`), скилл бутстрапа — **`iskronify`**. Ни файл в гите, ни git-поверхность (коммит, заголовок и тело PR, ветка) не ссылается на другую скилл-дистрибуцию: ни бренд, ни имя её скилла бутстрапа, ни «upstream/апстрим», ни номера её PR. `make validate` роняет чужой бренд-токен в отгружаемом; сообщение коммита и ветку прогреби перед пушем. Отношения дистрибуций — только в графе (#844/#1506).
- **Смысл живёт в графе, код референсирует**: обоснование, отброшенные альтернативы, устройство интеграции — узел; в тексте — референс. Механика шага — словами на месте. Сославшись, проверь, что узел это говорит; разошёлся — правь узел.
- **Фронтматтер `SKILL.md`** — плоский, однострочный, ровно три ключа: `name` (kebab, = директория), `slash: true` (голое `true`; обязателен — `/name` в OpenCode 2 регистрирует плагин поставки по нему, `js/opencode/commands.ts`), `description` с явными фразами-триггерами. Выпавший триггер — тихая потеря маршрутизации. `description` — в двойных кавычках, внутренние кавычки `\"`, **под 900 байт** (за 1024 гейт роняет, готчи #4522), **без `<`/`>`** (плейсхолдеры — как `@handle/mind`; в телах угловые допустимы).
- **Имена скиллов голые** — без `nks-`/`iskron-`: плагин даёт пространство `/iskron:<skill>`; плоская установка может столкнуться — канонический канал — плагин.
- **Форма вызова скилла принадлежит харнессу**: текст, едущий в несколько харнессов одним куском (тело ролевого файла из `references/delegation.md` — в `.claude/agents/` и `.opencode/agents/`), формы вызова не несёт — называй вызовы тулов.
- **Новый скилл** — директория `skills/<name>/`, поедет автообнаружением; списков компонентов в `marketplace.json`/`plugin.json` не добавляй.
- **Никаких seq-ссылок на графы в скиллах** — у потребителей нет доступа к `nks-dev`/`methodology`; называй понятия по имени, плейсхолдеры (`#42`, `#N`) допустимы. Исключение: `methodology-work` — поиск по имени и атрибутам. В `AGENTS.md` и `REALITY.md` seq нормальны — они не отгружаются.
- **В теле скилла — чем шаг исполняют, в справке (`references/*`) — чем его чинят**: справку при подключении не открывают, исполняющий вызов (например, `Monitor` со сторожем и `persistent: true`) стоит в теле.
- **Устойчивая дверь вместо пересказанной детали**: указывай на описание тула, `action="?"`, подсказки вывода, а не на поведение, наблюдённое сегодня; пересказывай ровно то, что готов держать истинным — утверждение о поведении дрейфует молча.
- **Ссылки на тулы живые, префикс — `iskron_`**: `nks_*` роняет `make validate`; каждое имя и значение enum сверяет `make check-surface` с `fixtures/surface.json`. Выброшенных тулов не перечисляй.
- **Момент скилла на поверхности вызова**: мост приписывает к описаниям пишущих тулов (`iskron_add_*`, `iskron_batch`) строку момента скилла `writing` (`js/bridge/moment.ts`), дверь `iskron` несёт карту моментов; правя `writing`, держи оба места в ногу.
- **Терминология**: `phenomenon` — типизированный примитив, `node` — произвольный; `kriya`/`holon`/`karta`/`vimarsha` по онтологии графа; отменённые термины не возвращай.
- **Версия моста = версия плагина**: `VERSION` в `js/delivery/version.ts` (слой поставки, там же метка канала сборки) штампует release-please (строка `x-release-please-version`, файл в `extra-files`; джоб `bundle-sync` пересобирает выходы и бандлы на релизной ветке) — **руками не трогать**. Каждая синтетическая ошибка и строка `grant.log` несут `vX.Y.Z+хеш`; тест держит `VERSION == plugin.json version`.
- **Дисциплина тестов — по классу, не по списку**: у всякого отгружаемого предмета со своим набором поведенческое изменение ложится пробой тем же коммитом, и проба **сначала краснеет на старом коде** через наводку предмета: мост и `doctor` — `ISKRON_BRIDGE_PATH=<старый iskron.mjs> make test`; сторожа — та же переменная, `make test-watchdog`; pi — `ISKRON_EXTENSION=<старый extensions/iskron.js> make test-extension`; OpenCode — `ISKRON_OPENCODE_PLUGIN=<старый opencode-plugin.js> make test-opencode`; рендер роадмапа — правкой импорта; хуки ритуалов — `ISKRON_HOOKS_SETTINGS`/`ISKRON_HOOKS_SURFACES`. Сторожа проверяют только знак мёртвого токена — держание и доставку кадра тестом не имитируй. Новая проверка в `scripts/` — замерь на корпусе и покажи красной на подсунутом дефекте до включения.

## Git-воркфлоу
- **Conventional commits**; ветки `feat/…`, `fix/…`, `chore/…`; заголовки PR тем же форматом. Правка существа скилла (новое, снятое, изменённое правило или шаг) — `feat` или `fix`, никогда `docs`: тип выбирает версию релиза. `docs` — только текст, который агент не исполняет (README, SETUP, комментарии).
- **Тело PR — одна-две строки**: что изменилось, номер дела. Ход работы и строки — в деле, в PR не копируются.
- **Без агентских подписей** на git-поверхностях: ни `Co-Authored-By`, ни «Generated with …», ни ссылок на сессию — в коммитах, PR и комментариях.
- **Гейт — один вызов**: `make check` перед коммитом, звенья руками не собирай; существо прозы — глазами по дифу `SKILL.md`. CI зовёт те же звенья поимённо, по джобам (звенья без зависимостей идут без `npm ci`): меняя состав `check:` в `Makefile`, тем же ходом правь `.github/workflows/ci.yml` — полноту сверяешь глазами, чекера нет.
- **Свежесть ветки — механически**: `git fetch -q origin main && git merge-base --is-ancestor origin/main HEAD` до пуша.
- **Форжа — GitHub, CLI — `gh`**: `gh pr checks <n> --watch`, `gh pr view <n>`.
- **Живой прогон моста до релиза** (правило владельца): релиз с изменённым отгружаемым JS — только после прогона собранного `iskron.mjs` ветки (dev-сборка `dist/dev/`, в изолированном `HOME`) на этой машине против `mcp.iskron.ru` (тулы отвечают, `connect` возвращает блок моста, `watchdog` печатает `hello`, кадр соседа доходит), до мержа релизного PR. **На haiku не запускается ничего** — ни прогон, ни субагент, ни ревью (#6749, слово владельца); реализация и ревью — opus или gpt-6.1-sol.
- **Ветка не живёт без PR**: запушил ветку — тем же ходом открой PR (черновой, если работа не кончена).
- **Definition of done**: слито в `main` на `github.com/iskron-ai/skills`. **Коммит, пуш, PR и мерж — твои** (слово владельца), без просьбы; мерж — при зелёных всех проверках CI. **Релиз — только после приёмки пачки** (#6635, слово владельца): каждый выпуск перезапускает мосты и плагины у всех клиентов на всех машинах — реже, пачкой; остаток «следующим патчем» не выпускается. Ветка без пуша или пуш без PR — недоставленная работа. Закоммиченные выходы на `main` — сборка последнего выпуска, исходник `js/` их обгоняет до следующего: правка скилла, описывающая новое поведение моста или плагина, едет в одном PR с релизом или после него, не раньше (#6635). После мержа — граф #1506.
- **Пуш и `gh` — две личности**: отказ `gh pr create` рядом с работающим пушем — сперва аккаунт (готчи #4522).
- **Никогда** `--force`, `--no-verify`, `--no-gpg-sign`, `git reset --hard` без явного указания.
