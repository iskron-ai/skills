# iskron/skills
Скилл-бандлы NKS для агентов (Claude Code skills) под деплой **iskron.ru**, смотрящий на `mcp.iskron.ru`. Среди них `iskronify` — скилл, приводящий любой репозиторий к стандарту этого `AGENTS.md`.

## Проект
- **Nature**: `library` — переиспользуемые скилл-бандлы для агентов над iskron. Послабление против production: проза и методология без поведенческих тестов; ворота — человеческий обзор дифа `SKILL.md` и `make check`. Отгружаемый **код** — исключение под-контура #4057 (js-bundle): production-лестница (lint, format, strict-типы, побайтовая сверка выходов, поведенческие пробы против фейков); его отказы громки и приземляются на человека.
- **Цена поломки**: ниже, «Production statement».
- **Потребители**: агенты над iskron через плагин `iskron@iskron`, Claude Desktop (скиллы загрузкой, мост stdio-записью), pi, OpenCode, Codex; о поломке прозы не узнаёт никто — дрейф методологии; о поломке кода — человек, чей логин ушёл в никуда.
- **Стек**: markdown `skills/*/SKILL.md` → zip-бандлы `*.skill`; отгружаемый JS из `js/` (TypeScript, esbuild, без рантайм-зависимостей); поставка в четыре канала.
- **Гейт**: `make check`.
- **Раскладка**: один `AGENTS.md`; карта кода — README компонентов по умолчанию (`js/` — первый, кто тронет компонент, пишет его README); исключение — выходы под `skills/`: README там уезжает потребителю, их навигация — «Структура проекта» здесь; ловушки — граф (#4522), `GOTCHAS.md` нет.
- **Фидбэк-рефлексия**: да — на мерже и на закрытии сессии, адресно по решению #3958 (скилл `feedback`).
- **Interop с workflow-набором**: нет — коэрсивный набор не установлен.

**Поставка и релиз.** Маркетплейс плагинов Claude Code (`iskron@iskron`); семвер в `.claude-plugin/plugin.json` поднимает **release-please** из Conventional Commits на `main` (feat→minor, feat!/BREAKING→major, иначе patch): мерж релизного PR пишет версию, тег `vX.Y.Z`, GitHub Release и `CHANGELOG.md` — никогда руками (`.github/workflows/release-please.yml`, `release-please-config.json`). Путь к графу один — stdio-мост из поставки (слово владельца, #6728; `make validate` роняет отгружаемую запись не stdio): `.mcp.json` плагина — ровно токен `${CLAUDE_PLUGIN_ROOT}` (#4522), манифест Codex — та же запись объектом `mcpServers`, OpenCode — плагин поставки (`~/.config/opencode/plugins/iskron.js`), не запись `mcp`; для разработки — пользовательская запись `iskron-bridge` (скилл `establish-mcp`; вход — OAuth либо личный токен `ISKRON_BRIDGE_TOKEN` / `~/.iskron-bridge/token`). CI — `.github/workflows/ci.yml`.

**Production statement.** Скиллы определяют, как каждый агент над iskron пользуется NKS через `mcp.iskron.ru`. Неверная инструкция (например, тул, который сервер выбросил) тихо деградирует каждого агента, загрузившего скилл: краха нет, есть дрейф методологии; потребитель — агент. Синхрон скиллов с поверхностью тулов — основная обязанность.

## Правила персистентности
Состояние живёт в **репо** или в **графе** — больше нигде. Встроенная память харнеса (директория памяти, сводки разговоров, `/tmp`, машинно-локальные файлы) **запрещена целиком, не по категориям**; временный каталог — только скретч сессии, и она его убирает.
- **Репо**: `skills/<name>/SKILL.md` (источник истины), производные бандлы, `README.md`, `REALITY.md`, соглашения и ритуалы, состояние веток.
- **Граф** (`nks-dev`): решения, вопросы по сути (вимарши), планы (карта превращений), уроки, подсказки; ловушки — #4522. Граф в репо не пересказывай — линкуй.
- **Дело** (разговор на узле графа): разовые постановка, вопрос, договорённость, приём; ход и исход работы — строками его сводки («Работа идёт в графе» ниже); состояние того, что работа меняет, — в графе (#6717).
- **Источник истины — `skills/<name>/SKILL.md`**; зипы `<name>.skill`, установленная копия в `~/.claude/skills/` и кэше плагинов — производные: правь исходник, гони `make build`.
- **Доставай состояние, не вспоминай.** Нет источника у «мы решили…» — прочти граф или репо до действия.
- **Узел не записан, пока не назван тянущий его** — какая крия сломается, если он исчезнет? Укрытия и форма записи — скилл `writing`.
- **Чей это факт?** — спрашивай всегда, поверх инструкции памяти харнеса; прежде чем закончить, разнеси каждый долгий факт разговора: свойство кода, ритуал, команда, порядок этого репо → этот файл; ловушка → #4522; смысл кода (решения, основания, связи) и знание, переживающее рефактор, → граф `nks-dev` (#6412), решение — узлом сразу; серверы, датированные долги (дата — в `attrs`) → узел; вопрос по сути, обязательство → вимарша; разовое → слово в деле; ход работы → модусы узлов; о другом проекте → его граф. Правило и способ самого проекта — здесь по полномочию. Собственное пользователя сюда не пишется — где оно живёт, решает дверь `iskron`.
- **Проектные инструкции — коммитящиеся файлы рабочего дерева (AGENTS.md, файл хуков) и граф проекта**: никогда глобальный файл инструкций, память харнеса, пользовательские хуки; личные предпочтения в проект не копируются; установка поставки (мост, его дом, плагин) — доставка, не настройка.
- Директория памяти **эвакуирована и заморожена**: держит memory-guard `PreToolUse` в `.claude/settings.json` (блок, exit 2); стаб не создаётся (прежний `MEMORY.md` остаётся как есть); поля `rituals:` хук не читает — выключая `guard`, сними и его.

## Жизненный цикл сессии
Список правил — по строке на правило; полная норма — «Сквозные нормы» скилла `iskron`.
- **Граф — работа, git — как пришли.** SHA, ветки, номера PR, «merged» в граф не пишутся (тела, имена, атрибуты); провенанс — в `reasoning` записи; в деле — свободно.
- **Старт сессии** — раздел «Старт» двери `iskron` до действий и до готовности, не только чтения. Адреса — из обложки; вход по строке `start`, квитанция и собственный мост субагента — по справке `start.md` двери.
- **Адреса**: граф `@nks/nks-dev` (`r5`), фокус-контур #1506 (под RU-деплоем #1086), роль агента #931 (стюард и соседнего скилл-репо #844). Работа над мостом, сторожами, рендером роадмапа, расширением pi или плагином OpenCode ориентируется на под-контуре **#4057** (`iskron_orient(realm="@nks/nks-dev", focus="4057")`): обязательства кода — стояние, привязка, слух — записаны только там.
- **Уборка — каждым законченным куском** («Уборка» в «Сквозных нормах» скилла `iskron`): скретч и свои кэши разработки — тем же ходом, дерево и ветка — «Дисциплина веток»; из дел, где твоего хода не ждут, — свои строки исходом и `leave` (ведущий — `propose_close` или передача ведения). Сидишь только там, где ждёшь ответа или ведёшь незакрытое.
- **Ремесло графа — у решающего** (#6717): чтение для решения, решение, ткачество, интеграция и приёмка («Ремесло графа» в «Сквозных нормах» скилла `iskron`). Субагентам со своим мостом-спутником — объёмное по готовому решению: код, гейт, ревью, проверка, правка многих задетых узлов с референсами на решение и окрестность; поиск по лестнице `recall` — `recaller` (находку решающий открывает сам), впуск сложного рассказа — `ingester`; итог сверяет запустивший.
- **Начало работы: граф, потом проект, потом код.** (1) разведка графа (`entry`): записанное о месте изменения, открытые вимарши, решённое и отвергнутое, записанное о внешних поверхностях; (2) поле интеграции от #1506 (для кода — от #4057), #931 и узлов изменения (`integrity`, раздел ниже); (3) проектирование (`design`), затем правка. Пропуск — только по явному «работай сразу» или другому названному протоколу, долг разведки — на reconcile; молчание человека — не разрешение (#6409).
- **Решение — в граф в момент принятия**, откуда бы ни пришло (чат, сокет, договор агентов), — в холон #1506 правкой задетого и связями, тезис — своим узлом, общий канон не правя (#8922); модусы — по `writing`; что считается исполнением — в узле; кто решил — в `reasoning` и деле, не в узле. Изменившаяся ситуация — так же сразу.
- **Задача описана до начала — тем, что она есть.** Разовая — в одном деле: постановка и договорённость — словом, ход и исход — строками по `cases.md` двери `iskron`; пришла без дела — открой его (`open_room` на узле предмета либо `iskron_case(action="talk", about=<предмет>)`) до первой перемены снаружи. В граф — переходы, которые она меняет, и решения. Вимарша — только вопрос по сути или обязательство; крия — повторяемый переход. Различение задачи и законной односторонней крии края — по `reconcile`, проходка 2.
- **Работа идёт в графе** (#6717) — «Сквозные нормы» двери `iskron`; до хода в деле прочти её справку `cases.md`, ведёшь дело — ещё `leading.md`. Там живут различение графа и дела, адресация, форма хода/исхода и передача ведения; здесь метод не копируется.
- **Итерация — только задетое**: пока правишь, гоняй пробы задетого и зависимых (проза — `make validate check-bundles`, код — `make lint typecheck` и `make test-<предмет>`), полный гейт `make check` — один раз на кандидате слияния (пуш, после которого мержишь); прошедшее на том же дереве не повторяй — и CI тоже.
- **Мерж → граф.** Пуш, открывший или обновивший PR, не отгрузил ничего: тела и модусы описывают то, что несёт `main`; последовательность висит на событии мержа, не на затишье. Все акты обязательны — кроме работы по ссылке от агента (постановка референсами, отчёт в деле): там ткачество, закрытие по оси и сведение — постановщику, делателю — семя превращения и модусы поставки (скилл `vahta`):
  - **Протки** (`weaving`): отгруженное — в контур #1506 узлами и рёбрами, не абзацем; механика репо остаётся в git. Ноль узлов и стрелок после содержательной волны — скажи прямо, почему.
  - **Продвинь карту**: открытая работа — `anga` к превращению; семя `genre=hint` одно на превращение — только не восстановимое чтением графа и дел; живые дела — указателем на их чтение (`iskron_case(action="at")`, `read`), номер — только где существенный выбор иначе не восстановить.
  - **Переключи модусы** по свидетельству на носителе (`REALITY.md`, **reality-audit**), не по мержу: мерж двигает узлы того, что несёт код; практику (`anagata→vartamana`) — выкат или прогон, увиденный на носителе (`anumita`), наблюдённый — `pratyakshita`.
  - **Закрой по оси** (`inquiry`): `addressed_by` к несущему узлу; `visarjana` — когда ответ стоит узлом, репо его показывает и реальность показывает достижимость (где нет — слово пользователя); иначе предъяви владельцу. Тем же ходом — инбокс `posed_to` (будит перемена у якоря, не возраст), `propose_close` со свидетельством.
  - **Сведи — `reconcile`**: узлы против кода, код против графа, отброшенное записано и референсируемо; остаток — вимаршами.
  - **Фидбэк-рефлексия** — на мерже и на закрытии сессии без мержа: опыт *о методе* (скилл, правило, поверхность подвели или удивили) — случаем, не мнением, после проверки на сказанное, в `@nks/nks-dev` якорем на узел инструмента, адресом его стюарду — маршруты по #3958 (скилл `feedback`). Ноль записей — валидный исход.
  - **Словарный проход**: заимствованные слова (список — принцип 8) в приземляемом тексте и узлах назови человеку и спроси, как это зовётся в проекте; сам не подменяй.
- **Дизайн не готов, пока решения, риски и жизненный цикл не в графе** — каким бы скиллом ни элиситирован; внешний design/spec-файл — черновик на впуск в той же сессии, решения держит граф. Без владельца: решения и риски — сейчас, превращение — с телосом на подтверждение.
- **Наборы исполнения ведут исполнение** (план, TDD, отладка, ревью); граф несёт память и дизайн: решения и риски исполнения — в граф до конца сессии.
- **Общая методология остаётся общей**: существо скиллов (навигация, создание узла, приведение репо к стандарту, intake, roadmap, вахта) смоделировано под #844/methodology — не дублируй под #1506; свой узел — только расхождение iskron с общей версией.
- **Синхрон «скилл ↔ тул» — постоянный двигатель**: сервер за `mcp.iskron.ru` переименовал или выбросил тул — правки скиллов ложатся сюда, в тот же отрезок.
- **Утверждение, которое ты сделал, — не утверждение, которое ты принимаешь.** Поведенческое («мост переживает смену сессии», «бандл ставится», «имя тула живо») закрывает холодный `verifier`: бриф — утверждение, носитель и фальсификатор из `REALITY.md`; дождись вердикта.
- **Мерж хуков**: в `.claude/settings.json` записи разных наборов сосуществуют — добавляй рядом, чужие не перезаписывай.
- Ритуалы старта, пуша и мержа несёт поставка по обложке; memory-guard — Claude Code: в репо (`.claude/settings.json`), OpenCode: несёт поставка. Interop-подсекции нет.
- **Держи этот файл честным.** Контракт — число после «КОНТРАКТ AGENTS.md:» в начале описания скилла `iskronify`: сравни с `contract` обложки, ничего не загружая. Выше `contract` или источники сдвинулись после `stamp` (`git log -1 --format=%cd -- skills/iskronify/`) — прогони `iskronify` первым ходом, в чистом дереве и ветке работы, по правилу «Кто исполняет прогон»; прогон не ждёт человека, порядок слотов — Шаг 1 `iskronify` (#6553); новый вопрос по слоту — слово в деле выравнивания на #1506, не узел. Здесь источник обгоняет установленный плагин: расхождение «описание против `contract`» на этой машине нормально до обновления плагина; авторитет — `skills/iskronify/SKILL.md`. **Ниже `contract`** — файл впереди поставки: не понижай и прогон не зови, обнови затеняющую копию и перечитай описание. Строка файла расходится со скиллом — назови вслух (в деле постановщику, иначе человеку): `contract` ниже — прав скилл; выше — прав файл; равен — дефект шаблона, фидбэк на #1506 адресом #931.
- **Держи тулчейн свежим**: обновления включены по умолчанию, бери как доставляет канал, не пинь. Канал без автообновления (распакованная копия) — проверь версию перед сессией или переезжай.

### Самопроверка этапа
Гейт зелёный и связный этап закончен (открыт или обновлён PR, либо собираешься тронуть узлы за пределами начальных) — перечитай дифф ветки против транка: неверные поведенческие утверждения о тулах, мёртвые указатели, разошедшиеся с источником производные строки, проза, которой место в графе, правки за пределами задачи; в коде `js/` — ещё баги, хрупкие места, слабая обработка ошибок, нарушения DRY/SOLID, недостающие или бесполезные тесты, файлы за 150 строк и бог-юниты. Чини в той же ветке или прямо скажи, что ничего не всплыло; находок не выдумывай. По этапу, не только в конце.

### Ревью и приёмка — чистым агентом против графа и диффа

Правило метода; канон и свидетельства живут узлом — граф `@nks/nks-dev`, `#3600`. Прежде чем отдать PR на ревью, прочти узел и исполняй, как там написано: копии текста здесь нет нарочно — файл несёт факты о коде и референсы на граф (`#4127`), а копия чужого канона расходится молча. Ниже — только то, что этому репо своё.
- **Самопроверка — всегда, холодное ревью после неё — где положено ниже.**
- **Ревью кода до мержа — только рефакторинг и крупная фича** (`js/`, код в `references/`, хуки, `scripts/`, CI), раз на готовую пачку (#8913, #8912; одна ветка и один PR на пачку — #8852; микроветки и подтяжка `main` без круга — #8915). Мелкое автор так и зовёт строкой в деле, ревьюер или мержащий вправе оспорить (#8914); его ревью — субагентом после мержа, не блокирует (#8921). Пачка-релиз — одно полное ревью перед мержем (#8916). Второе семейство на код — только по слову владельца с моделями (#8917). CI, тесты и проверка угрозы безопасности или потери данных — на каждой пачке.
- **Тела скиллов — вычитка перед релизом разными семействами моделей, обязательно** (#6540): на собранном кандидате тега рецензенты из Sol, Opus, GLM ищут разбухание, противоречие между текстами (карта норм #8078) и отход от канона; находка называет номер критерия #8077. Противоречие и отход от канона держат релиз; без этой вычитки тег не режется. На пачку тела скиллов ревью не получают.
- Ревьюер — роль `reviewer` (`.claude/agents/reviewer.md`), **в отдельном worktree** (`isolation: "worktree"`; запрет в брифе — вторая линия, #4043); где порождающий тул изоляции не даёт (OpenCode) — ведущий сам кладёт отрешённое дерево (`git worktree add --detach .worktrees/<имя> <голова>`), путь — в бриф строкой «работай только там», в отчёте — «изоляция ручная». Корень обхода владения — #1506 и #931. Возвращает находки и отчёт интеграции: затронутые контуры и роли, эстафеты, кого будить. Сторож есть только у пуша: этап без пуша держишь ты.

### Дисциплина веток
Одна ветка и один PR на пачку (#8852): пункты и работы субагентов вливаются в неё локально. **Ветка — в своём рабочем дереве внутри репо** (`git worktree add .worktrees/<ветка> -b <ветка> origin/main`; `.worktrees/` в `.gitignore`, #9109), не в основной копии и не рядом с репо: основную делят сессии, и `checkout` там сносит чужую работу. После мержа: `git worktree remove` своего дерева, `git branch -d` слитой и прочих, уже в `main`, свои кэши разработки (#9111); `git pull` в основной копии; вплети отгруженное в граф (#1506, закрой разрешённые вимарши); следующую ветку — от свежего `origin/main`; подтверди уборку до следующей задачи. **Брошенное дерево** (ветка в `main` или удалена на форже, копия чистая) убирает любой агент репо (`git worktree remove`, `prune`, `git branch -d`); незакоммиченное или неслитое не трогай — назови держателю или человеку (#9110). Дерево оркестратора `.worktrees/orchestra-<операция>` брошенным и своим не бывает, даже если в нём работал ты: в нём живёт терминал поднятого агента, освобождает его оркестратор; `unlock`, `move`, `remove --force`, `rm -rf` по нему запрещены (#10603).

## Рабочие принципы
1. **Думай до правки.** Сориентируйся в `nks-dev`, прочти карту превращений. Называй допущения; при неуверенности спрашивай, *что именно* неясно. **Вопрос человеку — словами, не тулом выбора**: текстом — только тому, кто отвечает сейчас; переживший такт — карточкой `ask` в деле («Вопрос человеку» двери `iskron`; дела нет — возьми его; места нет — его стояние-мост). `question` (OpenCode) и `AskUserQuestion` (Claude Code) запрещены плагинами и проектными permissions/policies; проверка — `node ~/.iskron-bridge/iskron-bridge.mjs check-rituals`. Возражай, видя более простой ход или ложную посылку. Тронь живую систему, прежде чем верить типу, имени, доке.
2. **Сначала простота.** Минимум правки; без спекулятивных шагов и абстракций для одноразового текста.
3. **Оставайся в границе репо.** Правки — только в рабочей директории; вне неё — чтение носителей (кэши харнесов, `~/.config/opencode`…), скретч сессии и дом поставки `~/.iskron-bridge` (обновление моста, живой прогон). Чужой контур (#844, nks-mcp, чужой репозиторий) — вимарша на его узле (`anga` к превращению) и слово его стюарду в деле (`iskron_case(action="talk", about=<предмет>)`). **Чужой код в контекст не бери** (#6699) — ни чтением, ни клоном, ни разведкой субагента: нужное — из графа (контур того репо, феномены, эстафеты, вопрошания) или словом стюарду; чего нет ни там, ни в ответе — вимаршей `posed_to` ему.
4. **Вторая имплементация — событие для доклада.** То же правило во втором скилле, тот же абзац в шаблоне и в теле — выведи оба места через `integrity`, назови человеку, предложи воссоединение или названную развилку; новый потребитель встаёт рёбрами тем же ходом.
5. **Хирургические правки.** Трогай нужные шаги; не переформатируй и не рефактори соседнее; держи регистр и терминологию бандла; не переписывай бандл ради одной починки без просьбы; чужое мёртвое флагуй, не удаляй. **Файлы правь инструментами редактирования харнеса** (чтение, правка, запись), не `sed`/`perl`/`python`/heredoc (слово владельца): правка инструментом видна диффом, требует прочтения и проходит хуки `PreToolUse`. Исключение — производные файлы, которые пишет `make`.
6. **Исполнение от цели.** Поведенческое изменение моста — падающим тестом до патча. Многошаговое — пары `шаг → проверка`. Рантайм — в реальном окружении. Фальсификатор — до взгляда; наблюдай носитель (`REALITY.md`), не исходник.
7. **Прочти, прежде чем отвечать на открытый вопрос** — из записанного, не из training data (скилл `recall`). Выдача поиска — зацепка, не данные: структуру и связи читай `iskron_look`, `iskron_orient`; субагенту — разведка кода и файлов (`reader`), поиск по графу (`recaller`); чтение найденного для решения — твоё (#6414).
8. **Думай в графе, говори на языке проекта.** Словарь графа — для рассуждения; человеку — слова проекта, пока он не употребил первым. Заимствованное о работе — ticket, task, sprint, backlog, epic, story, done, blocker, committed — сам не подменяй: назови и спроси, как это зовётся в проекте («Словарный проход»); говори: вопрос, изменение, что открыто, что это разрешает.
9. **Смотри настоящий источник**: `skills/<name>/SKILL.md`, не зип, не установленная копия, не допущение. Имя тула проверь в поверхности, прежде чем писать его в скилл.

## Внешние поверхности — то, чем пользуешься и чем не владеешь
Здешние:
- **поверхность тулов сервера за `mcp.iskron.ru`** — снимок `fixtures/surface.json`, `make check-surface`;
- **файловые поверхности агентов Claude Code и OpenCode** — чеклист пересверки в `skills/iskronify/references/delegation-1.md` и `delegation-2.md` (обе части по порядку; `delegation.md` — оглавление);
- **плагинная поверхность OpenCode 2** (`@opencode/plugin` 2.0.4, dev-зависимость только ради типов, `make typecheck`) — узел #5048;
- **загрузчик скиллов claude.ai** (им загружает и Claude Desktop) — отвергает описание с содержимым в форме XML-тега, отсюда запрет `<`/`>` в `description`.

Правила:
- **Прежде работы зафиксируй трогаемую часть поверхности** узлом в графе, с версией.
- **Пратьякша прежде шабды**: наблюдение своими руками (ответ, `--help` установленного бинаря, `make surface`) старше доков, доки старше памяти, память — не источник. `pratyakshita` — только наблюдённое.
- **Протки связь**: узел поверхности — `upadhi` к крие, что через него действует.
- **Держи в ногу**: расхождение или новая версия — правь узел тем же ходом, эпистемику опусти, если не наблюдал.
- Исходник у поверхности в `js/` несёт `(граф @nks/nks-dev, узел #N)` — этот узел читай перед работой; в `SKILL.md` seq не пишется («Конвенции кода»).

## Reality — против чего проверяется заявка

## Стек

Отгружаемый код — TypeScript под strict в `js/` (`bridge/`, `watchdog/`, `cli/`, `extension/`, `opencode/`, `roadmap/`, общее в `shared/`, слой поставки `delivery/` — #6806), однофайловые выходы без зависимостей (под-контур #4057): все каналы установки ставят `main`, поэтому **закоммиченные выходы — всегда сборка выпуска**, их пишет только джоб выпуска (`make build-release`); `make build-js` рабочей копии кладёт dev-сборку в `dist/dev/` (вне индекса) — ею гонятся пробы и живые прогоны. ## Конвенции кода
- **Бренд чистый.** Бренд — **iskron** (`iskron@iskron`, `/iskron:<skill>`, `mcp.iskron.ru`), скилл бутстрапа — **`iskronify`**. Ни файл в гите, ни git-поверхность (коммит, заголовок и тело PR, ветка) не ссылается на другую скилл-дистрибуцию: ни бренд, ни имя её скилла бутстрапа, ни «upstream/апстрим», ни номера её PR. `make validate` роняет чужой бренд-токен в отгружаемом; сообщение коммита и ветку прогреби перед пушем. Отношения дистрибуций — только в графе (#844/#1506).
- **Смысл живёт в графе, код референсирует**: обоснование, отброшенные альтернативы, устройство интеграции — узел; в тексте — референс. Механика шага — словами на месте. Сославшись, проверь, что узел это говорит; разошёлся — правь узел.
- **Фронтматтер `SKILL.md`** — плоский, однострочный, ровно три ключа: `name` (kebab, = директория), `slash: true` (голое `true`; по нему `/name` в OpenCode 2 регистрирует плагин поставки), `description` с явными фразами-триггерами (выпавший триггер — тихая потеря маршрутизации): в двойных кавычках, внутренние `\"`, **под 900 байт** (за 1024 гейт роняет), **без `<`/`>`** (плейсхолдеры — как `@handle/slug`; в телах угловые допустимы) — #4522.
- **Имена скиллов голые** — без `nks-`/`iskron-`: плагин даёт пространство `/iskron:<skill>`; канонический канал — плагин.
- **Форма вызова скилла принадлежит харнесу**: текст, едущий в несколько харнесов одним куском (тело ролевого файла из `references/delegation-1.md`/`delegation-2.md`), формы вызова не несёт — называй вызовы тулов.
- **Новый скилл** — директория `skills/<name>/`, поедет автообнаружением; списков компонентов в `marketplace.json`/`plugin.json` не добавляй.
- **Никаких seq-ссылок на графы в скиллах** — у потребителей нет доступа к `nks-dev`/`methodology`; называй понятия по имени, плейсхолдеры (`#42`, `#N`) допустимы. Исключение: `methodology-work` — поиск по имени и атрибутам. В `AGENTS.md` и `REALITY.md` seq нормальны — они не отгружаются.
- **Размещение обязательного шага** — по #9994: в харнесе с чтением справок обязательное допустимо в `references/*`, если тело явно велит прочесть целиком до хода, файл укладывается в предел клиента и полная доставка проверена; без чтения справок обязательное остаётся в теле. Указатель доставкой не считается.
- **Устойчивая дверь вместо пересказанной детали**: указывай на описание тула, `action="?"`, подсказки вывода, а не на поведение, наблюдённое сегодня; пересказывай ровно то, что готов держать истинным — утверждение о поведении дрейфует молча.
- **Ссылки на тулы живые, префикс — `iskron_`**: `nks_*` роняет `make validate`; каждое имя и значение enum сверяет `make check-surface` с `fixtures/surface.json`. Выброшенных тулов не перечисляй.
- **Момент скилла на поверхности вызова** — описания пишущих тулов доходят серверными байт в байт, строку момента мост к ним не приписывает (#7557; механика — `js/bridge/moment.ts`); момент несут карта моментов двери `iskron` и описание сервера; правя `writing`, держи карту моментов в ногу.
- **Терминология**: `phenomenon` — типизированный примитив, `node` — произвольный; `kriya`/`holon`/`karta`/`vimarsha` по онтологии графа; отменённые термины не возвращай.
- **Версия моста = версия плагина**: `VERSION` в `js/delivery/version.ts` штампует release-please — **руками не трогать**; каждая синтетическая ошибка и строка `grant.log` несут `vX.Y.Z+хеш`; тест держит `VERSION == plugin.json version`.
- **Дисциплина тестов — по классу, не по списку**: у всякого отгружаемого предмета со своим набором поведенческое изменение ложится пробой тем же коммитом, и проба **сначала краснеет на старом коде** через наводку предмета: мост и `doctor` — `ISKRON_BRIDGE_PATH=<старый iskron.mjs> make test`; сторожа — та же переменная, `make test-watchdog`; pi — `ISKRON_EXTENSION=<старый extensions/iskron.js> make test-extension`; OpenCode — `ISKRON_OPENCODE_PLUGIN=<старый opencode-plugin.js> make test-opencode`; рендер роадмапа — правкой импорта; хуки ритуалов — `ISKRON_HOOKS_SETTINGS`/`ISKRON_HOOKS_SURFACES`. Сторожа проверяют только знак мёртвого токена — держание и доставку кадра тестом не имитируй. Новая проверка в `scripts/` — замерь на корпусе и покажи красной на подсунутом дефекте до включения.

## Git-воркфлоу
- **Conventional commits**; ветки `feat/…`, `fix/…`, `chore/…`; заголовки PR тем же форматом. Правка существа скилла (новое, снятое, изменённое правило или шаг) — `feat` или `fix`, никогда `docs`: тип выбирает версию релиза. `docs` — только текст, который агент не исполняет (README, SETUP, комментарии).
- **Тело PR — одна-две строки**: что изменилось, номер дела. Ход работы и строки — в деле, в PR не копируются.
- **Без агентских подписей** на git-поверхностях: ни `Co-Authored-By`, ни «Generated with …», ни ссылок на сессию — в коммитах, PR и комментариях.
- **Гейт — один вызов**: `make check`, когда — «Итерация» в «Жизненном цикле сессии»; звенья руками не собирай; существо прозы — глазами по дифу `SKILL.md`. CI — на PR пачки и `main`, зовёт те же звенья поимённо: меняя состав `check:` в `Makefile`, тем же ходом правь `.github/workflows/ci.yml` — полноту сверяешь глазами, чекера нет.
- **Свежесть ветки — механически**: `git fetch -q origin main && git merge-base --is-ancestor origin/main HEAD` до пуша.
- **Форжа — GitHub, CLI — `gh`**: `gh pr checks <n> --watch`, `gh pr view <n>`. Пуш и `gh` — две личности: отказ `gh pr create` рядом с работающим пушем — сперва аккаунт (#4522).
- **Релизный PR — только squash**: после зелёных текущих проверок `gh pr merge <n> --squash --match-head-commit <sha>`; сохраняй заголовок release-please `chore(main): release …`. `--merge` и rebase для выпуска не подходят: `scripts/check-outputs-frozen.sh` опознаёт разрешённую перемену выходов по squash-коммиту с автором release-please, коммиттером GitHub и этим заголовком (#4218). Красный post-merge CI не обходи правкой гейта или переписыванием тега; доставка ждёт полного зелёного main CI на неизменных выпускных байтах.
- **Живой прогон моста до релиза** (правило владельца): релиз с изменённым отгружаемым JS — только после прогона собранного `iskron.mjs` ветки (dev-сборка `dist/dev/`, изолированный `HOME`) против стенда или изолированного LOCAL, не боя (#7544): тулы отвечают, `connect` возвращает блок моста, `watchdog` печатает `hello`, кадр соседа доходит; и **переход с прошлого выпуска**: места прошлого демона возвращаются мосту ветки без `take`, ни одна сессия не встаёт рядом (#6702). CI релизного PR гоняет пробы против сборки выпуска, соединения в нём нет (#4309); носитель прогона не гасят до вердикта холодного верификатора — иначе он только сверяет вывод, не повторяет (7.33.0, 7.34.0); после прогона и вердикта стюард ставит на PR метку `live-run` — без неё джоб `live-run` красный и мерж не идёт. **На haiku не запускается ничего** — ни прогон, ни субагент, ни ревью (#6749, слово владельца); реализация и ревью — opus или gpt-6.1-sol; вычитка тел скиллов на кандидате тега — разные семейства из Sol, opus, glm (#6540).
- **Ветка пачки не живёт без PR**: запушил — тем же ходом открой PR (черновой, если пачка не собрана). Ветка без пуша или пуш без PR — недоставленная работа.
- **Definition of done**: слито в `main` на `github.com/iskron-ai/skills`. **Коммит, пуш, PR и мерж — твои** (слово владельца), без просьбы; мерж — при зелёных всех проверках CI. **Готовое, влитое с зелёным CI и не ломающее соседей, выпускается сразу** (слово владельца 06.11, дело №3195): общих релизов и ожидания пачки нет, владельца и ведущего о выкате не спрашивают; держит выкат только названная поломка или зависимость. Перед тегом неизменно: вычитка тел скиллов разными семействами (#6540) и живой прогон моста (выше). На каждый тег — строка «совместимо с боями: …» и ref операторам: **выпуск не кончается тегом** — тег и коммит выпуска RU-оператору (#7660) делом на доставке каталога в дом (#3020, пин `SKILLS_REF`+`SKILLS_COMMIT`, #7562); выпуск доставлен, когда оператор наблюдал новые ref и commit в доме. Закоммиченные выходы на `main` — сборка последнего выпуска, исходник `js/` их обгоняет до следующего: правка скилла, описывающая новое поведение моста или плагина, едет в одном PR с релизом или после него, не раньше. После мержа — граф #1506.
- **Никогда** `--force`, `--no-verify`, `--no-gpg-sign`, `git reset --hard` без явного указания.
