# iskron-ai/skills

Агентские скилл-бандлы для работы с **NKS** (Nyāya Knowledge System) — методом структурного вопрошания над направленным графом. Это скиллы Claude Code, которые учат агента читать, писать, проектировать и ткать граф NKS через MCP-тулы `iskron_*`, подключённые к `mcp.iskron.ru`.

## Как этим пользоваться

Дверь одна — **`/iskron`**, и дальше своими словами:

```
/iskron почему мы решили держать мост, а не нативный OAuth?
/iskron запиши, что сторожа теперь два и второй выходит на кадре
/iskron продумай, как скиллу отличать запрос человека от запроса агента
/iskron проверь, правда ли бандл ставится на чистой машине
/iskron собери роадмап по этому репозиторию
/iskron разберись, что у меня висит открытым, и закрой отвеченное
/iskron меня не слышно на канале
```

(В Claude Code с установленным плагином дверь набирается `/iskron:iskron` — имя плагина неймспейсит скиллы; в харнессах без неймспейса работает `/iskron`.)

Дальше агент сам решает, чем твой запрос исполняется — одним методом поставки или их цепочкой, — и **делает работу**, а не советует, к чему обратиться. Имён внутри знать не нужно: это его устройство, не твоё.

Под дверью лежат методы на все стороны работы с графом — чтение и ориентация, запись, проектирование, ткачество, приёмка поведения, сверка кода с графом, впуск внешнего слова, живой канал между делателями, приведение репозитория к стандарту, роадмап. Каждый — отдельный скилл со своим именем; знаешь имя — зови напрямую, так короче. Не знаешь — не нужно.

Тексты скиллов — русские, выведенные из канона графа методологии (не перевод: ре-деривация).

## Установка

### Быстрее всего: отдай установку своему агенту

Вставь этот промпт в агента, которым уже пользуешься (Claude Code, Cursor, Codex):

```
Установи мне скиллы iskron: скачай https://raw.githubusercontent.com/iskron-ai/skills/main/SETUP.md
и выполни все шаги автономно, спросив мой токен, когда понадобится.
```

[`SETUP.md`](SETUP.md) — установщик, исполняемый агентом: обычный markdown, можно прочесть заранее. Ручные пути ниже — по харнессу.

### Claude Code

```sh
/plugin marketplace add iskron-ai/skills
/plugin install iskron@iskron
```

Все скиллы ставятся вместе под плагином `iskron`, мост к графу приходит записью MCP самого плагина. Claude Code неймспейсит скиллы именем плагина, поэтому дверь там набирается `/iskron:iskron`; в харнессах без неймспейса — просто `/iskron`. Модельный вызов работает сам. Кадры живого канала Claude Code в сессию сам не кладёт: их слышит сторож моста, которого агент должен поднять под `Monitor` (скилл `standing`), — не поднял, и канал глух.

**Обновление.** Мост обновляет себя сам (раз в шесть часов спрашивает релизы, свежее кладёт в `~/.iskron-bridge` и говорит агенту строкой в ответе), а скиллы — канал харнесса; проще всего сказать агенту «обнови»: дверь `/iskron` прогонит `node ~/.iskron-bridge/iskron-bridge.mjs update` и свежий `SETUP.md`. Руками: `iskron` — сторонний marketplace, поэтому — в отличие от официального маркетплейса Anthropic — он **не** автообновляется. Всё неофициальное обновляется вручную:

```sh
/plugin marketplace update iskron
/reload-plugins
```

Или один раз включи автообновление: `/plugin` → **Marketplaces** → `iskron` → **Enable auto-update** (тогда плагин освежается при старте).

### Codex

```sh
codex plugin marketplace add https://github.com/iskron-ai/skills
codex plugin add iskron@iskron
```

Скиллы и мост приходят плагином (запись MCP в его манифесте), грант мост держит свой — логиниться в Codex не нужно. Кадр живого канала входит в идущий тред дверью демона app-server; условие у неё одно — демон и сессия под одним коротким `CODEX_HOME`, рецепт в `SETUP.md`, ветка Codex.

### OpenCode

Плагин из той же поставки: тулы `iskron_*` под своими именами, кадры живого канала промптом в сессию, стояние держит мост. После плоской установки скиллов (npx, ниже) скопируй два файла из скилла `establish-mcp` — мост в `~/.iskron-bridge/iskron-bridge.mjs` и `scripts/opencode-plugin.js` в `~/.config/opencode/plugins/iskron.js`; команды — в `SETUP.md`, ветка OpenCode. Мост принимает и личный токен доступа вместо OAuth (`~/.iskron-bridge/token` или `ISKRON_BRIDGE_TOKEN`) — для безголовых машин и харнессов, чей OAuth не доходит.

### Pi

```sh
pi install git:github.com/iskron-ai/skills
```

Ставит скиллы **и** расширение `iskron` разом. Расширение — то, чего плоская установка дать не может: тулы `iskron_*` поднимаются прямо в сессии через встроенный мост (отдельно подключать граф-сервер не нужно — первый вызов уводит в браузер на обычный OAuth), а сокет живого канала держит сама сессия, без отдельного сторожа. Стояние агент занимает сам, изнутри — позвал `iskron_channel(action="connect")` и `register`, и слушание включилось: адрес сокета из ответа расширение берёт само, сессии не покидая. Обновление — `pi update git:github.com/iskron-ai/skills` (или `pi update --extensions`, чтобы обновить сразу все установленные пакеты).

### claude.ai

Плагин целиком: каждый [релиз](https://github.com/iskron-ai/skills/releases/latest) начиная с v3.2.0 несёт `iskron.zip` — архив плагина. Загрузи его как плагин в claude.ai; для обновления загрузи ассет более свежего релиза — то же имя плагина перезаписывает установленную копию. Автообновления у этого канала нет: установлено то, что ты загрузил последним (его `version` лежит в `.claude-plugin/plugin.json` внутри архива).

### Любой другой агент: плоская установка (npx)

Cursor, Windsurf и ещё полсотни харнессов — и скиллы для OpenCode:

```sh
npx skills add iskron-ai/skills --all --global
```

Ставит **плоско**, в общую директорию скиллов под голыми именами (`design`, `writing`, …) — возможны коллизии с одноимёнными скиллами других паков; в этом случае переименуй целевую директорию. Плагины Claude Code и Codex неймспейсят скиллы (`/iskron:design`) и таких коллизий не знают; на их установку плоская не влияет.

Два флага, и оба несущие. `--all` — это `--skill '*' --agent '*' -y`: все скиллы всем харнессам сразу, поэтому дописывать к нему `--agent claude` значит его же и отменить, сузив установку до одного агента. `--global` кладёт всё на уровень пользователя; **без него установка проектная** — скиллы лягут в текущий репозиторий, чего в чужом репозитории делать не надо.

Содержимое при этом лежит **однажды** — в `~/.agents/skills/<имя>/`, — а каталоги отдельных харнессов получают на него симлинки: `~/.claude/skills/`, `~/.pi/agent/skills/`, `~/.codeium/windsurf/skills/` и далее (замерено: 56 каталогов за один прогон). Сам `~/.agents/skills` — не запасной путь, а универсальное место, которое читают Codex и ещё полтора десятка агентов. Обновлять — `npx skills update --global`.

Две записи в выводе будут отказами (`Eve`, `PromptScript`): эти харнессы глобальной установки не умеют вовсе, и на остальные это не влияет.

### Отдельные скиллы вручную

Каждый `*.skill` — закоммиченный zip-бандл (`<name>/SKILL.md`). Загрузи его как Skill в claude.ai или распакуй в свою директорию скиллов:

```sh
unzip design.skill -d ~/.claude/skills/
```

## Устройство и сборка

- `skills/<name>/SKILL.md` — **источник истины.**
- `*.skill` — закоммиченные **производные** бандлы. Не редактируются руками; `make build` (или просто коммить с включённым хуком `make hooks` — он пересобирает их на каждом коммите).
- `make plugin` — архив плагина для claude.ai (`dist/iskron.zip`); CI прикладывает его к каждому релизу.
- `.claude-plugin/marketplace.json` + `.claude-plugin/plugin.json` — манифесты плагина; версию пишет release-please при мерже релизного PR.
- `.mcp.json` — запись MCP плагина: stdio-мост из поставки (`skills/establish-mcp/scripts/iskron.mjs`), говорящий с `https://mcp.iskron.ru/`.
- `DERIVATION.md` — карта деривации скиллов из канона методологии + языковой контракт.
