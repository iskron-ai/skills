# Впуск шабды в Искрон

Внешнее слово — issue, README, кусок исходников, разговор, RFC — это **шабда**: свидетельство с существованием вне графа. Оно ещё не твоё. Этот скилл впускает его **как утверждение с происхождением, не как автоматически удостоверенный факт** — отображённым в верный тип узла, помеченным провенансом, дедуплицированным, заякоренным — и затем сверенным. Когда его несут не в граф, а в дело или другому делателю, сверка с графом всё равно идёт прежде передачи (шаг 3).

Нить: **шабда → сверка → тезис**; given_as — по содержанию каждого утверждения, путь ding → sachverhalt не обязателен. Чужое становится своим через проверку, не через копирование: слово, впущенное массой как факты, затапливает граф мусором с видом авторитета.

**Источник — адаптер; дисциплина впуска ниже — одна.** `product-roadmap` соединяет её с GitHub-адаптером. Не впаивай источник в дисциплину.

## 0. Сначала различи, что поручено

**Записать рассказ, сценарий или документ** со многими делателями и актами — разнеси по циклу ниже; число продиктованных фраз само по себе не задаёт число крий. **Исполнить разовое поручение** — работа в деле, не впуск сценария. Решение владельца — акт по **writing**, не свидетельство на импорт. Короткое слово с одним делателем проходит обычные шаги впуска без отдельного субагента. Неясно, записать или исполнить, и от этого меняется ход — уточни предмет до записи.

### Сложный рассказ: набросок → впуск и ткачество → приёмка

1. **Решающий держит целое.** Прочти граф по предмету через **recall**, запиши набросок крупными переходами в задетые узлы по **writing**. Набросок — замысел, не транскрипция диктовки одной крией и не новый вид записи.
2. **Поставь впуск.** В дочернем деле по контракту двери передай спутнику весь исходный текст, набросок, границу, нужные узлы и способ проверки: сначала шаги 1–6 этого скилла, затем **weaving**, затем отчёт с узлами и вопросами. Для этой ветки адаптер не обрезает рассказ. Модель и способ запуска — по правилам среды, не по названию скилла.
3. **Спутник различает и ткёт.** Это предметное исключение из общего держания графа решающим: со своим мостом-спутником он вправе создавать и связывать узлы переданного рассказа и его стыки с окрестностью в пределах брифа. Другой делатель, подсистема, инструмент или собственное «до → после» — признак отдельного перехода; передачи стоят феноменами. Не режь по абзацам и не оставляй многодельный сценарий одной крией. Не совершай акты воли за владельца; чужое без твёрдого знания не меняй, вопросы по сути верни решающему. Своего моста нет — в граф не пиши, верни ограничение, не заявляй выполненный впуск.
4. **Решающий принимает чтением.** Открой сами записанные узлы и их окрестность, сверяя с полным рассказом и наброском: у каждого перехода свой делатель и «до → после», передачи явны, подсистемы различены. Отчёт спутника — «сообщили», не твоё наблюдение. Набросок не эталон: расхождение может быть более точным различением. Небрежную нарезку верни на ткачество; решения и приёмка остаются у тебя.

Канон: «Разнесение сложного рассказа», «Набросок рассказа и постановка субагенту», «Приёмка впуска и ткачества», «Через границу холона — по твёрдости знания». Дальше — единая дисциплина впуска; она не заменяется массовым копированием рассказа.

## Контракт адаптера источника

Добыть внешнее слово — работа адаптера, не этого скилла. Каким бы ни был источник (GitHub `gh`, чтение файла, транскрипт разговора), адаптер обязан отдать ядру, по каждому элементу:

- **содержание** — само утверждение (заголовок + обрезанное тело, или фрагмент прозы);
- **форма** — что это за высказывание (bug / feature-request / RFC / design-doc / факт-из-кода / решение) — по ней ядро отображает;
- **провенанс** — устойчивая обратная ссылка на исток (URL issue, путь+символ, «разговор 2026-…»), чтобы каждый узел мог `arose_from` к нему;
- **авторитет** — кто свидетельствует, каким средством и в какой области (случайный issue vs решение владельца vs код, который можно прочесть сейчас); модус выбирается для выделенного суждения (шаг 2).

Не может адаптер дать провенанс — элемент не впускается: он лёг бы незаякоренным и невидимым.

Гранулярность парсинга — это структура графа: мелко нарежешь — много узлов, крупно — узлы-контейнеры. Режь по различениям, которые граф понесёт, а не по абзацам источника.

## 1. Отобрази форму в тип узла

Внешнее слово неоднородно; один элемент — не одна форма узла. Отображай по **форме**, с суждением агента (предложи → подтверди), никогда слепым импортом:

| Внешняя форма | Узел | Замечание |
|---|---|---|
| bug / сообщение о поломке | `risk`-вимарша, или 🔥 sachverhalt-инцидент, если уже сбылось | сообщение — утверждение, что что-то не так |
| фича / план / направление | `bianhua` («X становится Y») + ведущие вимарши — **или** `kriya` (anagata/chanda), если это одно деяние | одно желание — не превращение: сначала найди существующее превращение (assembly), не порождай по одному на элемент |
| RFC / design-обсуждение / открытый вопрос | `samshaya`-вимарша | узел — сам вопрос |
| заявленный факт о системе | `phenomenon` (given_as по тому, что это) | подлежит сверке до утверждения |
| labels / теги | подсказка жанра/контура, не узел | сигнал маршрутизации |

Именование, given_as и сами модусы — дисциплина скилла **writing**: вызывай его при каждой записи. Этот скилл решает, *какую* форму принимает внешнее слово.

## 2. Средство, заявка и исток

Ход, в котором агенты ошибаются. `source_kind=shabda` и `arose_from` — исток; модус — знание выделенного суждения. Не ставь модус по виду файла. Разведи: **прочитанное** (текст документа, кода, отчёта — видишь сам); **сообщённое** (наблюдение автора — для тебя «сообщили», с истоком); **выведенное о предмете** (по силе и независимости свидетельства); **предполагаемое**. Надёжность свидетельства существенна там, где на ней держится вывод, и не обнуляется внешним происхождением. Код как текст прочитан — его исполнение этим не наблюдалось. Содержание нормативного текста проверяется чтением самого текста. Предложение, план, RFC — предложение по содержанию, не «непроверенный факт». Онтика — по предмету, не по дате документа. Невоспроизводимое прошлое исследуется доступными свидетельствами: два пересказа одного измерения — одно свидетельство. Опровергнутое утверждение остаётся записью `badhita` — она учит, как не мыслить.

**Воля владельца** входит своим волевым модусом, только когда слово пришло от правомочного владельца (провенанс места и роли, не тело кадра) и в названной им области; пересказ его решения — сообщение о воле. Проверка исполнения этой воли — отдельная заявка.

Моделируй соответственно: `attrs.source_kind="shabda"`, given_as по содержанию (шабда-документ как таковой — ding: вещь, существующая вне графа; имя — по содержанию, не по файлу: «⚙️ Брифинг factory-system-prompt», не «⚙️ factory-system-prompt.md»).

## 3. Дедуп до записи — и до передачи

Перед каждой вставкой — `iskron_semantic_search(q=<утверждение фразой>, realm=…)` против существующего графа (против *почвы*, не только прежнего бэклога). Дистанция около нуля — граф это уже несёт: свяжи или обнови, не дублируй. Сначала найди, потом пиши: провал впуска — N почти одинаковых узлов, по одному на пересказанный issue.

**Передача — тот же гейт.** Внешнее слово несут не только в граф: чужой разбор, фидбэк, письмо, пересказ отдают в дело, соседу или разносят по строкам. Прежде этого — сверка по каждому пункту: поиск по смыслу несколькими формулировками и чтение найденного — по **entry** (вход, шаг «по вопросу»), дела на найденных узлах — `iskron_case(action="at", node=<узел>)`. У каждого пункта один ответ: «решено в #N», «открыто в #N у роли», «идёт в деле №N» или «в графе нет — вот вопрос». Решённое и идущее — ответом тому, кто принёс слово; в дело или соседу уходит только дельта — новое и открытое — со ссылками. Предел: слово, живущее лишь в деле (и решение, ещё не легшее в граф), поиск не находит — текстом по делам `iskron_case` не ищет; сверь дела на найденных узлах; узла предмета нет (граф отстал) — прочти открытые дела графа `iskron_case(action="at")` без `node` и спроси ведущего подходящего. Не нашёл и так — тогда «в графе нет». «Я только передаю, решают они» сверку не снимает: несверенный пункт тратит ход получателя на указание, где это уже решено.

## 4. Якори каждый узел к истоку

Впущенный узел без происхождения — слух. Каждому нужны:

- **`arose_from`** → провенанс (issue, файл, разговор) — трассируемый исток; провенанс живёт этим ребром и `attrs`, а кто впустил и по чьему слову — `reasoning` записи, не строкой в теле: тело несёт само утверждение;
- дом его типа: вимарше — **`vimarsha_of`** в контур, о котором она (контур/феномен/крия, которых утверждение касается); феномену — **`context`** → его контур.

Якорение — закон скилла **inquiry** (незаякоренная вимарша невидима): соблюдай при впуске, не задним числом.

## 5. Сверь — и объяви ступень

Впуск не закончен, когда утверждение записано, — он закончен, когда оно *сверено*. И у сверки есть ступени; «сверено» без названной ступени — не результат:

- **Первая ступень — шабда против ГРАФА** (этот скилл). Граф здесь — инструмент наблюдения: накопленное и ранее проверенное наблюдение мира, не сам мир. Срез — по вопросу: карточка `iskron_look` — содержание и показанные связи; окрестность `iskron_orient(focus)` — относящиеся вопросы и соседи; `lens="trace"` — поток предмета. Это не лестница и не три обязательных вызова: полный ответ на карточке достаточен для своей заявки; неполный срез — потолок, не «нет».
- **Вторая ступень — граф против МИРА** — здесь не совершается: её несут крии свидетельствования (наблюдение перемены на её каноническом носителе). Совпадение шабды с графом НЕ есть подтверждение реальностью — это согласие слова с записанным. Закрывая вопрос словом «проверил», скажи, против чего сверял.
- **Шабда о невоспроизводимом прошлом** пратьякшей не сверяется в принципе — там сверка шабды шабдой с названными истоком, временным объёмом и зависимостью: схождение независимых свидетельств → pramanita (два пересказа общего наблюдения — не два наблюдения); вывод из документов при молчании прямых свидетельств → anumita; расхождение свидетельств → vyabhichara, не badhita. Это честный потолок рода, а не незавершённая сверка.

Затем градуируй:

- **совпало** — согласованность с записанным; модус меняется только у обоснованного суждения, не у заявки об исполнении;
- **разошлось** — различи предмет и стороны (ошибаться может и граф): прямой опровергающий случай — `vyabhichara`, неразличённая несовместимость — `samshaya`; `badhita` — только опровергнутому тезису; сбывшееся — инцидентом;
- **модус просто сдвинулся** → обнови модус записи.

## 6. Селективность — страж, не удобство

Никогда весь трекер, никогда «все доки». Объяви срез (открытые/размеченные, граница по дате, высокосигнальное подмножество), ограничь объём и **скажи, что отброшено** — молчаливый срез читается как «впустил всё». Отбор, модусы шабды и дедуп сдерживают впуск без разбора только вместе.
