# Шаг 6 — Ролевые суб-агенты делегирования — iskronify

Шаг процедуры скилла **iskronify**: исполняется в своём месте, после Шага 5.

Доктрина и шаблоны файлов — `references/delegation-1.md`, `references/delegation-2.md`: открой и прочти обе части по порядку до хода; прозой AGENTS.md не проецируется.
- Claude Code, всегда: `.claude/agents/reader.md`, `worker.md`, `designer.md`, `weaver.md`, `reviewer.md` и `verifier.md`. `verifier` и `reviewer` — даже без рантайма: они делают `REALITY.md` и ритуал ревью исполнимыми. В граф пишет только `weaver` в пределах порученной объёмной правки задетых узлов, на своём мосту-спутнике; решение, ткачество и интеграция — у ведущего, итог сверяет он («Ремесло графа» двери **iskron**).
- OpenCode (`opencode.json` / `.opencode/` или слово пользователя): `.opencode/agents/` те же шесть, `mode: subagent`.
- **Модель роли выбирает человек; ролевые файлы — проекция на машине.** Модель каждой роли — из предпочтений человека о работе агентов в его личной памяти (**minding**, срез «работа с агентами»), не из `opencode.json`, не алиасом по умолчанию и не id из референса. Предпочтения нет — спроси человека карточкой (через позвавшего), предложив рекомендацию класса (`delegation-1.md`, таблица ролей), и запиши ответ по **minding**; до ответа пин не ставь. Поставка рекомендует класс, моделей не требует и не запрещает. Свои файлы с пином в git не идут — в `.gitignore` по именам (Шаг 5); их хвост репо живёт в AGENTS.md («Хвост репо» в `delegation-1.md`).
- **Запись моста-спутника — одна форма на все ОС** (`delegation-1.md`, «Форма записи одна на все ОС»): `command: node`, `args` — `-e` с кодом, собирающим путь к домашнему мосту из `os.homedir()`, затем `--` и `--satellite`; копируй блок из референса дословно. Проверена живьём на macOS (Claude Code 2.1.285); на Windows не сверена. Машинного пути в файле нет — форма одна на всех машинах. Прежняя проекция (`sh -c`, контракт до 18; абсолютный путь) — перепиши этим блоком.
- `description` — канал маршрутизации: триггер-образно — когда звать, что вернётся, чему не доверять.
- Объёмное суждение без записи в граф (проекция файлов прогона `iskronify`, разбор слотов против кода) идёт роли `designer`; поиск и правка многих узлов, задетых решением или поправкой, — `weaver` с референсами на решение и окрестность, свой мост-спутник и сверка итога ведущим обязательны. Проектирование, решение, ткачество, интеграция, приёмка, решения владельца и диалог остаются ведущему; приёмное (ревью диффа, проверка утверждения) идёт холодному — ролевой файл законен. Поиск по графу — чтение для решения, его ведёт сам ведущий по **entry**.
- **Мержи**: одноимённый агент другого набора — вложи своё или переименуй свой (`iskron-reader`). Своя прежняя проекция (тело прошлого контракта) — перепиши текущим телом; хвост репо — из AGENTS.md (`delegation-1.md`, «Хвост репо»); чужое тело — не трогай.
- Самопроверка: файлы парсятся; каждый файл Claude Code несёт свою запись моста-спутника `iskron-sub-<роль>` — общей записи `iskron-sub` (контракт до 17) ни в одном нет; форма записи — `node -e` из референса, `sh -c` и машинного пути нет ни в одном; `doctor` из корня репо показывает файлы проекта в разделе «субагенты» без строк `НАДО:` (на английской поверхности — `TODO:`; есть — исполни их до отчёта); тела `worker`, `verifier`, `reviewer`, `designer`, `weaver` несут вход в дело строкой запуска и на общем мосту не зовут `iskron_stand`, `join`, `leave` (`reader` в дело не пишет); только `weaver` разрешает порученную объёмную правку графа на своём мосту-спутнике со сверкой запустившим; файла `designer` нет (контракт до 18) — допиши; прежняя проекция без `weaver` (контракт до 28) — допиши `weaver` по текущему блоку, свою прежнюю проекцию этой роли сверь с ним; своя прежняя проекция снятой роли поиска по графу (контракт до 36) — сними оба файла; `verifier` и `reviewer` читают `REALITY.md` репо; пришпиленные модели — выбор человека и существуют; свои шесть не в индексе, `git check-ignore` их ловит; AGENTS.md не несёт доктрины делегирования (максимум указатель и раздел хвоста); хвост репо не потерян — строки под `## Этот репо` и ключи фронтматтера сверх блока каждого ролевого файла стоят в разделе хвоста AGENTS.md и после прогона снова в файле; у прежней проекции без заголовка каждая снятая строка, называющая предмет репо, стоит в хвосте, а снятые родовые названы в отчёте; чужие файлы не перезаписаны, свои прежние не оставлены.
- Роль, спроецированная прогоном, в той же сессии может не зваться по имени (каталог ролей читается на старте) — скажи это в отчёте; холодное ревью этого прогона тогда идёт общим суб-агентом с телом роли в брифе, модель — выбор человека для `reviewer` из mind: параметром вызова, где харнес его даёт; где не даёт — моделью сессии, и отчёт это говорит.
