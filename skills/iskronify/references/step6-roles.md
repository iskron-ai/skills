# Шаг 6 — Ролевые суб-агенты делегирования — iskronify

Шаг процедуры скилла **iskronify**: исполняется в своём месте, после Шага 5.

Доктрина и шаблоны файлов — `references/delegation-1.md`, `references/delegation-2.md` и `references/deputy-chief-of-staff.md`: открой и прочти целиком в этом порядке до хода; прозой AGENTS.md не проецируется.
- Claude Code, всегда: `.claude/agents/reader.md`, `recaller.md`, `worker.md`, `designer.md`, `weaver.md`, `ingester.md`, `reviewer.md`, `verifier.md` и `deputy-chief-of-staff.md`. `verifier` и `reviewer` — даже без рантайма: они делают `REALITY.md` и ритуал ревью исполнимыми. Содержание графа пишут только `weaver` в пределах порученной объёмной правки задетых узлов и `ingester` в границах порученного рассказа, каждый на своём мосту-спутнике; решение, ткачество вне поручения и интеграция — у ведущего, итог сверяет он («Ремесло графа» двери **iskron**). Заместителю начштаба — ведение только назначенных дел, не содержание графа и не диалог с человеком; одно стандартное тело из отдельной справки. Он сам привязывает дочерние дела через `open_room`/`parent_room` на данных в поручении узлах без изменения их полей и связей — это не правка содержания графа.
- OpenCode (`opencode.json` / `.opencode/` или слово пользователя): `.opencode/agents/` те же девять, `mode: subagent`.
- **Модель роли выбирает человек; ролевые файлы — проекция на машине.** Модель каждой роли — из предпочтений человека о работе агентов в его личной памяти (**minding**, срез «работа с агентами»), не из `opencode.json`, не алиасом по умолчанию и не id из референса. Предпочтения нет — спроси человека карточкой (через позвавшего), предложив рекомендацию класса (`delegation-1.md`, таблица ролей), и запиши ответ по **minding**; до ответа пин не ставь. Поставка рекомендует класс, моделей не требует и не запрещает. Свои файлы с пином в git не идут — в `.gitignore` по именам (Шаг 5); их хвост репо живёт в AGENTS.md («Хвост репо» в `delegation-1.md`).
- **Запись моста-спутника — одна форма на все ОС** (`delegation-1.md`, «Форма записи одна на все ОС»): `command: node`, `args` — `-e` с кодом, собирающим путь к домашнему мосту из `os.homedir()`, затем `--` и `--satellite`; копируй блок из референса дословно. Проверена живьём на macOS (Claude Code 2.1.285); на Windows не сверена. Машинного пути в файле нет — форма одна на всех машинах. Прежняя проекция (`sh -c`, абсолютный путь) — перепиши этим блоком (`references/migrations.md`).
- `description` — канал маршрутизации: триггер-образно — когда звать, что вернётся, чему не доверять.
- Объёмное суждение без записи в граф (проекция файлов прогона `iskronify`, разбор слотов против кода) идёт роли `designer`; поиск и правка многих узлов, задетых решением или поправкой, — `weaver` с референсами на решение и окрестность, свой мост-спутник и сверка итога ведущим обязательны. Проектирование, решение, ткачество, интеграция, приёмка, решения владельца и диалог остаются ведущему; приёмное (ревью диффа, проверка утверждения) идёт холодному — ролевой файл законен. Поиск и ход по связям лестницы **recall** — `recaller` по постановке, только чтение; найденный узел ведущий открывает сам, брат и человек — его. Впуск сложного рассказа по **intake** — `ingester`: различение и ткачество переданного рассказа в границах брифа, набросок и приёмка чтением узлов — у ведущего.
- **Мержи**: одноимённый агент другого набора — вложи своё или переименуй свой (`iskron-reader`). Своя прежняя проекция (тело прошлого контракта) — перепиши текущим телом; хвост репо — из AGENTS.md (`delegation-1.md`, «Хвост репо»); чужое тело — не трогай.
- Самопроверка (при любом контракте — по содержимому; откуда взялась прежняя форма, говорит `references/migrations.md`): файлы парсятся; каждый файл Claude Code несёт свою запись моста-спутника `iskron-sub-<роль>` — общей записи `iskron-sub` ни в одном нет; форма записи — `node -e` из референса, `sh -c` и машинного пути нет ни в одном; `doctor` из корня репо показывает файлы проекта в разделе «субагенты» без строк `НАДО:` (на английской поверхности — `TODO:`; есть — исполни их до отчёта); тела `worker`, `verifier`, `reviewer`, `designer`, `weaver`, `ingester`, `deputy-chief-of-staff` несут вход в дело строкой запуска и на общем мосту не зовут `iskron_stand`, `join`, `leave` (`reader` и `recaller` в дело не пишут); запись содержания графа на своём мосту-спутнике со сверкой запустившим разрешают только `weaver` (порученная правка) и `ingester` (порученный рассказ), тело `weaver` исключения впуска не несёт; привязку дел заместителем через `open_room`/`parent_room` на данных в поручении узлах без изменения полей и связей самопроверка не запрещает; все девять файлов есть (отсутствующие допиши по текущим блокам, свою прежнюю проекцию сверь с ними); тело заместителя совпадает с единственным стандартом и одинаково в обоих харнесах, кроме фронтматтера и хвоста репо; своей проекции снятой роли `searcher` нет (есть — сними оба файла); `verifier` и `reviewer` читают `REALITY.md` репо; пришпиленные модели — выбор человека и существуют; свои девять не в индексе, `git check-ignore` их ловит; AGENTS.md не несёт доктрины делегирования (максимум указатель и раздел хвоста); хвост репо не потерян — строки под `## Этот репо` и ключи фронтматтера сверх блока каждого ролевого файла стоят в разделе хвоста AGENTS.md и после прогона снова в файле; у прежней проекции без заголовка каждая снятая строка, называющая предмет репо, стоит в хвосте, а снятые родовые названы в отчёте; чужие файлы не перезаписаны, свои прежние не оставлены.
- Роль, спроецированная прогоном, в той же сессии может не зваться по имени (каталог ролей читается на старте) — скажи это в отчёте; холодное ревью этого прогона тогда идёт общим суб-агентом с телом роли в брифе, модель — выбор человека для `reviewer` из mind: параметром вызова, где харнес его даёт; где не даёт — моделью сессии, и отчёт это говорит.
