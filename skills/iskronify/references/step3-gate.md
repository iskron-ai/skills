# Шаг 3 — Гейт качества (строжайший в принятом мандате) — iskronify

Шаг процедуры скилла **iskronify**: исполняется в своём месте, после Шага 2.

По каждому пункту: строжайший вариант для стека, цена выбора одной строкой, источник по Шагу 1. Послабления — из принятого ограничения, откалиброванного ценой поломки, во фронтматтер по-инструментно; нового основания нет — принципиальный вопрос. **Ужесточение уже-ослабленного гейта** — обязательство рефакторинга: сперва измерь (прогон на предлагаемой строгости, число провалов); смена принятого ограничения без основания — тем же порядком владельцу, возможно отдельной веткой. Прочие части прогона её не ждут.
- **Линтер** максимально строгий (`@typescript-eslint/strict`; Ruff `E,F,B,I,N,UP,RUF`; `golangci-lint` широкий; `clippy -- -D clippy::pedantic`).
- **Форматтер**, auto-fix on save + pre-commit (Prettier, `ruff format`, `gofumpt`, `rustfmt`).
- **Тайпчекер** strict, если есть (`tsc --strict`, `mypy --strict` / `pyright --strict`).
- **Pre-commit-хук**: линтер + форматтер + тайпчек по staged-файлам.
- **Тесты + дисциплина** (unit для библиотек; +integration для сервисов; +e2e для UI; порог покрытия для production) — в «Конвенции кода».
- **CI**: lint + typecheck + tests на каждый пуш, падает на предупреждениях; обязателен для `production`.
- **Гейт — ВЫЗЫВАЕМЫЙ**: один вызов, чья цепочка и есть правило (`npm run gate`, `make check`, `just check`); в `AGENTS.md` — его имя, не список шагов; CI зовёт тот же вызов. Собранный руками гейт теряет шаг молча и кончается зелёным. Цепочку вынужденно собирают руками — запиши почему и чем проверяется полнота.
- **CI-паритет**: всякая проверка, способная упасть, гейтит PR, не только post-merge (кодоген, генерация схем и доков, сборка образа, миграции) — дотяни до PR; неустранимый зазор — готчей.

Команды — в «Команды», дисциплина — в «Конвенции кода».
