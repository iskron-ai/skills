# iskronify — приведение репозитория к стандарту

Приведи **текущий репозиторий** к агентскому стандарту iskron: плотный `AGENTS.md` (читается каждую сессию каждым харнесом), `REALITY.md` рядом (носители реальности, читается по поводу), `CLAUDE.md`-указатель, ритуалы сессии хуками и гейт качества. Конфиг ты **генерируешь** из скелетов — пользователь шаблонов не вставляет.

Результат прогона — **интерфейс доверия**. `AGENTS.md` и `REALITY.md` — *производные виды*: проекция источников (код, `package.json`, CI, файловая система, граф) плюс тонкий слой авторского суждения, который больше нигде не живёт. У контракта два требования: **плотность** (каждая строка меняет поведение) и **точность** (каждая производная строка перепроверена против источника *в этом прогоне*).

Скелеты: `references/agents-template.md` (`AGENTS.md`: YAML-фронтматтер и тело) и `references/reality-template.md` (`REALITY.md`) — слоты `<…>` и заметки `<!-- … -->`. Заполни слоты, выброси неприменимые опциональные строки, вычисти каждую заметку и угловую скобку.

**Контракт: `33`.** Шаг 7 штампует это число в каждый `AGENTS.md`; то же число стоит в `description` после «КОНТРАКТ AGENTS.md:». Увеличивай на единицу, только когда перемена здесь или в скелетах делает уже сгенерированный файл *неверным* (секция или файл добавлены, переименованы, изъяты; ритуал изменён; имя тула выпало), никогда ради формулировок. Конфиг со штампом-датой или без штампа — ниже любого числа: прогони полную дугу (правило запуска — шаг «Выравнивание» двери `iskron`) и назови контракт, из которого пришёл конфиг.

Переход с 32: «самопроверка — всегда, холодное ревью — где положено», образец хука старта. С 31 — единица ветки, PR и ревью — пачка: их разделы, гейт и CI, побудка пуша, `reviewer`. С 28 — ещё личную ветку памяти и guard через minding, без вычисленного или сохранённого адреса; ритуалы и семь ролей (с `weaver`) — по справкам. Подъём счётчика зовёт существующий репозиторий на прогон, но не свидетельствует уже исполненного перевыравнивания.

**Строка `AGENTS.md` расходится со скиллом — назови вслух, молча не выбирай** (шаг «Выравнивание» двери `iskron`): штамп ниже контракта — прав скилл, прогони; равен — дефект шаблона, **feedback** стюарду поставки скиллов.

**Редакция установленной поставки сверяется здесь**: всякий прогон и всякий вывод «инструкция скилла неверна» начинается сверкой бегущего с выпущенным:

```
cat ~/.claude/plugins/cache/*/*/*/.claude-plugin/plugin.json     # что бежит (Claude Code; прочие харнесы — версия моста ниже)
gh release view --repo <репозиторий плагина> --json tagName      # что существует
node ~/.iskron-bridge/iskron-bridge.mjs --version                # какую сборку несёт копия моста
```

Отстал больше чем на патч — обнови поставку, перезапусти сессии харнеса и только потом гони дугу; число контракта движется с формой конфига, версия — с каждой отгрузкой.

Скелет *инлайнит* граф-агностичную дисциплину (Рабочие принципы, «Жизненный цикл сессии») в каждый `AGENTS.md` по строке на правило, не указателем в граф или скилл: есть харнесы без хука старта, и файл обязан стоять сам.

## Аудит → классификация → действие
Ловушка — «файл есть, значит, его факты верны». Аудируй каждую заботу против её источника и классифицируй:
- **absent** — выведи из источника; авторский слот без проверяемого источника — в дело выравнивания, никогда не выдумывай.
- **stale** — ре-спроецируй, перезаписав; записанное не тащи вперёд.
- **correct** — оставь.

Опаснее всего *почти-верный* конфиг: проверочный проход — по всему артефакту (Шаг 7).

### Источник истины по заботам
| Забота | Источник истины | Как проверить |
|---|---|---|
| Версии, зависимости | `package.json` / `pyproject.toml` / `go.mod` / `Cargo.toml` + lockfile | прочитать |
| Команды build/test/lint/dev | scripts, `Makefile`/`Justfile`, CI-workflow | прочитать; `--help`/dry-run, где дёшево |
| Гейт качества | конфиг линтера, `tsconfig`, CI-yaml | прочитать |
| Раскладка: карта кода, ловушки среды | слот обложки «Раскладка» | слота нет — умолчание из слота скелета; отступление (раздел вместо README) — только где README рядом с выходами запрещён, выводится из самого репо. `GOTCHAS.md` в репо — чья-то раскладка: разреши по Шагу 1; до того слот пустой, источник `не согласовано — дело №N`, файлы нетронуты |
| Структура проекта, path-алиасы | файловая система + конфиг бандлера; при раскладке «README компонента» — сами README | glob / list; таблица «компонент → README» сверяется существованием файлов |
| Nature, production statement, послабления | граф, код репо, слово агентов; принятые владельцем ограничения сохраняются | разрешить по порядку Шага 1; смена мандата или цены поломки без основания — принципиальный вопрос |
| Носители реальности (`REALITY.md`) | граф, наблюдаемый кодом путь поставки, слово агентов | проверить достижимость канонического носителя; неизвестное — Ceiling, не выдуманный носитель |
| Проектные решения, why-клаузы, открытые вопросы | граф | `iskron_orient` / `iskron_search` |
| Состояние веток | git + форжа | `git status` / `log`; CLI форжи |
| Ловушки | авторское; дом — по слоту «Раскладка» | только sanity-check — не автовыводить, не переносить между домами |
| Блоки канонов графа | узел-правило с `attrs.prose_for_repos` | `iskron_search(realm=<граф>, q="", attrs_filter="prose_for_repos:**")`; блок кладётся байт-в-байт на место из `attrs.prose_anchor`, ниже — только хвост репо; применимость — по `attrs.scope`, иначе по смыслу, сомнение — порядком Шага 1 |

**Производные факты** (верхние строки, блоки канонов) ре-проецируются каждый прогон; **авторское суждение** (ловушки, why-клаузы, nature, носители) сохраняется, лишь сверяясь на здравость с кодом.

## Контракт выхода — плотность и точность
1. **Императив агенту**: «ориентируйся до кода», не «агенту следует».
2. **Каждая строка меняет то, что агент делает**; иначе удали. Чек-лист, не эссе.
3. **Без проектных обоснований и пересказа графа** — линкуй; растёкшаяся в абзацы секция несёт обоснование — в граф. `(why: …)` — только для инварианта, который агент иначе нарушит.
4. **Таблицы и буллеты**, одна директива на буллет.

**Вне объёма — механика оркестрации** (цепочки гейтов, суб-агентная проверка пушей, model-routing, многополосная координация): её дом — скилл оркестрации или граф; срез делегирования проецируется ролевыми файлами (Шаг 6), не прозой.

## Процедура
Идемпотентна: в зрелом репо прогоняй каждую самопроверку и действуй только по провалам; докладывай, что осталось.

## Два такта
**Кто исполняет прогон.** Граф прогона — контур, роль, атрибуты, дело выравнивания — ведёт сам агент (ремесло графа, «Сквозные нормы» двери `iskron`). Объёмную проекцию файлов (`AGENTS.md`, ролевые файлы, хуки) он может отдать субагенту роли `designer` со своим мостом-спутником; нет субагентов, ролевого файла `designer` ещё нет (первый контакт, такт 1 до проекции, роли старше контракта) или спутник не поднялся — проецирует сам. Прогон обновляет файлы сам, не ждёт присутствия или подтверждения человека. Дело выравнивания ведёт позвавший (ведущий): держит граф прогона, будит человека и держит ожидание — только по принципиальному вопросу, не разрешённому графом, кодом и коллегами. `designer` работает в своём дочернем деле из строки запуска, дела выравнивания не ведёт, в граф не пишет, принципиальный вопрос возвращает в итоге. Порядок вопросов — Шаг 1, «Человек обычно не в треде».

**Ветвь «Первый граф» — `references/first-graph.md`: открой и исполни целиком до такта 1, без отдельного вызова, когда в git-репозитории нет ни одного из трёх признаков выравнивания (обложка, хук старта, штамп — Замер двери `iskron`) или у учётки нуль своих рабочих графов (личный mind не в счёт), в том числе когда человека пригласили в общий.** Рабочие графы у учётки есть — один вопрос до первого действия: подключить этот репозиторий к одному из её графов (список) или завести новый; сам граф без ответа не заводится. Свой рабочий граф есть и репозиторий хоть чем-то выровнен — ветвь не срабатывает. Разговор в ветви ведёт **onboarding**.

**Такт 1 «встать» — без вопросов, до минуты, в любом репозитории.** Первый такт при первом контакте, по слову «iskronify» или при найденном отставании конфига. Быстро разрешаемое — в файл с источником, остальное — дыркой в дело; затем такт 2 без ожидания человека.
1. **Адреса.** Граф и роль — из слова человека, строки окна с адресом места или существующего `AGENTS.md`. Граф не назван — `iskron_realm(action="list")`: нуль своих рабочих графов — ветвь «Первый граф» выше; иначе сверь с записанным о репо и спроси коллег; не разрешилось, какой граф выбрать или создать, — принципиальный вопрос о границе проекта (Шаг 1), имя не угадывай; создание — `iskron_realm(action="create")` по принятому выбору. Роль владельца — 主-роль человека твоих ключей (`iskron_me(action="kartas")`); перечень с твоей ролью агента — знак сбитой привязки: слот дыркой, вопрос — в деле выравнивания. `kartas` видит только привязанные роли: прежде чем заводить svatantra-роль (Шаг 2), ищи её — `iskron_search(q="", node_type="karta", manifested_as="svatantra")` в выбранном графе и прочти подходящие. Принадлежность роли задаёт связь `user`, не совпадение хэндла, имени или attrs. Непривязанную подходящую роль связывай с `user="me"` только по подтверждению человека; не выбирается — один вопрос человеку сессии, а без него — в деле выравнивания. Привязку роли владельца проверь по шагу «Сойдись или эскалируй» скилла **standing**.
2. **Контур репозитория.** `origin` → `хост/организация/репо` → `iskron_search(q="", node_type="holon", attrs_filter="repository:<значение>")`. Нет — `iskron_add_holon` (`contains` от корня графа или контура репозиториев) с `attrs.repository` и `open_room` дела выравнивания. Один репозиторий — один контур.
3. **Роль на репо.** `iskron_search(q="", node_type="karta", steward_of=<контур>)`; нет — `iskron_add_karta` (`manifested_as=adhikarin`, мотивация — дистиллят того, что репо поставляет, `attrs.skills` — CSV ключевых скиллов роли до 64 знаков: по нему карту агента отличают от непривязанной человеческой) и `steward` к контуру. Одна роль на репозиторий; у найденной без `attrs.skills` — допиши.
4. **Обложка и файлы.** Слоты — YAML-фронтматтер в начале `AGENTS.md` по скелету и Шагу 7. Язык обложки и тела — язык репозитория: скелет русский, в английском репозитории агент переводит его сам — ключи графа и роли агента `'Graph'` и `'Agent role'`, имя роли в ссылке в кавычках `"…"`, штамп `(iskronify: contract N, stamp YYYY-MM-DD`; ключи двух языков в одной обложке — дефект, посадка его не читает. Язык обложки не выбирает ни адрес моста, ни язык поверхности: их держит установка. Из графа и кода — «выведено»; из записанного ответа — «согласовано: кто», в том числе агент соседнего контура. Не разрешённое — пустое значение и источник «не согласовано — дело №N»; отсутствие человека дыркой слот не делает. `REALITY.md` — таблицей разрешённых носителей; пока их нет — заголовок скелета и строка: «Носители ещё не установлены; дело выравнивания №N. До их установления поведенческие заявки не принимаются.»
5. **Дело выравнивания** на контуре из п. 2: открытое уже есть (`iskron_case(action="at", node=<контур>)`) — веди его; нет — открой `open_room` у записи контура или `iskron_update` существующего, зачином до 64 знаков: «Выравнивание <репо> под контракт N». Прежде первой записи — место под ролью на репо (строка Замера двери `iskron`): место держит мост — `iskron_channel(action="register", realm, karta=<роль на репо>, name=<его имя>)` называет его, нет — `iskron_stand(realm, karta=<роль на репо>)`; затем `join`; вахта не нужна. Проекцию отдаёшь `designer` — заведи ему дочернее дело (`open_room` с `parent_room` — дело выравнивания), его №N — в строку запуска; он встаёт спутником (`iskron_stand` с `satellite_of` места позвавшего, по `references/delegation-1.md` и `references/delegation-2.md` — открой и прочти обе по порядку до хода), `register` под выведенным именем не зовёт, вопросы слотов говорит словом в дочернем деле, выходит концом поручения (`leave`). **Строка «слот: <имя>»** (`partial` — на ком, чего ждёт) — по желанию и только у неразрешённого, ждущего слота; разрешённый — значение и источник во фронтматтер, без строки; вопрос — словом в деле. Так везде ниже. Первое слово: «есть вопросы по проекту, за который я отвечаю, — ответьте или скажите, кто может ответить». **Анкету, вопросы прогона, план и ход выравнивания в граф не пиши**; в граф такт пишет только структуру (контур с `repository`, роль) и ловушки правилами (Шаг 7).
6. **Хук старта и сторож памяти** — из Шага 4 только `SessionStart` и memory-guard; стаб `MEMORY.md` (Шаг 5) — **только над пустой или отсутствующей директорией памяти**. Непустая — эвакуация по Шагу 5 в такте 2; до неё строка скелета о заморозке ссылается на строку дела выравнивания, а не утверждает завершения. Остальные хуки — такт 2. Указатель `CLAUDE.md` — Шаг 7.
7. **Вахта** — не здесь; место для записи — п. 5.
Отчёт — слово в деле выравнивания: что разрешено, что открыто; такт по слову другого дела — поручение: слово-отчёт там, называющее дело выравнивания, с исходом по наблюдённому; затем эстафета Шага 7.

**Такт 2 «доделать» — сам, не блокируя.** Продолжи после такта 1; каждый следующий старт читает сводку дела по шагу «Выравнивание» двери `iskron`; писать — своим местом и войдя, как в п. 5. Слоты разрешай по Шагу 1 и вписывай во фронтматтер без переспроса; строка «слот: …», если была, снимается тем же ходом (`ok`). Ответ агента подписывается его именем, не именем владельца, и подтверждения человеком не требует. Полная дуга (Шаги 1, 3, 4, 6) идёт без человека; неразрешённый слот держит только зависимую часть. Все слоты разрешены — «Согласование» = «пусто», предложи закрыть (`propose_close`, свидетельство — слоты фронтматтера со значениями и источниками), если ведущий ты; иначе слово ведущему.

### Шаг 1 — Разреши слоты (такт 2)
Не выбирай дефолты молча. Прочти граф, код репо и старый конфиг; чего они не разрешили — спроси у агентов соседних контуров в деле выравнивания. Запиши во фронтматтер значение и источник: **Nature** (не `production` — что ослаблено и почему), **имя графа**, «Стек», **гейт** (Шаг 3). Принятые авторские ограничения сохраняй.

**Переход со старой анкеты.** «Согласование» или дырка называет узел (`#N`), не дело, — форма прежнего контракта. Прочти узел (`iskron_look`): ответы с именем ответившего — в слоты «согласовано: кто»; открытые — пустое значение и источник `не согласовано — дело №N`, вопрос — словом в деле выравнивания; узел-анкету отпусти (`visarjana`, reasoning «перенесён в дело №N»), чужой — слово автору.

Также согласуй:
- **Кто владеет направлением** — svatantra-роль владельца (主), создаётся в Шаге 2; принципиальные вопросы слотов — ей через ведущего в деле выравнивания, не анкетой в графе.
- **Общее изменяемое состояние build/test** (база, фиксированный порт, dev-сервер, глобальный кэш, облачная песочница): есть — зафиксируй ловушкой изоляцию по полосам (агенты гоняют ветки конкурентно в отдельных worktree).
- **Реальность** → `REALITY.md` по `references/reality-template.md`, из графа, кода и ответов коллег. Дожимай до *канонического носителя* каждого класса: собранный артефакт, не исходники; живой эндпоинт, не хендлер; чистая установка, не тёплый кэш. Недостижимое — в *Ceiling* с причиной; вывод о носителе не равен наблюдению поведения; датированные замеры — узлами в граф; в `AGENTS.md` — раздел «Reality» указателем. Как таблица работает при закрытиях — **reality-audit**, Ceiling.
- **Личной памяти в AGENTS.md нет** — ни слота, ни правила: где живёт личное и когда читается, решает дверь `iskron` (срез на старте) и **minding**; прежний слот «Кросс-проектная память» снимай при прогоне. Личную память обеспечь единым входом **minding**: без хэндла и сохранённого адреса, недоступность не отсутствие. Сообщение memory-guard несёт личную ветку через minding. Проектные инструкции держат коммитящиеся файлы рабочего дерева и граф проекта — никогда глобальный файл инструкций, память харнеса, пользовательские хуки; о глобальном файле не спрашивай и не заводи. Личное предпочтение, мнение или переносимый способ → личный mind, даже на тему разработки; правило самого проекта → AGENTS.md или граф проекта по полномочию; применение найденного — по **minding**, не копированием в проект.
- **Фидбэк-рефлексия** (опыт *о методе* — в граф работы, случаем, адресом стюарду инструмента): умолчание шаблона — **да**, источник `выведено: умолчание шаблона`, без вопроса человеку; регион feedback-reflection скелета остаётся, хук мержа несёт такт. **Нет** — только по записанному слову (`согласовано: кто`): удали регион целиком.
- **Сосуществование с workflow-набором** — только когда найден коэрсивный набор (его скиллы в списке или его директория в кэше плагинов; сегодня superpowers): (1) **полный interop** (рекомендуется) — подсекция из `references/superpowers-interop.md` + spec-write-хук; (2) **только проза**; (3) **пропустить** — назови риск: дизайн-сессии набора не осядут в граф.

**Человек обычно не в треде** (присутствие его — не условие прогона). «Согласуй», «спроси», «подтверди» для слота везде означают этот порядок:
1. **Сделай всё, что от ответа не зависит**: аудит, выводимое, гейт, хуки.
2. **Сперва граф и код, затем братья — агенты соседних контуров.** Неразрешённое — в одном деле выравнивания: вопрос — `ask` («Ожидание от делателя» справки двери **iskron** `cases.md`), строка «слот» — на отдельном от карточки ключе, не узел и не дело на слот; знающих коллег зови `invite`, поручение — `say` с `to` на место; их `answer` прими `ack`, ответ — в слот с их именем. Факт из графа или кода — «выведено», без строки дела; неочевидное основание — словом в деле.
3. **Только принципиальный остаток — человеку через ведущего дела.** Смена мандата, принятого ограничения, цены поломки, выбор или создание графа (граница проекта, такт 1, п. 1) либо неразрешимый конфликт источников — принципиальное; отсутствие ответа или сведений само по себе — нет. Прежде эскалации назови проверенное в графе и коде, кого спросил и почему нужно решение владельца. Ведущий говорит вопрос словом в деле и будит человека `invite` его места, а нет места — его роли с контуром (`karta=<роль владельца>`, `holon=<контур репо>`); нет и её — вопрос остаётся в деле, остальная работа продолжается.
4. **Дырка, не догадка** (п. 4 такта 1), `Согласование` называет дело; непринципиальное неизвестное ждёт знающего агента или ведущего, старт двери найдёт ответ и впишет без переспроса.
Отвеченное пишется сразу; один слот не держит остальные.

### Шаг 2 — Первое заведение графа
- Графа нет — ветвь «Первый граф» (такт 1).
- Фокус-контур (граница проекта, `contains` от корня) — спроектируй `design`, создай `iskron_add_holon`; `#seq` — в обложку. **Контур несёт атрибут `repository`** — `хост/организация/репо` из `git remote get-url origin`, без протокола и `.git` (например `github.com/iskron-ai/skills`); его сверяет с origin старт двери. Ставь при заведении и на повторном прогоне; один контур — один репозиторий. Стоит другой — не перезаписывай: та же `организация/репо` на другом хосте — алиас (атрибут несёт каноническое имя; предложи человеку перевести origin; ищи подстрокой `attrs_filter="repository:*организация/репо*"`), иная организация или репо — форк или зеркало, решает человек. «Not found» форжи по каноническому имени — не отсутствие: приватный репозиторий так отвечает всякому без учётных данных; одна ли это форжа — проверяй без них или по публичному репо на ней.
- **Делатель — стюард.** Роль агента (такт 1, п. 3; мотивация — дистиллят Production statement) проведи `steward` к фокус-контуру — эта роль, не старшая, иначе ориентация на контур не найдёт делателя. Нет svatantra-роли владельца и поиск такта 1, п. 1 её не нашёл — создай; привязка — по тому же шагу **standing**. Оба seq — в обложку.
- **Холон + стюард — корень поля интеграции**; обход держит `integrity`. Об «общих поверхностях» не спрашивай и списка в AGENTS.md не пиши; не найденная зависимость — дефект модели (`design`, `weaving`).
