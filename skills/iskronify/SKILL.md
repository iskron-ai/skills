# Repo-boost

Приведи **текущий репозиторий** к агентскому стандарту iskron: плотный `AGENTS.md` (читается каждую сессию каждым харнессом), `REALITY.md` рядом (таблица носителей реальности, читается по поводу — при поведенческой заявке и в брифе `verifier`/`reviewer`), `CLAUDE.md`-указатель, ритуалы сессии хуками и гейт качества. Конфиг ты **генерируешь** из скелетов — пользователь шаблонов не вставляет.

Деливерабл — **интерфейс доверия**. `AGENTS.md` и `REALITY.md` — *производные виды*: проекция источников (код, `package.json`, CI, файловая система, граф) плюс тонкий слой авторского суждения, который больше нигде не живёт. Контракт двуглав: **плотность** (каждая строка меняет поведение) и **точность** (каждая производная строка перепроверена против источника *в этом прогоне*). Плотная ложная строка хуже многословной.

Скелеты: `references/agents-template.md` (тело `AGENTS.md`) и `references/reality-template.md` (тело `REALITY.md`) — `##`-секции со слотами `<…>` и заметками `<!-- … -->`. Заполни слоты, выброси неприменимые опциональные строки, вычисти каждую заметку и угловую скобку. Скелеты — *что произвести*; этот файл — *как*.

**Контракт: `17`.** Шаг 7 штампует это число в каждый `AGENTS.md`. Увеличивай на единицу, только когда перемена здесь или в скелетах делает уже сгенерированный файл *неверным* (секция или файл добавлены, переименованы, изъяты; ритуал изменён; имя тула выпало), никогда ради формулировок. То же число стоит первым словом в `description` — нарочно: триггер срабатывает по описанию, а в контексте сессии сходятся только описания скиллов и штамп `AGENTS.md`; расхождение копий ловит `make validate`. Конфиг со штампом-датой или без штампа — ниже любого числа: предложи полную дугу (правило запуска держит шаг «Выравнивание» двери `iskron`) и назови контракт, из которого пришёл конфиг.

**Строка `AGENTS.md` расходится со скиллом — назови вслух, молча не выбирай**: в деле постановщику, без дела — человеку. Штамп ниже контракта установленного `iskronify` — прав скилл, предложи прогон; равен — дефект шаблона, фидбэк стюарду поставки скиллов (**feedback**). Правило стоит и в скелете («Держи этот файл честным») — для агента, этот скилл не загрузившего.

**Редакция установленной поставки сверяется здесь.** Всякий прогон — и всякий вывод «инструкция скилла неверна» (туда шлют **feedback** и **entry**) — начинается сверкой бегущего с выпущенным:

```
cat ~/.claude/plugins/cache/*/*/*/.claude-plugin/plugin.json     # что у тебя бежит
gh release view --repo <репозиторий плагина> --json tagName      # что существует
node ~/.iskron-bridge/iskron-bridge.mjs --version                # какую сборку несёт копия моста
```

Отстал больше чем на патч — обнови поставку, перезапусти сессии харнесса и только потом гони дугу: конфиг из протухшего скилла наследует его дефекты. Число контракта этого не заменяет: оно движется с формой конфига, версия — с каждой отгрузкой.

Скелет *инлайнит* граф-агностичную дисциплину (Рабочие принципы, «Жизненный цикл сессии») в каждый `AGENTS.md` — сжато, по строке на правило, но **инлайн, не указателем** в граф или скилл: есть харнессы без хука старта, и файл обязан стоять сам.

## Аудит → классификация → действие
Репозиторий — спектр, не «свежий или настроенный»; ловушка — «файл есть, значит, его факты верны». Аудируй каждую заботу против её источника и классифицируй:
- **absent** — выведи из источника; авторский слот без проверяемого источника — в дело выравнивания, никогда не выдумывай.
- **stale** — ре-спроецируй, перезаписав; записанное не тащи вперёд.
- **correct** — оставь.

Опаснее всего *почти-верный* конфиг: устаревшие строки среди доверенных — проверочный проход идёт по всему артефакту (Шаг 7).

### Источник истины по заботам
| Забота | Источник истины | Как проверить |
|---|---|---|
| Версии, зависимости | `package.json` / `pyproject.toml` / `go.mod` / `Cargo.toml` + lockfile | прочитать |
| Команды build/test/lint/dev | scripts, `Makefile`/`Justfile`, CI-workflow | прочитать; `--help`/dry-run, где дёшево |
| Гейт качества | конфиг линтера, `tsconfig`, CI-yaml | прочитать |
| Раскладка: карта кода, ловушки среды | слот обложки «Раскладка» | слота нет — умолчание (один `AGENTS.md`, карта в «Структуре проекта», готчи в графе), если в репо нет `GOTCHAS.md` и `AGENTS.md` не ссылается на README папок; есть хоть одно — это чья-то раскладка: слот дыркой `<не согласовано — дело №N>`, файлы нетронуты до ответа |
| Структура проекта, path-алиасы | файловая система + конфиг бандлера; при раскладке «README папки» — сами README | glob / list; таблица «папка → README» сверяется существованием файлов |
| Nature, production statement, послабления | пользователь (авторское) | подтвердить |
| Носители реальности (`REALITY.md`) | пользователь (авторское) | подтвердить — никогда не выводить |
| Проектные решения, why-клаузы, открытые вопросы | граф | `iskron_orient` / `iskron_search` |
| Состояние веток | git + форжа | `git status` / `log`; CLI форжи |
| Готчи | авторское; дом — по слоту «Раскладка» | только sanity-check — не автовыводить, не переносить между домами |
| Блоки канонов графа | узел-правило с `attrs.prose_for_repos` | `iskron_search(realm=<граф>, q="", attrs_filter="prose_for_repos:**")`; блок кладётся байт-в-байт на место из `attrs.prose_anchor`, ниже — только хвост репо; применимость — по `attrs.scope`, иначе по смыслу, в сомнении — вопрос человеку |

**Производные факты** (верхние строки, блоки канонов) ре-проецируются каждый прогон; **авторское суждение** (готчи, why-клаузы, nature, носители) сохраняется, лишь сверяясь на здравость с кодом.

## Контракт выхода — плотность и точность
1. **Императив агенту**: «ориентируйся до кода», не «агенту следует».
2. **Каждая строка меняет то, что агент делает**; иначе удали. Чек-лист, не эссе.
3. **Без проектных обоснований и пересказа графа** — линкуй. `(why: …)` — только для инварианта, который агент иначе нарушит.
4. **Таблицы и буллеты**, одна директива на буллет.
5. Секция, растёкшаяся в абзацы, несёт обоснование — перенеси в граф.

**Вне объёма — механика оркестрации** (цепочки гейтов, суб-агентная проверка пушей, model-routing, многополосная координация): её дом — скилл оркестрации или граф; срез делегирования проецируется ролевыми файлами (Шаг 6), не прозой.

Пример: ❌ «Мы стараемся аккуратно обращаться с состоянием, потому что стор — единственное место данных, иначе демо может выглядеть сломанным.» ✅ «Persona-scoped UI читает роль через `use-acting-context`; перепроверь рендер при смене персоны. (why: устаревшее чтение показывает данные чужой роли.)»

## Процедура
Идемпотентна: в зрелом репо прогоняй каждый self-check и действуй только по провалам; докладывай, что осталось.

## Два такта

**Такт 1 «встать» — без вопросов, до минуты, в любом репозитории.** Первый и по умолчанию единственный такт при первом контакте, по слову «iskronify» от человека или из дела. Не выводимое ложится дыркой.
1. **Адреса.** Граф и роль — из слова человека, строки окна с адресом места или существующего `AGENTS.md`. Графа нет и он не назван → единственный вопрос: имя графа (`iskron_realm(action="list")`; создание — `iskron_realm(action="create")` по слову человека). Роль владельца — 主-роль человека твоих ключей (`iskron_me(action="kartas")`); перечень, где стоишь ты сам, — знак сбитой привязки: слот дыркой, вопрос — в деле выравнивания; ролей у человека нет — заведи svatantra-роль (Шаг 2).
2. **Контур репозитория.** `origin` → `хост/организация/репо` → `iskron_search(q="", node_type="holon", attrs_filter="repository:<значение>")`. Нет — `iskron_add_holon` (`contains` от корня графа или контура репозиториев) с `attrs.repository` и `open_room` дела выравнивания. Один репозиторий — один контур.
3. **Роль на репо.** `iskron_search(q="", node_type="karta", steward_of=<контур>)`; нет — `iskron_add_karta` (`manifested_as=adhikarin`, мотивация — дистиллят того, что репо шипит) и `steward` к контуру. Одна роль на репозиторий.
4. **Обложка и файлы.** Скелет `AGENTS.md`: выводимые слоты (граф, контур, роли, репозиторий, стек, команда гейта, структура, раскладка по умолчанию) — «выведено»; авторские (nature, цена поломки, потребители, память, фидбэк, interop) — `<не согласовано — дело №N>`. «Жизненный цикл сессии» инлайнится из скелета как есть. `REALITY.md` пишется заголовком скелета и одной строкой: «Ещё не устоялось: прогони интервью (скажи iskronify), прежде чем принимать здесь любую поведенческую заявку.» — не слот; файл без таблицы читался бы «проверять нечего», а на него указывают `AGENTS.md` и ролевые файлы. Таблица Reality в `AGENTS.md` уже есть — переносится в `REALITY.md` по Шагу 7, заглушка не пишется.
5. **Дело выравнивания** на контуре из п. 2. Прежде первой записи — назовись (`iskron_channel(action="register", realm, karta=<роль на репо>, name=<выведенное имя>)`) и войди (`iskron_case(action="join")`); стояние на вахту не нужно. Открытое дело уже есть (`iskron_case(action="at", node=<контур>)`) — веди его; нет — открой `open_room` у записи контура или `iskron_update` существующего, зачином до 64 знаков: «Выравнивание <репо> под контракт N». Каждый авторский слот — строка своим ключом «слот: <имя>» (`partial` — на ком, чего ждёт), вопрос — словом в деле. Помочь ответить зови (`invite`): человека — его место, пока места нет — роль с контуром или кадр в его стояние-мост; агента, знающего ответ (стюарда соседнего репо), — `invite` или `iskron_case(action="talk")`. Первое слово: «есть вопросы по проекту, за который я отвечаю, — ответьте или скажите, кто может ответить». **Анкету, план и ход выравнивания в граф не пиши**; в граф такт пишет только структуру (контур с `repository`, роль) и готчи правилами (Шаг 7).
6. **Хук старта и сторож памяти** — из Шага 4 только `SessionStart` и memory-guard; стаб `MEMORY.md` (Шаг 5) — **только над пустой или отсутствующей директорией памяти**. Непустая — не трогай: эвакуация ждёт ответа о файле предпочтений (слот в деле), строка скелета о заморозке пишется `<не согласовано — дело №N>`. Остальные хуки — такт 2. Указатель `CLAUDE.md` — Шаг 7.
7. **Стояние** — не здесь: его занимает старт двери `iskron`, только на вахту.
Отчёт — строки гроссбуха такта в деле выравнивания, затем свободным текстом, что открыто; такт по слову другого дела — слово-отчёт там, называющее дело выравнивания; затем эстафета Шага 7. Такт по слову дела — поручение: его строку закрываешь ты, тем же ключом, по наблюдённому исходу.

**Такт 2 «доделать» — лениво, не блокируя.** Каждый старт в этом репо (шаг «Выравнивание» двери `iskron`) читает сводку дела из строки «Согласование» — `iskron_case(action="read")`; писать — назвавшись и войдя, как в п. 5. Ответ пришёл — слот вписывается «согласовано: кто» без переспроса, строка «слот: …» закрывается `ok`; нет — одна строка человеку, работа идёт. Ответ агента — не слово владельца: слот несёт «согласовано: <агент>», человеку предлагается **верифицировать выведенное**. Все слоты согласованы — «Согласование» становится «пусто», предложи закрыть (`propose_close` со свидетельством — строки слотов), если ведущий ты; иначе слово ведущему. Полная дуга (Шаги 1, 3, 4, 6 с интервью, строгим гейтом, всеми хуками, ролевыми агентами) — когда человек рядом и сказал «iskronify» либо дело закрыло авторские слоты: тогда `AGENTS.md` и `REALITY.md` перепроецируются той же обложкой.

### Шаг 1 — Согласуй (такт 2)
Не выбирай дефолты молча. Подтверди и запиши в обложку: **Nature** (не `production` — что ослаблено и почему), **имя графа**, «Стек», **гейт** (строжайший — Шаг 3). В существующем репо сперва выведи из репо и старого конфига, подтверждай только двусмысленное.

**Переход со старой анкеты.** «Согласование» или дырка называет узел (`#N`), не дело, — форма прежнего контракта. Прочти узел (`iskron_look`): ответы с именем ответившего — в слоты «согласовано: кто»; открытые — строками «слот: <имя>» в дело выравнивания, дырки — `<не согласовано — дело №N>`; узел-анкету отпусти (`visarjana`, reasoning «перенесён в дело №N»), чужой — слово автору.

Также согласуй:
- **Кто владеет направлением** — svatantra-роль владельца (主), создаётся в Шаге 2; вопросы вне мандата — вимаршами `posed_to` ей.
- **Общее изменяемое состояние build/test** (база, фиксированный порт, dev-сервер, глобальный кэш, облачная песочница): есть — зафиксируй по-полосную изоляцию готчей (агенты гоняют ветки конкурентно в отдельных worktree).
- **Реальность** → `REALITY.md`. Ничего не выводи — спрашивай: куда приземляется изменение, какие эффекты производит, какие наблюдаемы и какой командой / URL / запросом, что агент достаёт сам, что требует пользователя. Дожимай до *канонического носителя* каждого класса: собранный артефакт, не исходники; живой эндпоинт, не хендлер; чистая установка, не тёплый кэш. Класс без достижимого наблюдения — в *Ceiling* с причиной. Датированные замеры (сроки, версии, «наблюдено тогда-то») — узлами в граф, в `REALITY.md` — только нужное для наблюдения. В `AGENTS.md` — раздел «Reality» указателем: прочти `REALITY.md` прежде поведенческой заявки, первая строка таблицы названа, Ceiling — там. (Как таблица работает при закрытиях — скилл vahta, §3 «Работа и эстафета», абзац о `reality-audit` перед закрытием.)
- **Кросс-проектная память** — раз на пользователя. Личный граф `@<handle>/mind` есть у каждого, о нём не спрашивай: нет — заведи граф и роль по **minding**; маршрутизация и сообщение memory-guard всегда несут его ветку. Поведение агента настраивают **только** коммитящиеся файлы рабочего дерева (AGENTS.md, файл хуков) и граф проекта — никогда глобальный файл инструкций (`~/.claude/CLAUDE.md`, `~/.config/opencode/AGENTS.md`…), память харнесса, пользовательские хуки; о глобальном файле не спрашивай и не заводи. Установка поставки — доставка, не настройка. Предпочтение, влияющее на процесс и результат, — в AGENTS.md или граф проекта; личное — в `@<handle>/mind`.
- **Фидбэк-рефлексия** — раз на пользователя: рефлексировать ли опыт *о методе* в конце сессии или на мерже и записывать стоящее в граф работы (контур инструмента, адресом стюарду, после проверки на дубли, случаем)? **Да** → регион feedback-reflection скелета остаётся, хук мержа несёт такт. **Нет** → удали регион целиком.
- **Сосуществование с workflow-набором** — только когда найден коэрсивный набор (его скиллы в списке или его директория в кэше плагинов; сегодня superpowers): (1) **полный interop** (рекомендуется) — подсекция из `references/superpowers-interop.md` + spec-write-хук; (2) **только проза**; (3) **пропустить** — назови риск: дизайн-сессии набора не осядут в граф.

**Человек обычно не в треде** (вахта, ночь, дело, чужой харнесс) — «спроси» тогда вырождается в выдумку слота или простой; оба хуже пропуска. Порядок:
1. **Сделай всё, что от ответа не зависит**: аудит, выводимое, гейт, хуки.
2. **Вопрос — в деле выравнивания**, одно дело на всё, строка на слот; не в граф и не делом на слот. Сперва агенты: `invite` или `iskron_case(action="talk")` со стюардами соседних контуров; их ответ — в слот с их именем.
3. **Человека буди** `invite` его места; места нет — `invite` его роли с контуром (`karta=<роль владельца>`, `holon=<контур репо>`, как в п. 5 такта 1): вопрос ждёт в деле, и роль в новом графе заведена тем же тактом. Переходно — ещё и кадр в его стояние-мост: `iskron_channel(action="list")`, строку различай по `@handle`, не по имени (роль — не адрес). Моста нет — вопрос остаётся в деле; есть роль выше (стюард родительского контура, бригадир) — слово ей там же, что твой человек недостижим; нет её, как в новом графе, — скажи это человеку одной строкой, когда он появится в сессии.
4. **Дырка, не догадка**: `<не согласовано — дело №N>`; старт двери найдёт ответ и впишет, не переспрашивая.
Отвеченное пишется сразу; один слот не держит остальные.

### Шаг 3 — Гейт качества (строжайший, пользователь подтверждает)
По каждому пункту: строжайший вариант для стека, трейд-офф одной строкой, подтверждение. Послабления — только по явной просьбе, откалиброванной ценой поломки, и записываются в обложке по-инструментно. **Ужесточение уже-ослабленного гейта** — обязательство рефакторинга: сперва измерь (прогон на предлагаемой строгости, число провалов), нужна та же явная просьба, возможно — отдельная ветка.
- **Линтер** максимально строгий (`@typescript-eslint/strict`; Ruff `E,F,B,I,N,UP,RUF`; `golangci-lint` широкий; `clippy -- -D clippy::pedantic`).
- **Форматтер**, auto-fix on save + pre-commit (Prettier, `ruff format`, `gofumpt`, `rustfmt`).
- **Тайпчекер** strict, если есть (`tsc --strict`, `mypy --strict` / `pyright --strict`).
- **Pre-commit-хук**: линтер + форматтер + тайпчек по staged-файлам.
- **Тесты + дисциплина** (unit для библиотек; +integration для сервисов; +e2e для UI; порог покрытия для production) — в «Конвенции кода».
- **CI**: lint + typecheck + tests на каждый пуш, падает на предупреждениях; обязателен для `production`.
- **Гейт — ВЫЗЫВАЕМЫЙ**: один вызов, чья цепочка и есть правило (`npm run gate`, `make check`, `just check`); в `AGENTS.md` — его имя, не список шагов; CI зовёт тот же вызов. Собранный руками гейт теряет шаг молча и кончается зелёным. Цепочку вынужденно собирают руками — запиши почему и чем проверяется полнота.
- **CI-паритет**: всякая проверка, способная упасть, гейтит PR, не только post-merge (кодоген, генерация схем и доков, сборка образа, миграции) — дотяни до PR; неустранимый зазор — готчей.

Команды — в «Команды», дисциплина — в «Конвенции кода».

### Шаг 4 — Хуки
**Деливерабл — ритуалы, не файл.** Определи харнессы репо и прошей поверхность *каждого* в рабочем дереве (hooks-файл Claude Code, plugin-директория OpenCode проекта; хуки Codex живут в CODEX_HOME, вне worktree, и не прошиваются) по `references/harness-surfaces.md`. Где поверхности нет — скажи, какой ритуал не автоматизирован: его держит проза «Жизненного цикла сессии». Конфиг формата, о котором гадаешь, не пиши.

**Хук меряется ценой в контексте и тем, чему учит**: одна строка и указатель на раздел AGENTS.md, не пересказ ритуала; срабатывание — на самом событии; не ставится, если та же строка приходит другим путём (описание тула, дверь скилла); не учит обратному правилу (не наказывает законный вопрос человеку). Блокирует только хук с однозначным путём (memory-guard).

Claude Code: хуки в `.claude/settings.json` (коммитится). **Мержи, никогда не перезаписывай** — записи других наборов остаются рядом в тех же массивах. Конверт: `"<Событие>": [ { "matcher"?: …, "hooks": [ { "type": "command", "command": "… echo '{\"hookSpecificOutput\":{\"hookEventName\":\"<Событие>\",\"additionalContext\":\"<строка>\"}}' || true" } ] } ]` — вложенность `событие → массив → hooks` легко перепутать. **Открой `references/hooks.md` и спроецируй фильтры пуша и мержа оттуда** байт-в-байт, с образцами проверки. Проецируя фильтр в JSON, **удваивай каждую обратную косую** (`\n` → `\\n`) и экранируй кавычки `\"`: иначе фильтр не компилируется, хук молчит навсегда, а `|| true` это прячет. Запись `.claude/settings.json` харнесс может счесть самомодификацией — вынеси её на подтверждение человеку, не считай, что легла молча. Хуки:
- **`SessionStart`** → прочитать раздел «Старт» двери `iskron` до действий; адреса репо (граф, фокус-контур, seq ролей агента и владельца); стояние только на вахту (слово «вахта», `start`, адрес места из окна, кадр), одним `iskron_stand`; `start <граф> <роль> <дело №N>` входит в дело; у субагента свой мост-спутник (`iskron_stand` с `satellite_of`, `join`, `leave` — на нём), на мосту запустившего он в граф не пишет. Протокол старта не пересказывай.
- **`PostToolUse`/Bash — пуш**: `git push` отработал (по исходу, справка не будит) → пуш не отгрузил ничего: самопроверка диффа, **словарный проход** по тексту PR, **холодное ревью этапа** (раздел о ревью AGENTS.md); отгрузка — мерж.
- **`PostToolUse`/Bash — мерж**: мерж форжи слил PR (по исходу) либо подтяжка ствола (`git checkout main && git pull`) → акты после мержа из «Жизненного цикла сессии» (проткать, продвинуть карту, модусы, закрыть по оси, reconcile, фидбэк-рефлексия, если согласована, словарный проход).
- **`PreToolUse` `Write|Edit|MultiEdit` — memory-guard**: путь внутри локальной директории проектной памяти → **блок** (exit 2, маршрутизирующее сообщение в stderr).
- **`PostToolUse` `Write|Edit` — spec-write** (только полный interop, по interop-штампу AGENTS.md): путь похож на design/spec-док → напоминание, что запись дизайна — граф.
- **Свежесть ветки** — предложи pre-push-хук (`references/hooks.md`).

Self-check: четыре базовых хука на месте (старт, пуш, мерж, memory-guard); хуков, снятых прежними контрактами (сторож незастывания на `Stop`, указатель момента writing на пишущих тулах), нет — на рефреше убери свои, не трогая чужих; spec-write есть **тогда и только тогда**, когда interop-штамп говорит `full`; `SessionStart` зовёт «Старт» двери `iskron` (не `entry`) с реальными адресами; фильтры пуша и мержа — байт-в-байт из `references/hooks.md` и проверены на образцах оттуда; ни одна чужая запись не выпала.

- Тело — в **`AGENTS.md`** (Codex и OpenCode читают нативно), таблица носителей — в **`REALITY.md`** корня. **Указатель `CLAUDE.md`** — только для Claude Code; форма по `git config core.symlinks` и платформе:

  Работающий указатель любой формы не переделывай. Пер-харнессные детали (merge root→cwd у Codex, `AGENTS.override.md`) — `references/harness-surfaces.md`.
- **Легаси-конфиг**: скелеты — рама; производные факты ре-спроецируй, авторское сохрани, сверив с кодом; проектное без слота — в «Конвенции кода» или новую секцию. Таблица Reality внутри `AGENTS.md` (контракт до 16) — переезжает в `REALITY.md` строками целиком, датированные наблюдения из неё — узлами в граф (не удаляются), в `AGENTS.md` остаётся указатель. Содержательный `CLAUDE.md` — влей в `AGENTS.md`, замени указателем. Файлы «Раскладки» не вливаются — только сверяются ссылки. Один источник на заботу.
- Interop full / prose-only: подсекция `### Workflow-suite interop (superpowers)` в конце «Жизненного цикла сессии» из `references/superpowers-interop.md` (только деплоируемая часть) со штампом `*(interop: <full|prose-only> — verified against superpowers@<version> — re-check on suite upgrade)*`; на рефрешах аудируй её как любую заботу.
- **Проверочный проход (на равных с плотностью)**: каждая *производная* строка обоих файлов против источника — **весь артефакт**, не только тронутое. Не привязывается к источнику — авторское суждение (сохрани) или догадка (вырежи).
- **Проход плотности**: «меняет ли строка то, что агент делает?» — режь нарратив и обоснования (в граф). Блоки канонов не трогаются — сверяются с узлом байт-в-байт.
- Автоматический чекер «заявленное vs фактическое» — согласованный не-дефолт; строить — только узкий пер-репо по именованным строкам, обобщённый — никогда. Дисциплина — пере-прогон.
- **Штамп**: хвостовая строка `AGENTS.md` — `*(iskronify: контракт <число из шапки>, штамп <YYYY-MM-DD> — предложи перезапуск, когда описание установленного iskronify называет контракт выше или когда источники, из которых выведен этот файл, сдвинулись после этой даты.)*`. На рефреше перезапиши; двух не оставляй.
- **Обложка — таблица**: слот, значение, источник (`выведено` / `согласовано: кто` / `<не согласовано — дело №N>`); «Согласование» называет дело выравнивания, не узел.
- **Готчи в `AGENTS.md` не живут**: узел графа на контуре, в файле и коде — `(граф, #N)`; при `GOTCHAS.md` по «Раскладке» — строка там со ссылкой на узел.
- **`REALITY.md` проверен**: носители названы авторски (не выведены), ни одного датированного замера, Ceiling назван; раздел «Reality» в `AGENTS.md` — указатель без строк таблицы.
- Ни один слот `<…>` без ссылки на дело и ни одна заметка `<!-- … -->` не пережили в обоих файлах.
- **Каждое имя скилла в проецируемых файлах** (`AGENTS.md`, `REALITY.md`, хуки, ролевые файлы) разрешается как записано на канале установки репо — сверь с живым реестром, не по памяти; невызываемое имя не падает, а молчит. Механической сверки в прокачиваемом репо может не быть — тогда вручную, как имена тулов по живой поверхности сервера. Тело, едущее в несколько харнессов (ролевой файл), формы вызова не несёт вовсе — называй вызовы тулов.
- На бутстрап-пуше граф отражает перемену структурой (контур, роль, готчи, карта); ход выравнивания — строками дела.
- **Передай эстафету**: закончи тизером роадмапа (скилл `product-roadmap`, quick-режим) по свежему репо, названным по имени. После такта 1 — два пункта: тизер, затем «открытые слоты обложки — в деле выравнивания №N; ответишь там или агентам — впишу на старте; полная дуга — по слову `iskronify`».
