# Repo-boost

Приведи **текущий репозиторий** к агентскому стандарту iskron: плотный `AGENTS.md` (читается каждую сессию каждым харнессом), `REALITY.md` рядом (таблица носителей реальности, читается по поводу — при поведенческой заявке и в брифе `verifier`/`reviewer`), `CLAUDE.md`-указатель, ритуалы сессии хуками и гейт качества. Конфиг ты **генерируешь** из скелетов — пользователь шаблонов не вставляет.

Деливерабл — **интерфейс доверия**. `AGENTS.md` и `REALITY.md` — *производные виды*: проекция источников (код, `package.json`, CI, файловая система, граф) плюс тонкий слой авторского суждения, который больше нигде не живёт. Контракт двуглав: **плотность** (каждая строка меняет поведение) и **точность** (каждая производная строка перепроверена против источника *в этом прогоне*). Плотная ложная строка хуже многословной.

Скелеты: `references/agents-template.md` (`AGENTS.md`: YAML-фронтматтер и тело) и `references/reality-template.md` (`REALITY.md`) — слоты `<…>` и заметки `<!-- … -->`. Заполни слоты, выброси неприменимые опциональные строки, вычисти каждую заметку и угловую скобку. Скелеты — *что произвести*; этот файл — *как*.

**Контракт: `27`.** Шаг 7 штампует это число в каждый `AGENTS.md`. Увеличивай на единицу, только когда перемена здесь или в скелетах делает уже сгенерированный файл *неверным* (секция или файл добавлены, переименованы, изъяты; ритуал изменён; имя тула выпало), никогда ради формулировок. То же число стоит первым словом в `description` — нарочно: триггер срабатывает по описанию, а в контексте сессии сходятся только описания скиллов и штамп `AGENTS.md`; расхождение копий ловит `make validate`. Конфиг со штампом-датой или без штампа — ниже любого числа: прогони полную дугу (правило запуска держит шаг «Выравнивание» двери `iskron`) и назови контракт, из которого пришёл конфиг.

**Строка `AGENTS.md` расходится со скиллом — назови вслух, молча не выбирай**: в деле постановщику, без дела — человеку. Штамп ниже контракта установленного `iskronify` — прав скилл, прогони; равен — дефект шаблона, фидбэк стюарду поставки скиллов (**feedback**). Правило стоит и в скелете («Держи этот файл честным») — для агента, этот скилл не загрузившего.

**Редакция установленной поставки сверяется здесь.** Всякий прогон — и всякий вывод «инструкция скилла неверна» (туда шлют **feedback** и **entry**) — начинается сверкой бегущего с выпущенным:

```
cat ~/.claude/plugins/cache/*/*/*/.claude-plugin/plugin.json     # что у тебя бежит
gh release view --repo <репозиторий плагина> --json tagName      # что существует
node ~/.iskron-bridge/iskron-bridge.mjs --version                # какую сборку несёт копия моста
```

Отстал больше чем на патч — обнови поставку, перезапусти сессии харнесса и только потом гони дугу: конфиг из протухшего скилла наследует его дефекты. Число контракта этого не заменяет: оно движется с формой конфига, версия — с каждой отгрузкой.

Скелет *инлайнит* граф-агностичную дисциплину (Рабочие принципы, «Жизненный цикл сессии») в каждый `AGENTS.md` — сжато, по строке на правило, но **инлайн, не указателем** в граф или скилл: есть харнессы без хука старта, и файл обязан стоять сам.

## Аудит → классификация → действие
Репозиторий — спектр, не «свежий или настроенный»; ловушка — «файл есть, значит, его факты верны». Аудируй каждую заботу против её источника и классифицируй:
- **absent** — выведи из источника; авторский слот без проверяемого источника — в дело выравнивания, никогда не выдумывай.
- **stale** — ре-спроецируй, перезаписав; записанное не тащи вперёд.
- **correct** — оставь.

Опаснее всего *почти-верный* конфиг: устаревшие строки среди доверенных — проверочный проход идёт по всему артефакту (Шаг 7).

### Источник истины по заботам
| Забота | Источник истины | Как проверить |
|---|---|---|
| Версии, зависимости | `package.json` / `pyproject.toml` / `go.mod` / `Cargo.toml` + lockfile | прочитать |
| Команды build/test/lint/dev | scripts, `Makefile`/`Justfile`, CI-workflow | прочитать; `--help`/dry-run, где дёшево |
| Гейт качества | конфиг линтера, `tsconfig`, CI-yaml | прочитать |
| Раскладка: карта кода, ловушки среды | слот обложки «Раскладка» | слота нет — умолчание: один `AGENTS.md`, навигация по файлам — компактно в README компонента, готчи в графе; прогон README компонентов не пишет: пока README компонента нет, его карта — в «Структуре проекта» `AGENTS.md`, и первый, кто тронет компонент, переносит её в README. Отступление — раздел «Структура проекта» вместо README — только там, где README рядом с выходами запрещён (выходы уезжают потребителю); запрет действует на такие выходы, не на весь репо, и выводится из него самого. `GOTCHAS.md` в репо — чья-то раскладка: разреши по Шагу 1; пока источники её не разрешили — слот пустой, источник `не согласовано — дело №N`, файлы нетронуты |
| Структура проекта, path-алиасы | файловая система + конфиг бандлера; при раскладке «README компонента» — сами README | glob / list; таблица «компонент → README» сверяется существованием файлов |
| Nature, production statement, послабления | граф, код репо, слово агентов; принятые владельцем ограничения сохраняются | разрешить по порядку Шага 1; смена мандата или цены поломки без основания — принципиальный вопрос |
| Носители реальности (`REALITY.md`) | граф, наблюдаемый кодом путь поставки, слово агентов | проверить достижимость канонического носителя; неизвестное — Ceiling, не выдуманный носитель |
| Проектные решения, why-клаузы, открытые вопросы | граф | `iskron_orient` / `iskron_search` |
| Состояние веток | git + форжа | `git status` / `log`; CLI форжи |
| Готчи | авторское; дом — по слоту «Раскладка» | только sanity-check — не автовыводить, не переносить между домами |
| Блоки канонов графа | узел-правило с `attrs.prose_for_repos` | `iskron_search(realm=<граф>, q="", attrs_filter="prose_for_repos:**")`; блок кладётся байт-в-байт на место из `attrs.prose_anchor`, ниже — только хвост репо; применимость — по `attrs.scope`, иначе по смыслу, сомнение — порядком Шага 1 |

**Производные факты** (верхние строки, блоки канонов) ре-проецируются каждый прогон; **авторское суждение** (готчи, why-клаузы, nature, носители) сохраняется, лишь сверяясь на здравость с кодом.

## Контракт выхода — плотность и точность
1. **Императив агенту**: «ориентируйся до кода», не «агенту следует».
2. **Каждая строка меняет то, что агент делает**; иначе удали. Чек-лист, не эссе.
3. **Без проектных обоснований и пересказа графа** — линкуй. `(why: …)` — только для инварианта, который агент иначе нарушит.
4. **Таблицы и буллеты**, одна директива на буллет.
5. Секция, растёкшаяся в абзацы, несёт обоснование — перенеси в граф.

**Вне объёма — механика оркестрации** (цепочки гейтов, суб-агентная проверка пушей, model-routing, многополосная координация): её дом — скилл оркестрации или граф; срез делегирования проецируется ролевыми файлами (Шаг 6), не прозой.

Пример: ❌ «Мы стараемся аккуратно обращаться с состоянием, потому что стор — единственное место данных, иначе демо может выглядеть сломанным.» ✅ «Persona-scoped UI читает роль через `use-acting-context`; перепроверь рендер при смене персоны. (why: устаревшее чтение показывает данные чужой роли.)»

## Процедура
Идемпотентна: в зрелом репо прогоняй каждый self-check и действуй только по провалам; докладывай, что осталось.

## Два такта
**Кто исполняет прогон.** Граф прогона — контур, роль, атрибуты, дело выравнивания — ведёт сам агент: это ремесло графа («Сквозные нормы» двери `iskron`). Объёмную проекцию файлов (`AGENTS.md`, ролевые файлы, хуки) он может отдать субагенту роли `designer` — у того свой мост-спутник; нет субагентов, ролевого файла `designer` ещё нет (первый контакт, такт 1 до проекции, роли старше контракта) или спутник не поднялся — проецирует сам. Прогон обновляет `AGENTS.md` и производные сам, не ждёт присутствия или подтверждения человека. Дело выравнивания ведёт позвавший (ведущий); `designer` работает в своём дочернем деле из строки запуска и дела выравнивания не ведёт (п. 5). Человека будит и ожидание держит ведущий, не `designer`, и только по принципиальному вопросу, не разрешённому графом, кодом и коллегами: `designer` возвращает его вопросом в итоге. Вопросы прогона — порядком Шага 1 («Человек обычно не в треде»).

**Ветвь «Первый граф» — `references/first-graph.md`: при нуле рабочих графов у учётки (`@handle/mind` не в счёт) или приглашении в общий граф открой и исполни целиком до такта 1, без отдельного вызова.** Ядро: разговор ведёт **onboarding**; граф → минимальные хуки → роль человека (`user="me"`) → контур и репозиторий → после Шага 7 слово о возможностях; граф не создаётся без показа найденного, origin и вопроса об области. Рабочий граф есть — ветвь не срабатывает.

**Такт 1 «встать» — без вопросов, до минуты, в любом репозитории.** Первый такт при первом контакте, по слову «iskronify» или при найденном отставании конфига. Быстро разрешаемое — в файл с источником, остальное — дыркой в дело; затем такт 2 без ожидания человека.
1. **Адреса.** Граф и роль — из слова человека, строки окна с адресом места или существующего `AGENTS.md`. Граф не назван — `iskron_realm(action="list")`: нуль рабочих графов или приглашение в общий — ветвь «Первый граф» выше; иначе сверь с записанным о репо и спроси коллег; не разрешилось, какой граф выбрать или создать, — принципиальный вопрос о границе проекта по Шагу 1, не угадывай имя. Создание — `iskron_realm(action="create")` по принятому выбору. Роль владельца — 主-роль человека твоих ключей (`iskron_me(action="kartas")`); перечень, где стоишь ты сам, — знак сбитой привязки: слот дыркой, вопрос — в деле выравнивания. `kartas` видит только привязанные роли: прежде чем заводить svatantra-роль (Шаг 2), ищи её в графе — `iskron_search(q="", node_type="karta", manifested_as="svatantra")`. Он отдаёт все 主-роли графа: роль владельца — та, чей `handle` в атрибутах совпал с handle из `iskron_me(action="whoami")`; такая есть — не заводи, не выбирается — один вопрос человеку сессии, какая из найденных его. Привязку роли владельца проверь по шагу «Сойдись или эскалируй» скилла **standing**.
2. **Контур репозитория.** `origin` → `хост/организация/репо` → `iskron_search(q="", node_type="holon", attrs_filter="repository:<значение>")`. Нет — `iskron_add_holon` (`contains` от корня графа или контура репозиториев) с `attrs.repository` и `open_room` дела выравнивания. Один репозиторий — один контур.
3. **Роль на репо.** `iskron_search(q="", node_type="karta", steward_of=<контур>)`; нет — `iskron_add_karta` (`manifested_as=adhikarin`, мотивация — дистиллят того, что репо шипит) и `steward` к контуру. Одна роль на репозиторий.
4. **Обложка и файлы.** Слоты — YAML-фронтматтер в начале `AGENTS.md` по скелету и Шагу 7. Из графа и кода — «выведено»; из записанного ответа — «согласовано: кто», в том числе агент соседнего контура. Не разрешённое — пустое значение и источник «не согласовано — дело №N»; авторский слот не становится дыркой только потому, что человек отсутствует. «Жизненный цикл сессии» инлайнится из скелета. `REALITY.md` — таблицей разрешённых носителей; пока их нет, заголовок скелета и строка: «Носители ещё не установлены; дело выравнивания №N. До их установления поведенческие заявки не принимаются.» Таблица Reality в `AGENTS.md` уже есть — переносится в `REALITY.md` по Шагу 7.
5. **Дело выравнивания** на контуре из п. 2 ведёт позвавший (ведущий): открытое уже есть (`iskron_case(action="at", node=<контур>)`) — ведёт его; нет — открывает `open_room` у записи контура или `iskron_update` существующего, зачином до 64 знаков: «Выравнивание <репо> под контракт N». Прежде первой записи — своё место и вход (`iskron_case(action="join")`); вахта не нужна. Исполняешь сам — ведущий ты: место сессии уже держит мост — `iskron_channel(action="register", realm, karta=<роль на репо>, name=<его имя>)` называет его; места нет — `iskron_stand(realm, karta=<роль на репо>)` одним вызовом (`register` без держимого места сервер отказывает). Проекцию файлов исполняет субагент `designer` — ведущий заводит ему дочернее дело (`open_room` с `parent_room` — дело выравнивания) и ставит его №N в строку запуска; `designer` встаёт спутником (`iskron_stand` с `satellite_of` места позвавшего, как в `references/delegation-1.md`, `references/delegation-2.md` — открой и прочти обе части по порядку до хода), `register` под выведенным именем не зовёт (имя — позвавшего), вопросы слотов говорит словом в дочернем деле, в граф не пишет, дела выравнивания не ведёт и выходит концом поручения (`iskron_case(action="leave")`). Неразрешённый, ждущий слот можно держать строкой «слот: <имя>» (`partial` — на ком, чего ждёт) — по желанию; разрешённый — значение и источник во фронтматтер, без строки; вопрос — словом в деле. Вопросы прогона — порядком Шага 1 («Человек обычно не в треде»). Первое слово: «есть вопросы по проекту, за который я отвечаю, — ответьте или скажите, кто может ответить». **Анкету, вопросы прогона, план и ход выравнивания в граф не пиши**; в граф такт пишет только структуру (контур с `repository`, роль) и готчи правилами (Шаг 7).
6. **Хук старта и сторож памяти** — из Шага 4 только `SessionStart` и memory-guard; стаб `MEMORY.md` (Шаг 5) — **только над пустой или отсутствующей директорией памяти**. Непустая — эвакуация по Шагу 5 в такте 2; до неё строка скелета о заморозке не утверждает завершения, а ссылается на строку дела выравнивания. Остальные хуки — такт 2. Указатель `CLAUDE.md` — Шаг 7.
7. **Стояние** — не здесь: его занимает старт двери `iskron` — на вахту или перед первой записью.
Отчёт — слово в деле выравнивания: что разрешено, что открыто; такт по слову другого дела — слово-отчёт там, называющее дело выравнивания; затем эстафета Шага 7. Такт по слову дела — поручение, и его исход по наблюдённому говоришь словом в том деле.

**Такт 2 «доделать» — сам, не блокируя.** Продолжи после такта 1; каждый следующий старт (шаг «Выравнивание» двери `iskron`) читает сводку дела из ключа «Согласование» фронтматтера — `iskron_case(action="read")`; писать — своим местом и войдя, как в п. 5. Слоты разрешай графом, кодом и словом коллег по Шагу 1. Впиши значение и источник во фронтматтер без переспроса; строка ожидания «слот: …», если слот её держал, снимается тем же ходом (`ok`), разрешённому без ожидания строка не заводится. Ответ агента подписывается его именем, не именем владельца; повторного подтверждения человеком не требует. Полная дуга (Шаги 1, 3, 4, 6, гейт, хуки, ролевые агенты) идёт без человека; неразрешённый слот держит только зависимую часть. Все слоты разрешены — «Согласование» = «пусто», предложи закрыть (`propose_close`, свидетельство — слоты фронтматтера со значениями и источниками), если ведущий ты; иначе слово ведущему.

### Шаг 1 — Разреши слоты (такт 2)
Не выбирай дефолты молча. Прочти граф, код репо и старый конфиг; чего они не разрешили — спроси у агентов соседних контуров в деле выравнивания. Запиши во фронтматтер значение и источник: **Nature** (не `production` — что ослаблено и почему), **имя графа**, «Стек», **гейт** (Шаг 3). Принятые авторские ограничения сохраняй; переспрос человеку нужен только для принципиального остатка.

**Переход со старой анкеты.** «Согласование» или дырка называет узел (`#N`), не дело, — форма прежнего контракта. Прочти узел (`iskron_look`): ответы с именем ответившего — в слоты «согласовано: кто»; открытые — строками «слот: <имя>» в дело выравнивания, пустое значение и источник `не согласовано — дело №N` во фронтматтер; узел-анкету отпусти (`visarjana`, reasoning «перенесён в дело №N»), чужой — слово автору.

Также согласуй:
- **Кто владеет направлением** — svatantra-роль владельца (主), создаётся в Шаге 2; принципиальные вопросы слотов — ей через ведущего в деле выравнивания, не анкетой в графе.
- **Общее изменяемое состояние build/test** (база, фиксированный порт, dev-сервер, глобальный кэш, облачная песочница): есть — зафиксируй по-полосную изоляцию готчей (агенты гоняют ветки конкурентно в отдельных worktree).
- **Реальность** → `REALITY.md`. Установи из графа, кода и ответов коллег: куда приземляется изменение, какие эффекты производит, какие наблюдаемы и какой командой / URL / запросом, что агент достаёт сам, что требует пользователя. Дожимай до *канонического носителя* каждого класса: собранный артефакт, не исходники; живой эндпоинт, не хендлер; чистая установка, не тёплый кэш. Класс без достижимого наблюдения — в *Ceiling* с причиной; вывод о носителе не равен наблюдению поведения. Датированные замеры (сроки, версии, «наблюдено тогда-то») — узлами в граф, в `REALITY.md` — только нужное для наблюдения. В `AGENTS.md` — раздел «Reality» указателем: прочти `REALITY.md` прежде поведенческой заявки, первая строка таблицы названа, Ceiling — там. (Как таблица работает при закрытиях — скилл vahta, §3 «Работа и эстафета», абзац о `reality-audit` перед закрытием.)
- **Кросс-проектная память** — умолчание шаблона: значение из скелета, источник `выведено: умолчание шаблона`, без вопроса человеку. Личный граф `@<handle>/mind` есть у каждого, о нём не спрашивай: подтверждено отсутствие — заведи граф и роль по **minding**; недоступность не отсутствие. Наполнение и полная сверка — по просьбе; чисто проектная работа не требует чтения mind. Маршрутизация и сообщение memory-guard всегда несут личную ветку. Проектные инструкции держат коммитящиеся файлы рабочего дерева (AGENTS.md, файл хуков) и граф проекта — никогда глобальный файл инструкций (`~/.claude/CLAUDE.md`, `~/.config/opencode/AGENTS.md`…), память харнесса, пользовательские хуки; о глобальном файле не спрашивай и не заводи. Установка поставки — доставка, не настройка. Личное предпочтение организации работы, мнение или переносимый способ → `@<handle>/mind`, даже на тему разработки; правило и способ самого проекта → AGENTS.md или граф проекта по полномочию. Личное не отменяет чужого обязательства; применение найденного — по **minding**, не копированием в проект.
- **Фидбэк-рефлексия** — рефлексировать ли опыт *о методе* в конце сессии или на мерже и записывать стоящее в граф работы (контур инструмента, адресом стюарду, после проверки на дубли, случаем). Умолчание шаблона — **да**, источник `выведено: умолчание шаблона`, без вопроса человеку: регион feedback-reflection скелета остаётся, хук мержа несёт такт. **Нет** — только по записанному слову (`согласовано: кто`): удали регион целиком.
- **Сосуществование с workflow-набором** — только когда найден коэрсивный набор (его скиллы в списке или его директория в кэше плагинов; сегодня superpowers): (1) **полный interop** (рекомендуется) — подсекция из `references/superpowers-interop.md` + spec-write-хук; (2) **только проза**; (3) **пропустить** — назови риск: дизайн-сессии набора не осядут в граф.

**Человек обычно не в треде.** Прогон сам обновляет `AGENTS.md` и производные; присутствие человека не условие. Везде выше и ниже «согласуй», «спроси», «подтверди» для слота означают этот порядок:
1. **Сделай всё, что от ответа не зависит**: аудит, выводимое, гейт, хуки.
2. **Сперва граф и код, затем братья — агенты соседних контуров.** Неразрешённое — в одном деле выравнивания, вопросом `ask` по двери **iskron**, «Ожидание от делателя»; строка «слот: <имя>» — по желанию, на отдельном от карточки ключе («Ключ вопроса не перекрывай строкой работы» там же), не узел и не дело на слот. Позови знающих коллег `iskron_case(action="invite")`; поручение — `say` с `to` на место по «Разовая задача — слово в деле» двери. Их `answer` прими `ack`, ответ — в слот с их именем. Факт из графа или кода впиши как «выведено», без строки дела; неочевидное основание — словом в деле.
3. **Только принципиальный остаток — человеку через ведущего дела.** Смена мандата, принятого ограничения, цены поломки, выбор или создание графа (граница проекта, такт 1, п. 1) либо неразрешимый конфликт источников — принципиальное; отсутствие ответа или сведений само по себе — нет. Прежде эскалации назови, что проверено в графе и коде, кого спросил и почему это требует решения владельца. `designer` возвращает такой вопрос в отчёте; ведущий говорит его словом в деле (строка «слот: …» — по желанию). Позвавший будит человека и держит ожидание: `invite` его места; места нет — его роли с контуром (`karta=<роль владельца>`, `holon=<контур репо>`). Нет доступного места — вопрос остаётся в деле у ведущего; остальная работа продолжается.
4. **Дырка, не догадка**: значение слота `''`, его источник `'не согласовано — дело №N'`; `Согласование` называет это дело. Непринципиальное неизвестное ждёт знающего агента или ведущего — словом в деле, строка по желанию. Старт двери найдёт ответ и впишет без переспроса.
Отвеченное пишется сразу; один слот не держит остальные.

### Шаг 4 — Хуки
**Деливерабл — ритуалы, не файл.** Определи харнессы репо и прошей поверхность *каждого* в рабочем дереве (hooks-файл Claude Code, plugin-директория OpenCode проекта; хуки Codex живут в CODEX_HOME, вне worktree, и не прошиваются) по `references/harness-surfaces.md`. Где поверхности нет — скажи, какой ритуал не автоматизирован: его держит проза «Жизненного цикла сессии». Конфиг формата, о котором гадаешь, не пиши.

**Хук меряется ценой в контексте и тем, чему учит**: одна строка и указатель на раздел AGENTS.md, не пересказ ритуала; срабатывание — на самом событии; не ставится, если та же строка приходит другим путём (описание тула, дверь скилла); не учит обратному правилу (не наказывает законный вопрос человеку). Блокирует только хук с однозначным путём (memory-guard).

Claude Code: хуки в `.claude/settings.json` (коммитится). **Мержи, никогда не перезаписывай** — записи других наборов остаются рядом в тех же массивах. Конверт: `"<Событие>": [ { "matcher"?: …, "hooks": [ { "type": "command", "command": "… echo '{\"hookSpecificOutput\":{\"hookEventName\":\"<Событие>\",\"additionalContext\":\"<строка>\"}}' || true" } ] } ]` — вложенность `событие → массив → hooks` легко перепутать. **Открой `references/hooks.md` и спроецируй фильтры пуша и мержа оттуда** байт-в-байт, с образцами проверки. Проецируя фильтр в JSON, **удваивай каждую обратную косую** (`\n` → `\\n`) и экранируй кавычки `\"`: иначе фильтр не компилируется, хук молчит навсегда, а `|| true` это прячет. Хуки прогон пишет сам, как всю дугу такта 2. Харнесс, спрашивающий разрешение на запись `.claude/settings.json` как на самомодификацию, — его ограничение, не норма: назови его словом в отчёте и проверь чтением, что запись легла. Хуки:
- **`SessionStart`** → прочитать раздел «Старт» двери `iskron` до действий; адреса репо (граф, фокус-контур, seq ролей агента и владельца); стояние — на вахту (слово «вахта», `start`, адрес места из окна, кадр) или перед первой записью в граф или дело, одним `iskron_stand`; читающая сессия места не занимает; `start <граф> <роль> <дело №N>` входит в дело; у субагента свой мост-спутник (`iskron_stand` с `satellite_of`, `join`, `leave` — на нём), на мосту запустившего он в граф не пишет. Протокол старта не пересказывай.
- **`PostToolUse`/Bash — пуш**: `git push` отработал (по исходу, справка не будит) → пуш не отгрузил ничего: самопроверка диффа, **словарный проход** по тексту PR, **холодное ревью этапа** (раздел о ревью AGENTS.md); отгрузка — мерж.
- **`PostToolUse`/Bash — мерж**: мерж форжи слил PR (по исходу) либо подтяжка ствола (`git checkout main && git pull`) → акты после мержа из «Жизненного цикла сессии» (протки, продвинуть карту, модусы по свидетельству, закрыть по оси, reconcile, фидбэк-рефлексия, если согласована, словарный проход; у работы по ссылке от агента — только семя превращения и модусы поставки). Сообщение хука называет и исключение — тем же списком, что раздел `AGENTS.md`, иначе ритуал и хук расходятся.
- **`PreToolUse` `Write|Edit|MultiEdit|NotebookEdit` — memory-guard**: путь внутри локальной директории проектной памяти → **блок** (exit 2, маршрутизирующее сообщение в stderr). Маршрут — из слотов сообщения `references/hooks.md`: граф проекта по имени из «Граф» фронтматтера, раздел персистентности — заголовком, как он стоит в `AGENTS.md`, на языке файла, и личный граф `@handle/mind`.
