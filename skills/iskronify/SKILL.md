# iskronify — приведение репозитория к стандарту

Приведи **текущий репозиторий** к агентскому стандарту iskron: плотный `AGENTS.md` (читается каждую сессию каждым харнесом), `REALITY.md` рядом (носители реальности, читается по поводу), `CLAUDE.md`-указатель, ритуалы сессии и гейт качества. Конфиг **генерируешь** из скелетов `references/agents-template.md` (обложка и тело) и `references/reality-template.md`: слоты `<…>` заполни, неприменимые опциональные строки выброси, ни заметки `<!-- … -->`, ни угловой скобки в выходе не оставляй. Оба файла — *производные виды*: проекция источников (код, `package.json`, CI, файловая система, граф) плюс тонкий слой авторского суждения, которое больше нигде не живёт. У контракта два требования: **плотность** (каждая строка меняет поведение) и **точность** (каждая производная строка перепроверена против источника *в этом прогоне*).

**Контракт: `40`.** Шаг 7 пишет это число в `contract` обложки каждого `AGENTS.md`; то же число стоит в `description` после «КОНТРАКТ AGENTS.md:». Увеличивай на единицу, только когда перемена здесь или в скелетах делает уже сгенерированный файл *неверным* (секция, файл или ритуал добавлены, изменены, изъяты; имя тула выпало; обязательство внутри раздела снято), никогда ради формулировок. Обложка ниже 40, прежней формы, со штампом-датой или без штампа — прогони полную дугу (правило запуска — шаг «Выравнивание» двери `iskron`), назови контракт, из которого пришёл конфиг, и **до перемен открой `references/migrations.md`**: переходы с исходного числа и признаки прежних форм, которые ищутся содержимым при любом контракте.

**Файл впереди поставки — не понижай.** `contract` обложки выше 40 — прогон не зови и число не переписывай: найди копию `iskronify`, которая затеняет установленную (вендорённая `.agents/skills/iskronify`, кэш плагина), обнови её и перечитай описание. **Строка `AGENTS.md` расходится со скиллом — назови вслух, молча не выбирай** (шаг «Выравнивание» двери `iskron`): `contract` ниже — прав скилл, прогони; выше — прав файл, обнови поставку; равен — дефект шаблона, **feedback** стюарду поставки скиллов.

**Редакция установленной поставки сверяется здесь**: всякий прогон и всякий вывод «инструкция скилла неверна» начинается сверкой бегущего с выпущенным:

```
cat ~/.claude/plugins/cache/*/*/*/.claude-plugin/plugin.json     # что бежит (Claude Code; прочие харнесы — версия моста ниже)
gh release view --repo <репозиторий плагина> --json tagName      # что существует
node ~/.iskron-bridge/iskron-bridge.mjs --version                # какую сборку несёт копия моста
```

Отстал больше чем на патч — обнови поставку, перезапусти сессии харнеса и только потом гони дугу; число контракта движется с формой конфига, версия — с каждой отгрузкой.

Скелет *инлайнит* дисциплину («Правила персистентности», «Жизненный цикл сессии», «Рабочие принципы») в каждый `AGENTS.md` исполнимой строкой на правило — действие, условие, ответственный, детали указателем: есть харнесы без хука старта, и файл обязан стоять сам.

## Аудит → классификация → действие
Ловушка — «файл есть, значит, его факты верны». Аудируй каждую заботу против её источника и классифицируй:
- **absent** — выведи из источника; авторский слот без проверяемого источника — в дело выравнивания, никогда не выдумывай.
- **stale** — ре-спроецируй, перезаписав; записанное не тащи вперёд.
- **correct** — оставь.

Почти-верный конфиг опаснее отсутствующего: проверочный проход Шага 7 — по всему артефакту.

### Источник истины по заботам
| Забота | Источник истины | Как проверить |
|---|---|---|
| Версии, зависимости | `package.json` / `pyproject.toml` / `go.mod` / `Cargo.toml` + lockfile | прочитать |
| Команды build/test/lint/dev | scripts, `Makefile`/`Justfile`, CI-workflow | прочитать; `--help`/dry-run, где дёшево |
| Гейт качества | конфиг линтера, `tsconfig`, CI-yaml | прочитать |
| Раскладка: карта кода, ловушки среды | слот «Раскладка» раздела «Проект» | слота нет — умолчание скелета (README компонента; карта временно в «Структуре проекта»; README уезжает потребителю — файл карты вне поставки; раздел — только где README рядом с выходами запрещён). `GOTCHAS.md` в репо — чья-то раскладка: разреши по Шагу 1; до того слот «открыто», файлы нетронуты |
| Структура проекта, path-алиасы | файловая система + конфиг бандлера; при раскладке «README компонента» — сами README | glob / list; таблица «компонент → README» сверяется существованием файлов |
| Nature, production statement, послабления | граф, код репо, слово агентов; принятые владельцем ограничения сохраняются | разрешить по порядку Шага 1; смена мандата или цены поломки без основания — принципиальный вопрос |
| Носители реальности (`REALITY.md`) | граф, наблюдаемый кодом путь поставки, слово агентов | проверить достижимость канонического носителя; неизвестное — Ceiling, не выдуманный носитель |
| Проектные решения, why-клаузы, открытые вопросы | граф | `iskron_orient` / `iskron_search` |
| Состояние веток | git + форжа | `git status` / `log`; CLI форжи |
| Ловушки | авторское; дом — по слоту «Раскладка» | только sanity-check — не автовыводить, не переносить между домами |
| Блоки канонов графа | узел-правило с `attrs.prose_for_repos` | `iskron_search(realm=<граф>, q="", attrs_filter="prose_for_repos:**")`; блок кладётся байт-в-байт на место из `attrs.prose_anchor`, ниже — только хвост репо; применимость — по `attrs.scope`, иначе по смыслу, сомнение — порядком Шага 1 |

**Производные факты** (верхние строки, блоки канонов) ре-проецируются каждый прогон; **авторское суждение** (ловушки, why-клаузы, nature, носители) сохраняется, лишь сверяясь на здравость с кодом.

## Контракт выхода — плотность и точность
1. **Императив агенту**: «ориентируйся до кода», не «агенту следует».
2. **Каждая строка меняет то, что агент делает**; иначе удали. Чек-лист, не эссе.
3. **Без проектных обоснований и пересказа графа** — линкуй; растёкшаяся в абзацы секция несёт обоснование — в граф. `(why: …)` — только для инварианта, который агент иначе нарушит.
4. **Таблицы и буллеты**, одна директива на буллет.

**Вне объёма — механика оркестрации** (цепочки гейтов, суб-агентная проверка пушей, model-routing): её дом — скилл оркестрации или граф; срез делегирования проецируется ролевыми файлами (Шаг 6), не прозой.

## Процедура
Идемпотентна: в зрелом репо прогоняй каждую самопроверку и действуй только по провалам; докладывай, что осталось.

## Два такта
**Кто исполняет прогон.** Граф прогона (контур, роль, атрибуты, дело выравнивания) ведёт сам агент — ремесло графа («Сквозные нормы» двери `iskron`). Объёмную проекцию файлов (`AGENTS.md`, ролевые файлы, хуки) можно отдать роли `designer` со своим мостом-спутником; нет субагентов, файла `designer` или спутника — проецируй сам. Прогон обновляет файлы сам, человека не ждёт. Дело выравнивания ведёт позвавший (ведущий): держит граф прогона, человека будит только принципиальным вопросом, не разрешённым графом, кодом и коллегами (Шаг 1, «Человек обычно не в треде»). `designer` работает в дочернем деле из строки запуска, дела выравнивания не ведёт, в граф не пишет, вопросы слотов говорит словом там, принципиальное возвращает итогом; его остаток ведущий переносит в дело выравнивания.

**Ветвь «Первый граф» — `references/first-graph.md`: предложи человеку и, принял — открой и исполни целиком до такта 1**, когда в git-репозитории нет ни одного из трёх признаков выравнивания (обложка, хук старта, штамп — Замер двери `iskron`) или у учётки нуль своих рабочих графов (личный mind не в счёт; приглашённый в общий — тоже). Рабочие графы есть — один вопрос до первого действия: подключить репозиторий к одному из них (список) или завести новый; без ответа граф не заводится. Свой граф есть и репозиторий хоть чем-то выровнен — ветвь не срабатывает. Разговор ведёт **onboarding**; рабочий запрос человека ветви не ждёт.

**Такт 1 «встать» — без вопросов, до минуты, в любом репозитории.** Первый контакт, слово «iskronify» или найденное отставание конфига. Быстро разрешаемое — в файл, остальное — «открыто» и вопросом в дело; затем такт 2 без ожидания человека.
1. **Адреса.** Граф и роль — из слова человека, строки окна с адресом места или `AGENTS.md`. Граф не назван — `iskron_realm(action="list")`: нуль рабочих — ветвь «Первый граф»; иначе сверь с записанным о репо и спроси коллег; выбор или создание графа не разрешились — принципиальный вопрос о границе проекта (Шаг 1), имя не угадывай; создание — `iskron_realm(action="create")` по принятому выбору. Роль владельца — «Старт», п. 1 двери **iskron**; привязку проверь по шагу «Сойдись или эскалируй» скилла **standing**. Своя роль агента в `kartas` — сбитая привязка: вопрос в дело выравнивания. `kartas` видит только привязанные: прежде svatantra (Шаг 2) ищи `iskron_search(q="", node_type="karta", manifested_as="svatantra")` и прочти подходящие; непривязанную связывай с `user="me"` только по подтверждению человека; не выбирается — один вопрос человеку сессии, без него — в дело выравнивания.
2. **Контур репозитория.** `origin` → `хост/организация/репо` → `iskron_search(q="", node_type="holon", attrs_filter="repository:<значение>")`. Нет — `iskron_add_holon` (`contains` от корня графа или контура репозиториев) с `attrs.repository` и `open_room` дела выравнивания. Один репозиторий — один контур; на повторном прогоне сверь снова.
3. **Роль на репо.** `iskron_search(q="", node_type="karta", steward_of=<контур>)`; нет — `iskron_add_karta` (`manifested_as=adhikarin`, мотивация — дистиллят того, что репо поставляет, `attrs.skills` — CSV ключевых скиллов роли до 64 знаков: по нему карту агента отличают от непривязанной человеческой) и `steward` к контуру. Одна роль на репозиторий; у найденной без `attrs.skills` — допиши.
4. **Обложка и файлы — шагом моста**, первым ходом такта и снова по мере адресов п. 1–3, 5: `node ~/.iskron-bridge/iskron-bridge.mjs prepare --json --lang <ru|en> [--graph rN --holon N --agent-role N --case N] </dev/null` без модели пишет блок `iskron:` в `AGENTS.md`, заготовки `REALITY.md` и указателя `CLAUDE.md`, memory-guard рядом с чужими; стоящее не перезаписывает; контур и роль без флага выводит по `origin` из графа, когда у моста есть ключ (`derived`). Твоё — `left` (код 3); код 1 — отказ, ничего не записано; ответ не JSON (мост старше) — обложка по скелету и Шагу 7, guard по Шагу 4. Тело — на языке репозитория (скелет русский, английский переводишь сам). Слоты «Проекта» — из графа, кода и записанного ответа (и агента соседнего контура) значением; неразрешённое — «открыто», вопрос — в деле; отсутствие человека дыркой слот не делает. `REALITY.md` — таблица разрешённых носителей; пока их нет — заготовка моста (без него — заголовок скелета и строка «Носители ещё не установлены; дело выравнивания №N. До их установления поведенческие заявки не принимаются.»); до носителей поведенческих закрытий нет.
5. **Дело выравнивания** на контуре п. 2: открытое есть (`iskron_case(action="at", node=<контур>)`) — веди его; нет — `open_room` у записи контура или `iskron_update`, зачин до 64 знаков: «Выравнивание <репо> под контракт N». Прежде первой записи — место под ролью на репо: держит мост — `iskron_channel(action="register", realm, karta=<роль на репо>, name=<его имя>)`, нет — `iskron_stand(realm, karta=<роль на репо>)`; затем `join`. Проекцию отдаёшь `designer` — дочернее дело (`open_room` с `parent_room`), его №N — в строку запуска; он встаёт спутником (`iskron_stand` с `satellite_of` твоего места — `references/delegation-1.md`, `delegation-2.md`, обе по порядку до хода), `register` не зовёт, вопросы слотов — словом в дочернем деле, уходит `leave`; остаток переносишь в дело выравнивания. Строка «слот: <имя>» (`partial` — на ком, чего ждёт) — по желанию, только у неразрешённого; разрешённый — значением в «Проект»; вопрос — карточкой `ask`. Первое слово: «есть вопросы по проекту, за который я отвечаю, — ответьте или скажите, кто может ответить». **Анкету, план и ход выравнивания в граф не пиши**: такт пишет туда только структуру (контур с `repository`, роль) и ловушки правилами (Шаг 7).
6. **Сторож памяти** — хук ставит п. 4; стаба `MEMORY.md` нет и не обещается — guard его не пропустил бы. Непустая директория памяти — эвакуация по Шагу 5 в такте 2; до неё строка скелета о заморозке ссылается на строку дела выравнивания, а не утверждает завершения.
Отчёт — слово в деле выравнивания: что разрешено, что открыто; такт по слову другого дела — поручение: слово-отчёт там, называющее дело выравнивания, с исходом по наблюдённому; затем эстафета Шага 7.

**Такт 2 «доделать» — сам, не блокируя.** Продолжи после такта 1; каждый следующий старт читает сводку дела по шагу «Выравнивание» двери `iskron`; писать — своим местом и войдя, как в п. 5. Слоты разрешай по Шагу 1 и вписывай в «Проект» без переспроса; строка «слот: …», если была, снимается тем же ходом (`ok`). Ответ агента подписывается его именем, не именем владельца, и подтверждения человеком не требует. Полная дуга (Шаги 1, 3, 4, 6) идёт без человека; неразрешённый слот держит только зависимую часть. Все слоты разрешены — предложи закрыть (`propose_close`, свидетельство — слоты «Проекта» и кто ответил), если ведущий ты; иначе слово ведущему.

### Шаг 1 — Разреши слоты (такт 2)
Не выбирай дефолты молча. Прочти граф, код репо и старый конфиг; чего они не разрешили — спроси у агентов соседних контуров в деле выравнивания. Запиши в «Проект»: **Nature** (не `production` — что ослаблено и почему), «Стек», **гейт** (Шаг 3), политику ревью пачки (слот «Холодного ревью» скелета — где нет применимого блока канона); граф — в обложку. Принятые авторские ограничения сохраняй. Прежняя анкета (узел `#N` вместо дела) — `references/migrations.md`, с 37.

Также согласуй:
- **Кто владеет направлением** — svatantra-роль владельца (主), создаётся в Шаге 2; принципиальные вопросы слотов — ей через ведущего в деле выравнивания, не анкетой в графе.
- **Общее изменяемое состояние build/test** (база, фиксированный порт, dev-сервер, глобальный кэш, облачная песочница): есть — зафиксируй ловушкой изоляцию по полосам (агенты гоняют ветки конкурентно в отдельных worktree).
- **Реальность** → `REALITY.md` по `references/reality-template.md`, из графа, кода и ответов коллег. Дожимай до *канонического носителя* каждого класса: собранный артефакт, не исходники; живой эндпоинт, не хендлер; чистая установка, не тёплый кэш; подтверждено правомочным держателем или предложено — помечай. Недостижимое — в *Ceiling* с причиной; вывод о носителе не равен наблюдению поведения; датированные замеры — узлами в граф; в `AGENTS.md` — раздел «Reality» указателем. Как таблица работает при закрытиях — **reality-audit**.
- **Личной памяти в AGENTS.md нет** — ни слота, ни правила: где живёт личное и когда читается, решают дверь `iskron` и **minding**; обеспечь её единым входом **minding** — без хэндла и сохранённого адреса, недоступность не отсутствие; сообщение memory-guard несёт личную ветку через minding. Проектные инструкции — коммитящиеся файлы дерева и граф проекта, никогда глобальный файл инструкций, память харнеса, пользовательские хуки: о глобальном файле не спрашивай и не заводи. Личное предпочтение, мнение или переносимый способ → личный mind, даже на тему разработки; правило самого проекта → AGENTS.md или граф проекта по полномочию; применение найденного — по **minding**, не копированием в проект.
- **Фидбэк-рефлексия** (опыт *о методе* — в граф работы, случаем, адресом стюарду инструмента): умолчание шаблона — **да**, источник `выведено: умолчание шаблона`, без вопроса человеку; регион feedback-reflection скелета остаётся, хук мержа несёт такт. **Нет** — только по записанному слову (`согласовано: кто`): удали регион целиком.
- **Сосуществование с workflow-набором** — только когда найден коэрсивный набор (его скиллы в списке или его директория в кэше плагинов; сегодня superpowers); найденный набор — не согласие: (1) **полный interop** (рекомендуется) — подсекция из `references/superpowers-interop.md` + spec-write-хук; (2) **только проза**; (3) **пропустить** — назови риск: дизайн-сессии набора не осядут в граф.

**Человек обычно не в треде** (присутствие его — не условие прогона). «Согласуй», «спроси», «подтверди» для слота везде означают этот порядок:
1. **Сделай всё, что от ответа не зависит**: аудит, выводимое, гейт, хуки.
2. **Сперва граф и код, затем братья — агенты соседних контуров.** Неразрешённое — в одном деле выравнивания: вопрос — `ask` («Ожидание от делателя» справки двери **iskron** `cases.md`), строка «слот» — на отдельном от карточки ключе, не узел и не дело на слот; знающих коллег зови `invite`, поручение — `say` с `to` на место; их `answer` прими `ack`, ответ — в слот с их именем. Факт из графа или кода — «выведено», без строки дела; неочевидное основание — словом в деле.
3. **Только принципиальный остаток — человеку через ведущего дела.** Смена мандата, принятого ограничения, цены поломки, выбор или создание графа (граница проекта, такт 1, п. 1) либо неразрешимый конфликт источников — принципиальное; отсутствие ответа или сведений само по себе — нет. Спросить, кроме человека, некого (новый граф, соседей нет) — невыводимое спрашивай у него карточкой `ask` в деле и словом на его место; не угадывай. Прежде эскалации назови проверенное в графе и коде, кого спросил и почему нужно решение владельца. Ведущий говорит вопрос словом в деле и будит человека `invite` его места, нет места — его роли с контуром (`karta=<роль владельца>`, `holon=<контур репо>`); нет и её — вопрос остаётся в деле, работа продолжается.
4. **Дырка, не догадка** (п. 4 такта 1), вопрос — в деле; непринципиальное неизвестное ждёт знающего агента или ведущего, старт двери найдёт ответ и впишет без переспроса.
Отвеченное пишется сразу; один слот не держит остальные.

### Шаг 2 — Первое заведение графа
- Графа нет — ветвь «Первый граф» (такт 1).
- Фокус-контур (граница проекта, `contains` от корня) — спроектируй `design`, создай `iskron_add_holon`; seq — в `holon` обложки. **Контур несёт атрибут `repository`** — `хост/организация/репо` из `git remote get-url origin`, без протокола и `.git` (например `github.com/iskron-ai/skills`); его сверяет с origin старт двери и каждый прогон. Один контур — один репозиторий. Стоит другой — не перезаписывай: та же `организация/репо` на другом хосте — алиас (атрибут несёт каноническое имя; предложи человеку перевести origin; ищи подстрокой `attrs_filter="repository:*организация/репо*"`), иная организация или репо — форк или зеркало, решает человек (Шаг 1). «Not found» форжи по каноническому имени — не отсутствие: приватный репозиторий так отвечает всякому без учётных данных; одна ли это форжа — проверяй без них или по публичному репо на ней.
- **Делатель — стюард.** Роль агента (такт 1, п. 3; мотивация — дистиллят Production statement) проведи `steward` к фокус-контуру — эта роль, не старшая, иначе ориентация на контур не найдёт делателя. Роль владельца не нашлась (такт 1, п. 1) — создай svatantra; привязка — по тому же шагу **standing**. Seq роли агента — в `agent_role` обложки; от неё проведи `group` к роли владельца, если стрелки ещё нет.
- **Холон + стюард — корень поля интеграции**; обход держит `integrity`. Об «общих поверхностях» не спрашивай и списка в AGENTS.md не пиши; не найденная зависимость — дефект модели (`design`, `weaving`).
