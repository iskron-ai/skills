# Шаг 1 · Замер, до разбора запроса — дверь iskron

Шаг двери **iskron**, вынесенный сюда дословно, чтобы дверь доходила до модели целиком в клиентах, режущих вывод тула (OpenCode: 51 200 байт). Исполняется при каждом вызове двери с запросом, до его разбора.

Два чтения графа плюс бесплатное локальное; замер вправе перебить любой маршрут.

1. **`iskron_orient(realm=..., focus=фокус-контур)`** из `AGENTS.md`: живые превращения и когда двигались, `НАТЯЖЕНИЯ` по классам, активные вопрошания, открытые дела контура (войти — ход из подсказки под ними).
2. **`iskron_orient(realm=..., focus=роль агента)`**, если она названа: число зовущих в заголовке очереди, риски, строка `КАНАЛ`. Список целиком — вызовом из хвоста выдачи, постранично; отвеченное от зовущего отличает печатная помета заката, не волевой модус. Очередь — фон: прочти зовущее, которого касается работа.

Бесплатно: `git status --short`, ветка, `AGENTS.md` и число в его штампе. Живость тулов отдельно не проверяй. Ходы таблицы — починка, не замер.

Первое совпавшее перебивает запрос — скажи человеку, почему:

| Замер | Ход |
|---|---|
| тулов нет или молчат | **establish-mcp**, затем исходный запрос |
| проектного графа нет: `iskron_realm(action="list")` пуст, несёт чужие графы или из своих (handle человека и его организации — `iskron_me(action="whoami")`) только `@handle/mind` | нет `@handle/mind` — заведи без вопросов граф, роль человека и карту ассистента по **minding** (handle пуст — скажи и не заводи). Работа в mind не пишется. Нуль рабочих графов — **onboarding**: в репозитории — ветвь «Первый граф» **iskronify** (найденные графы, куда человека позвали, и origin — человеку, вопрос об области, новый граф только при отсутствии подходящего и с названным именем), вне репозитория — цикл onboarding; граф без вопроса не создаётся. Графы, куда человека не звали, кандидатами не предлагай. Запрос — до первой записи по **writing**; места в новом графе ещё нет — ролей нет; первые записи (роль человека, контур, роль агента) ложатся без него, место — `iskron_stand`, как только роль агента легла |
| `AGENTS.md` нет или штамп ниже контракта `iskronify` | прогони **iskronify** по правилу шага «Выравнивание» |
| ход будет писать в граф или говорить в деле | записи подписывает место этой сессии; знак — стояние названо привязанным к этой сессии. Место держит среда и сказала это словом (промпт хода называет твоё место, как у встроенного агента, или его назвал ответ `iskron_stand`) — место уже твоё: для записи нового не занимай. Корень выровненного проекта в OpenCode садится сам до первого запроса и говорит в промпте строкой, каким местом стоит сессия или почему не посажена. Эта строка и говорит, заменит ли вахта или своё имя место одним `iskron_stand` без `take` (место предварительное — так подтвердил мост) или нужен `take` (место прежнее своё или не сличено с обложкой); не сказала — `take` нужен. Не посажена — `iskron_stand`, как при пустом месте; после стопа владельца строки посадки нет — место даёт только явный `iskron_stand` по его слову. `iskron_channel(action="register", realm=..., karta=<роль>, name=<имя места>)` только называет место, которое эта сессия или её мост уже держит, — без такого места сервер его отказывает, назваться им нельзя. Своего места нет → `iskron_stand` одним вызовом (**standing**). Адрес согласования с человеком — seq роли владельца из `AGENTS.md`; `me` при нескольких ролях человека отказывает перечислением — бери seq оттуда |
| запись вернулась безавторной **повторно**, хотя ты называешься | **establish-mcp** — привязку держит только мост поставки |
| граф назван голым slug | разреши через `iskron_realm(action="list")` до чтения |

Замер не перебил — иди в запрос. Ничего из замера не пропадает: его числа идут в ответ человеку.
