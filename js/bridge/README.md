# js/bridge — ядро MCP-моста

Вход процесса — `main.ts`, цикл — `engine.ts` и `deliver.ts`; демон машины и тонкий клиент — `daemon.ts` и `thin.ts`.

- `spawned-for.ts` — основание запуска по #9959: явная пара либо окружение области сессии, закреплённое за одним графом и ролью; на MCP-проводе поле получает только register. `claimdelivery.ts` проверяет вход и ответ register до привязки; `claimseat.ts` держит независимую идентичность своего connect/held для выбора квитанции. `call.ts` и `standing.ts` используют ту же проверку внутренних регистраций; `standanswer.ts` — итог stand с выбранной seats-квитанцией и признаком свежести этой попытки. `standcwd.ts` — проверка каталога для stand и его занятости. `standundo.ts` снимает только своё новое место после отказа регистрации. Нижние пробы — `stand.test.mjs`, `daemon.test.mjs`; реальную Orca не удостоверяют.

- `stand.ts` — занятие места: доска, connect/register, hello, стук, занятость; схема тула — `standtool.ts`; отказы с рабочим ходом, снятие прежнего места при take и ожидание 429 — `standmoves.ts`; повтор register при 429 rate_limited источника (второй пояс предохранителя #10801: ждёт только основное место хода, возвращающего место (вид хода `registerMove("returns")`: перепривязка, возврат с диска, `iskron_stand`, обновление навыков; снимок расхода `usage.ts` — `"once"`, один register без ожидания) — ровно Retry-After из отказа, не больше трёх попыток, в сроке хода: начало хода + 60 с (`../shared/ratelimit.ts`), ожидание позже срока не начинается — место отдаёт отказ; место рядом не ждёт — один register, его вернёт следующий ход; source_paused и прочие — не повторять; ход регистрации `RegisterMove` (`ratelimit.ts`) несёт часы стопа с начала хода, начало и срок: ни одного register после стопа, а перед каждым register — сверка id места (граф, роль, имя — из держания или hello) с журналом снятых мест (`endedseats.ts`: каждое `standing_ended` и приказ останова, и с id, которого мост ещё не держит), снятое с начала хода не регистрируется, прочие идут дальше; register мост шлёт только через ворота `registergate.ts` (`registerByCall`, `registerRaw`) — они спрашивают ход перед каждой отправкой, включая повтор после 429 и после 409 «открыто одновременно» (этот повтор живёт только в воротах, `callTool` шлёт один раз); путь мимо ворот — литерал register или повтор 409 вне ворот — роняет проба `register-gate.test.mjs`; стоп на перепривязке держится на границе вызова — ожидавший вызов не уходит, ответ — слово стопа) — `ratelimit.ts`, применён на возврате места с диска (`resume.ts`), местах рядом (`besideback.ts`) и перепривязке места, включая спутника (`standing.ts`); страж стопа на выходе вызова (стоп сессии с начала вызова — места, занятые или привязанные вызовом, снимаются, привязки нет, ответ — слово стопа) и откат перехода при отказе register после connect — `standundo.ts`; полный вызов своего прежнего места — `standagain.ts`; хвост ответа — строка отставания поставки и правила человека из mind (`standtail.ts`, `../shared/mindslice.ts`; не у предварительной посадки харнесса — её ответ модель не читает; #9817).
- `provisional.ts` — предварительное место автопосадки: служебный id и флаг вместе, имя `.root-<12 hex>` (48 случайных бит, остаётся 30 из 48 знаков для основы) против гонки экземпляров; признак живёт в записи держания и сохраняется при возврате и переписывании той же записи той же сессии; явный stand той же сессии в том же графе заменяет только это место без take и снимает признак (#7972, #5164); снимает его и первая успешная запись сессии через это место — пишущий ход дела, `add_*`, `update`, `arrow`, `batch`, `delete_node`, кроме служебных вызовов плагина: дальше явный stand с другим именем отказывает по правилу одного места (#8033). `replynotes.ts` — что ответ тула отмечает о месте: вход спутника в дело и эту первую запись. `seatproof.ts` — этот обслуживающий мост подтверждает семантику полем provisional в held, stand и resume/check; плагин не выводит поддержку старого демона из дисковой записи.
- `board.ts`, `fields.ts`, `standing.ts` — чтение доски и ответов канала, привязка места.
- `journal-fold.ts` — свёртка журналов машины (`standings.log`, `grant.log` через `appendJournal` в `store.ts`, `daemon.log` в `daemon.ts`): строка той же формы (UUID и случайный хвост `.root-<12 hex>` замаскированы) в пределах минуты не пишется, а считается; счёт — своей строкой после минуты. Первая строка формы — целиком, с id; счёт, открытый к выходу процесса, теряется (#10782). Проба — `../tests/journal-fold.test.mjs`.
- `hold*.ts`, `resume*.ts`, `separate*.ts` — держание и возврат места, выбор места рядом. Граф места — `@owner/slug` до любого вызова сервера (`seatRealm` в `hearing.ts`, `canonicalRealm` в `realms.ts`; `mind` — как есть); запись прежней сборки с rN или голым слагом `holdcanon.ts` переводит на ключ `@owner/slug` при первом чтении живой (по возрасту, как `readHoldRecord`) записи, прежние ключи остаются в записи (`formerKey`, строка или список): по ним место находит возврат, дверь слушает и на их сокетах, место рядом называется и ими (#8677). Отказ или молчание списка графов негативом не держится — спросится при следующем stand или возврате. Прямые вызовы api вне MCP несут граф `@owner/slug` или числом (`apiRealm` в `realms.ts`; список графов api — `realmindex.ts`). Плагин спрашивает, что за граф rN, методом `realm` (`realmask.ts`, #8191): известное таблицей моста — без сети, иначе один список графов; неразрешённое возвращается как дано.
- `satellite.ts` — место субагента на прогон; `session.ts` — конец сессии; `runend.ts` — конец места с концом агента (сразу по `end`, по окну смерти в демоне — кроме места, которое после конца прогона держал другой мост, его запись держания новее; connect, отвеченный после конца прогона, сокета не открывает и уходит с окном, у спутника — сразу), `deadstop.ts` — снятие канала умершего токеном его мёртвого сокета, `stopseat.ts` — то же снятие для отложенного конца спутника: спутник при каждом держании кладёт адрес своего сокета рядом с грантом (`<ключ>.stop`, 0600) с воплощением держания — случайным id, выданным его первым держанием ключа, сохранённым пере-взводом и возвратом по ключу и названным событием `held` (`stoprecord.ts`); мост запустившего по `iskron/stopseat {key, incarnation}` снимает им только запись того же воплощения (stopped — только если `ended[]` ответа называет id места из записи (запись несёт его с connect или hello) / moved — запись другого воплощения, токен не текущий или 200, чей `ended[]` места не называет: место держит другой, не тронуто, запись чужого воплощения не удаляется / нет записи или воплощения — ничего); кончившийся сам спутник удаляет свою запись, `ownwhoami.ts` — учётка, за которую говорит токен моста в этот миг (#9817): `whoami` хранится по отпечатку предъявляемого токена (`credentialKey` — сервер, каталог гранта, отпечаток; тем же ключом — срез правил демона, `standtail.ts`), новый вход в хранилище — новый отпечаток и новый `whoami`; плагин спрашивает его методом `iskron/whoami` на каждом чтении среза — ответ `{handle, server}`, сервер — тот, с которым говорит сам мост (`CFG.serverUrl`), без чтения доски и без revoke по имени, исход по месту из `ended[]`, `endword.ts` — то же снятие токеном сразу по слову харнеса (`end`), revoke по имени — только на api без ручки (#9232), `deadseat.ts` — сверка доской для api без этой ручки и запись держания, уходящая только с подтверждённым снятием, `away.ts` — метка объявленной отлучки, при которой место ждёт свою сессию.
- `sessionclose.ts` — закрытие своей сессии MCP: DELETE с её Mcp-Session-Id на выходе сессии моста и при замене сессии, которую сервер ещё держит (`letGo` в `transport.ts`; после 404 — не закрывается), одна попытка с потолком, id и исход — в журнал и `grant.log`; id, выданный сервером, — туда же строкой открытия (#9174); сессию, отложенную окном смерти, демон закрывает и тогда, когда сам уходит внутри окна — по SIGTERM или передачей преемнику (#9306). Окно «сервер недоступен» держит и закрытия (#11375): пока оно стоит или истекло и ждёт пробника — DELETE не уходит, а хранится в памяти процесса, по одному на id сессии, и пробником не бывает; ответ на стук без окна — хранимые уходят; каждое закрытие идёт воротами возврата родом «открытие» (не больше двух в полёте), 404 — сделано, без повтора; процесс, ушедший с хранимыми, пишет их «не отправлено». Отказанный окном initialize сессию не отпускает (`admit` в `post()` — до ветки initialize). Пробы — `../tests/session-close.test.mjs`, `../tests/sessionclose-window.test.mjs`.
- `snapshot.ts` — снимок своей области сессии для `status`; `daemon.ts` собирает области в один ответ без открытия сессии.
- `downwindow.ts` — окно «сервер недоступен» на всю машину (граф @nks/nks-dev, узлы #7700, #8144): первый стук семейства сбоев (соединение так и не установилось — отказ порта, неизвестный хост, DNS; 502/503/504 передней линии; соединение, закрытое под запросом, и таймаут окно не открывают — их обслуживает собственный повтор вызова) открывает одно окно на сервер — запись `<хранилище>.json.down` рядом с грантом, её видит каждый мост каталога гранта; пока окно стоит, стук не уходит (`transport.ts` `post()` — ворота каждого JSON-RPC-стука; короткая MCP-сессия оркестратора — `../shared/mcpsession.ts` — через тот же допуск, `windowfetch.ts`: её initialize, вызовы и закрытие, #11375), вызов отвечает сразу «не отправлено — мост сам стучит дальше»; первый стук по истечении окна — единственный на машину пробник (замок `<хранилище>.json.down.probe`, чужой пробник в полёте — отказ сразу); упавший пробник шагает лесенкой полного джиттера (первые ступени — паузы собственного повтора вызова, потолок 60 с) либо называет более долгий Retry-After сервера (заголовок или `errors[0].data.retry_after_secs`); любой ответ меньше 500 окно закрывает. Между вызовами ничего не стоит: машина, которая никого не зовёт, никого не стучит. `NET_BACKOFF_MS` определён здесь один раз; слово отказа называет правду: не отправлено, сервер недоступен, позови снова примерно через N с — сам мост вызов не повторяет. Пробы — `../tests/down-window.test.mjs`, `../tests/orchestra-window.test.mjs`. Предел: `prepare` (`../cli/preparegraph.ts`) свою сессию шлёт мимо окна — он не часть демона.
- `returngate.ts` — ворота возврата машины (граф @nks/nks-dev, узел #11375), одни на сервер в процессе демона: сессия, вернувшаяся первой (повторное открытие MCP после 404 — `transport.ts` `reinitialize`; перерегистрация мест после потери сессии, возврата с диска после перезагрузки плагина или смены демона, обновления навыков после самообновления — ход `registerMove(…, regate)` в `registergate.ts`, каждая его отправка, повтор после 409 «открыто одновременно» тоже, — через ворота и в счёте полёта; рукопожатие харнесса, которое тонкий мост повторяет преемнику после смены демона или самообновления, — id с `REPLAY_ID_PREFIX` из `../shared/seam.ts`, `deliver.ts`), — проба машины; остальные ждут её исхода; проба ответила — ждущие возвращаются не больше двух разом, каждая после случайной задержки в окне `шаг × ждущих` (шаг 1 с, потолок 60 с) — и когда ждущий один: два возврата разом — тоже разброс (`ISKRON_BRIDGE_RETURN_STEP_MS`/`_CAP_MS` и закреплённая доля жребия `ISKRON_BRIDGE_RETURN_DRAW` — для проб); проба встретила 502/503/504 или не соединилась — ждущие не стучат и отвечают словом окна (`downwindow.ts`), следующая проба — по лестнице окна. Возврат начинает только вызов: молчащая сессия не возвращается. Предел: мост вне демона (полный мост, `ISKRON_BRIDGE_DAEMON=0`) — сам себе машина, ворота держат только его; первое занятие места (stand) через ворота не идёт. Всякое иное рукопожатие, которое открывает демон (новые тонкие мосты после перезагрузки плагина, сессия оркестратора), — через те же ворота родом «открытие»: без толкотни сразу (нет пробы, никто не ждёт, меньше двух в полёте), всего не больше двух в полёте с возвратами, при больше чем двух ждущих — случайная задержка в окне; проба 404 и окно «сервер лёг» держат и его. Пробы — `../tests/return-gate.test.mjs`, `../tests/return-gate-disk.test.mjs` (с разу смены демона), `../tests/skillrefresh-gate.test.mjs`.
- `verdict.ts` — синтетический отказ с вердиктом «могло ли примениться» (`syntheticError`): причина, вердикт по исходу и виду удержания (`wait`, `knock`, `dead`, `human`, `down`) и хвост; вид `down` никогда не говорит «retry freely» — вызов не поставлен в очередь, перезапускать ничего не надо, мост стучит сам. Вынесен из `deliver.ts` (лимит строк), вызывают `deliver.ts` и `thin.ts`.
- `refusal.ts` — отказ api как данные; `ruleOf` — `errors[0].rule` тела ProblemDetail, общий для `deadstop.ts` и `statuspost.ts`. `statuspost.ts`: 404 с правилом `no_live_standing` (и причина кадра `status_rejected` `no_live_standing`/`unknown_standing`; граф @nks/nks-dev, узлы #4235, #11376) — канал жив, живого места на нём нет: исход несёт `rule` и не несёт `code`, потому никто не читает его как повернутый адрес; 404 без правила — по-прежнему повернутый адрес. `status.ts` (`liveAgain`): занятость не делает ни connect, ни register (решение владельца на #4235) — мост перечитывает запись держания: другой адрес места — строка туда один раз; тот же — «строка занятости НЕ поставлена: места на канале нет — встань снова (iskron_stand)». Пустая строка не перерешается.
- `skillwatch.ts`, `skillrefresh.ts` — последнее принятое объявление и единое решение об освежении плоского набора; сериализованная публикация в фоне после ответа на вызов тула, независимо от расхода. Загруженный каталог версии плагина не заменяется соседним.
- `skillcatchup.ts` — догон набора на stand/возврате (#10122): только major/minor и собственный глобальный flat/OpenCode, включая активный XDG-lock внутри HOME. `skillcatchup-manifest.ts` получает полный git-tree SHA текущего выпуска; `skillcatchup-guard.ts` проверяет все имена, источник, реальные пути, симлинки/хардлинки и полный перечень blob-байтов, затем перечитывает ref/hash/version/stamp. `skillcatchup-run.ts` запускает существующий CLI skills 1.7.6 явным списком имён и одним agent, с пределом 20 с и гашением POSIX-группы при сроке/стопе; `skillcatchup-update.ts` держит единственного писателя и ставит обычное освежение метаданных в очередь. Автодогон не поддержан на Windows, для проектного корня, pi и плагинов Claude Code/Codex: только первое слово с командой. Снятое не удаляется. Слова — `../delivery/words/skillcatchup.ts`; нижние пробы — `../tests/skillcatchup*.test.mjs`, API и updater в них подставные.
  `pi-source.ts` — только распознавание источника предупреждения pi: клиент pi, реальный путь стандартной git-установки и её точный origin. Регистрацию пакета у pi не удостоверяет; иных каталогов/форм origin не угадывает. Не расширяет владение flat и допуск автозаписи; неизвестное ведёт к doctor (#10316).
  Блокировка `.agents/.skill-catchup.lock` после запуска add снимается только полным post-read; SIGKILL или любой неподтверждённый исход её сохраняет. Она проверяется до сравнения версий: свежий bridge.VERSION не доказывает полноту набора. Повтор не является восстановлением; сначала оператор подтверждает остановку группы updater и происхождение блокировки. Отказы второго живого писателя, неизвестной блокировки и свежей VERSION при старом SKILL — `../tests/skillcatchup-gate.test.mjs`.
- `status*.ts`, `leave.ts` — занятость, отпускание и возвращение.
- `context-gate.ts` — ограда записи после наблюдённого обвала заполненности OpenCode (#10121); чтение — по `../shared/toolreads.ts`, отдельно от безопасности повтора. Загрузки двери и всего известного списка роли связаны с местом и поколением; неизвестный список требует явного `context_restored` у stand, локально без register. `context-state.ts`/`context-store.ts` — пометка по серверу и месту в своём auth-dir (`*.context-gate.json`, 0600, атомарная запись через `writeOwned`): перезапуск сбрасывает baseline и загрузки, но не известный pending; ошибки чтения/сохранения не разрешают запись. Пробы — `context-gate.test.mjs`, `context-store.test.mjs`, `opencode-context-gate.test.mjs`; порядок живого usage → tool и прокси ими не удостоверены.
  Справка `action="?"` разрешается по объявленному `action` уже полученной схемы: `toolsync.ts` держит её в области сессии; `initialize.ts` берёт однократный снимок серверного кэша при первом initialize и согласует форму счётов (дополнительные мосты OpenCode используют готовую витрину без tools/list); `moment.ts` обновляет по живому/кэшированному списку и перечитыванию после переоткрытия. Уведомление смены поверхности убирает старое разрешение; новый список заменяет его, следующие страницы дополняют. Пробы — `context-schema.test.mjs` и `context gate: help schemas` в `daemon.test.mjs` (две сессии одного настоящего демона).
- `stophold.ts` — остановка снятием места владельцем (чужой 4001, кадр standing_ended): место отпущено и забыто, ни один автоматический путь его не занимает; имя свободно. Кадр standing_ended и приказ останова останавливают лишь место, чей id в них; мост, не знающий id своего места, — лишь адресованные этим id (`to_standing_id`); иначе строка в журнале или отказ приказу (дело №1046).
- `lifeseat.ts` — побудка о живости, адресованная лишь `to_standing_id`, получает имя своего места этого моста (`to_standing`), чтобы текст называл предупреждённое место.
