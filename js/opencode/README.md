# js/opencode — плагин iskron для OpenCode 2: тулы через мост, канал, команды

Один плагин, три половины; у каждой корневой сессии свой мост, а значит своё стояние (граф @nks/nks-dev, узел #4266). Выход — `skills/establish-mcp/scripts/opencode-plugin.js`, ставится копией в `~/.config/opencode/plugins/iskron.js`.

`bridge-io.ts` ищет читаемый файл моста: `ISKRON_BRIDGE_PATH` → `iskron.mjs` рядом с загруженным плагином → домашняя копия (#4901). Каталоги пропускаются. Проба приоритетов и отсутствия файлов — `opencode-package-bridge.test.mjs` против собранного плагина; отрицательный контроль — `ISKRON_OPENCODE_PLUGIN` прежнего выпуска.

Служебное слово запуска, ритуалов, посадки и приглашения, шапка команды скилла и попутные счёты — в `system` первого основного `context` своей сессии, не в сохранённом вводе человека (#9341). `prompt` по-прежнему ждёт ограниченную посадку/вход, но `p.prompt.text` не меняет; аргументы команды сохраняет без `trim`. `compaction` не забирает ожидающее слово и счёты; повтор `context` не повторяет их. Удаление, стоп/конец и выгрузка подавляют неотданное слово; перемещение очищает очередь старого экземпляра. Пробы: `opencode-hook-context.test.mjs`, проверки `prompt`/`system` в `opencode-kit.mjs` и `rootseat-kit.mjs`; живой прибор `scripts/rootseat-run-opencode.mjs` сверяет первый HTTP и сохранённую историю.

Приготовленное слово привязано к `prompt.messageID`: отдаётся лишь когда соответствующий `user.id` есть в `context.messages`, не более раннему запросу той же сессии. После `compaction` допускается `keepID` нового checkpoint харнесса для снимка ожидающих id; обычный prompt с таким metadata не получает допуск. Команда несёт непрозрачный одноразовый ключ в `metadata`, а не сравнивает аргументы с текстом другого ввода. Живые приборы: `scripts/hook-context-surface.mjs --delivery` — одинаковые ordinary/command/ordinary без изменения истории; `scripts/compaction-run-opencode.mjs <свежий-каталог> --pending-command --keep` — очередь через штатное автосжатие и одноразовая шапка только в продолженном system (#9867). Поставщик не меняет ввод; само сжатие харнесса заменяет его представление checkpoint с `recent`.

- `plugin.ts` — дверь: половины, поток событий сервиса, хуки сессии.
- `questions.ts` — запрет `question`: удаление через `tool.transform` и отказ `permission.evaluate`; область `QUESTION_SCOPE` из поставки (`repo` — собственная обложка, перечитывается на каждом вызове; `all` — безусловно), `ask` дела не меняет. Пробы — `opencode-questions.test.mjs`, `blocking-question.test.mjs` (#10397).
- `spawn-admission.ts` — marker первой строки допускается только при доказанно пустом `session.context` до admission; недоступная/непонятная история отказывает, обычный ввод без marker её не читает. `spawned-for.ts` — пара для stand до автопосадки, общая попытка одинаковых concurrent admission, terminal conflict разных пар, проверка seats-квитанции и запрет работы проигравшему. Ввод человека не меняется; cleanup через `rootseat-tools.ts` требует свежести места, подтверждённой этим stand, и не отзывает возвращённое место. Окружение процесса сервера мостам не наследуется: для OpenCode используется явное поле либо строка prompt. Нижние пробы — `spawned_for` в `rootseat.test.mjs`.
- `hook-context.ts` — одноразовые служебные слова по id допущенного ввода; очередь, поколения переноса и подавление после удаления/стопа.
- `context-gate.ts` — наблюдение завершённой загрузки skill своей сессии, begin/end через внутренний usage; system-вложение не считается загрузкой (#10121). `usage.ts` передаёт каждый снимок заполненности без склейки, до следующей пишущей операции; более поздний отчёт харнесса не отменяет уже отправленную запись. `context_restored:true` не проходит взятие места и обогащение cwd/model/satellite_of; false и отсутствие флага сохраняют обычный stand. Ограда и список скиллов роли — в `../bridge/context-gate.ts`, слова — `../delivery/context-gate.ts`. Пробы — `opencode-context-gate.test.mjs`, `opencode-context-stand.test.mjs` с подставным контекстом и настоящими dev-мостом/плагином, не живой порядок событий харнесса.
  `usage.ts` отправляет наблюдаемую модель как `provider/id`; неизвестный provider или id не наследуется от прошлого шага. Заполненность старого шага не становится baseline новой модели. Проба смены provider при одинаковых id/window — `opencode-context-model.test.mjs` против собранных плагина и моста.
- `quiet-calls.ts` — лежалая пачка без зовов, которые ничего не просят: отзыв, отозванное приглашение и, для сессии, поднятой по `spawned_for`, любое приглашение; метки доставки остаются, текст собирается заново. Пробы — `opencode-quiet-calls.test.mjs` и стейл-проба в `opencode.test.mjs`.
- `piles.ts` — выбор пути кадра и чтение тихой пачки: адресация дела и мягкий graph inbox; последний ждёт служебного context следующего хода без самостоятельного промпта. Свёртка — общая `../shared/graph-inbox.ts` через `splitBatch`.
- `turnend.ts` — конец хода на вахте (`../shared/turnend.ts`, #9342, #9345): кадр, вложенный каналом, кроме счёта без адресованного месту (`../shared/quietframe.ts`; при id inbox — когда ход его взял, `session.inbox.delivered`; взятие, услышанное до ответа промпта, ждёт его в книге `inbox.ts`), промпт без метки поставки — слово человека (его время живёт дольше хода: 30 минут консоль наблюдаема), завершённый говорящий вызов (хук `execute.after`), текст `session.text.ended` после последнего вызова (короткая строка без «?» — квитанция); на `session.execution.succeeded` (и устаревшем `session.idle`) ход кадра корня, потерявший слово, получает слово `TURN` в очередь — раз: освобождён ход, взявший inbox самого этого слова, а не следующий (тот может быть ходом ждущего кадра); слово без id inbox не освобождает ничего — его ход своего кадра не несёт. Обложка без `turn` в поле `rituals:` глушит его; обложки нет — включён (кадр доказывает место). Пробы — `opencode-turnend.test.mjs`, `rituals-turn.test.mjs`.
- `rites.ts` — ритуалы сессии по обложке репо каталога сессии (`../shared/ritualcover.ts`, граф @nks/nks-dev, #9319, раздел РИТУАЛЫ): слово старта `PREPARE` (или раннего входа `RITES`, пока обложка называет только граф) первому промпту корня, отказ `execute.before` записи в локальную память (`../shared/memorypath.ts`), строки пуша и мержа `RITES` после вызова оболочки по исходу (`../shared/ritualjudge.ts`; пуш в ствол — слово мержа, #8362), одна на id вызова поперёк экземпляров; свой плагин ритуалов в `.opencode/plugins/` глушит модуль в этом репо, ритуал вне поля `rituals:` обложки молчит. Пробы — `rituals-delivery.test.mjs`, `rituals-optout.test.mjs`.
- `onboardstart.ts` — первый промпт корня: признаки репозитория каталога сессии (`../shared/reposigns.ts`, харнесс `opencode`); ни одного из трёх — одна строка `ONBOARD_START`, иначе и вне git-репозитория — тишина. Только локальное чтение: ни вызова графа, ни моста, ни места. Один раз на читаемую корневую сессию; ребёнок, нечитаемая сессия и стоп молчат. Порядок слов посадка → приглашение. Пробы — `onboarding start` в `opencode.test.mjs`, совместный старт в `onboardstart.test.mjs`; serve — `scripts/rootseat-run-opencode.mjs --onboarding=fresh|partial|outside` (без платной модели).
- `service.ts` — вызов через слот держит его занятым и освежает простой.
- Половина «тулы»: `tools.ts` — мост на сессию; `half.ts` — её вход для `plugin.ts` и пустая форма; `slot.ts` — мост одной сессии; `bridge-io.ts` — поиск моста, кэш тулов, рукопожатие; `firstlist.ts` — первый список тулов с сервера в фоне; без кэша setup ждёт его до предела, вход человека или неудачный первый список обрывают ожидание (#8742); `host.ts` — что OpenCode говорит о себе; `login.ts`, `devicewait.ts` — вход человека; `status.ts` — текст `iskron_bridge`; `skillread.ts` — чтение файлов скиллов поставки вне рабочей копии.
- Слух и места: `keep.ts` — слух переживает простой, перезапуск и вытеснение; `keepalive.ts` — место держит каталог загруженным; `marker.ts`, `records.ts`, `adopt.ts`, `procstart.ts` — маркер потери и возврат мест; `moves.ts`, `handoff.ts` — перенос сессии между папками; `twins.ts` — экземпляры на два написания одного каталога; `putdown.ts` — слово мосту корня перед остановкой: `end` удалённой сессии, `away` перезагрузки и переноса (#7493); `rootseat.ts` — корень выровненного проекта пытается встать по обложке `AGENTS.md` (`../shared/cover.ts`) до первого модельного запроса: своё место с диска, иначе служебный stand на роль; первый промпт ждёт не дольше срока и сообщает действительное удержание или отказ, поздний исход входит вторым словом через канал, повисшая посадка отпускает очередь по потолку; `rootseat-by.ts` — stand и строгое сличение с обложкой: rN против другого написания разрешает мост сессии (`method("realm")`, `../bridge/realmask.ts`, #8191), неразрешённый rN остаётся несличённым и не отменяет факта удержания; `rootseat-tools.ts` — срок жизни попытки и доказательство из ответа моста; `rootseat-attempt.ts` — одна попытка: обложка каталога, затем stand через очередь экземпляра; `rootseat-doors.ts` — договор посадки с плагином и сроки; `rootseat-say.ts` — слова посадки и выбор слова по исходу; `rootseat-start.ts` — сторона плагина: хук тулов и одно слово старта на промпт; `rootseat-again.ts` — внутри git-репозитория (`repoRoot`, вердикт не `outside`; принадлежность проверяется до любого дефекта) корень с дефектной обложкой или без `AGENTS.md` получает слово выровнять скиллом `iskronify` и ждёт выравнивания в той же сессии. Дефект здесь — нет файла, нет фронтматтера или слота, граф или роль не читаются или неоднозначны; номер контракта плагин не сверяет — это делает сам `AGENTS.md` («Держи этот файл честным») и хук старта, однозначная обложка старого контракта садится. После каждого тула экземпляра (хук `execute.after`) — дешёвый stat файла обложки, на каждом промпте корня — перечтение; стала однозначной — одна посадка тем же путём; хук тула и промпт, пришедший во время неё, ждут её в пределах срока посадки, слово «встал» (или «не уложилась») даёт один из них — steer в идущий ход (`leaddoors.ts` teller) или на этом промпте; новая причина — её слово один раз; явный stand за это время — только сличение; стоп, удаление, выгрузка — ожидание снято. При приглашении онбординга на том же промпте слово выравнивания не даётся — одно слово. Вне репозитория — как раньше: нет `AGENTS.md` — тишина, дефектный — «не посажена» с причиной, без ожидания, верный — первичная автопосадка. Пробы — `rootseat-realign*.test.mjs`, `rootseat-outside.test.mjs`.
- Дочерние сессии: `satellite.ts` — спутник места корня; `children.ts` — мосты детей и возврат ведущего; `leads.ts`, `leaddoors.ts`, `leadwords.ts` — ведущий субагент (договор и двери к OpenCode, доступ к словам слоя; принятый выход из дела переживает остановку плагина — маркер несёт его, следующий экземпляр заканчивает поручение, №1317); `casesleft.ts` — последнее ли дело покинул ведущий: слово платформы (`iskron_case` mine мостом ребёнка), не свой учёт (#7234); `release.ts` — revoke запустившего: после конца ребёнка снятие места на платформе мостом запустившего (#7505); `leadends.ts` — кончившиеся ведущие: реестр процесса на globalThis и запись на диске (`opencode-ended.*`), их видят все экземпляры и следующий после перезагрузки, снимает новое явное занятие места (#7505, #4266); `leadframes.ts` — кадры ведущего: кончившемуся ничего, слово запустившего (непосредственного родителя-сессии и его места) — в идущий ход; `launch.ts` — строка запуска с делом; `runends.ts` — кончившиеся дети; `cascade.ts` — отмена хода родителя; `notice.ts` — родное уведомление о субагенте; `waits.ts` — ребёнок, которого родитель не слышит, — только ребёнок, которого держит этот экземпляр (#6815 п.7).
- Слова плагина — в слое поставки (`js/delivery/words/opencode.ts`, `opencode-keep.ts`, `leads.ts`, `plugin.ts`), на языке сессии (`shared/lang.ts`); ядро текстов и имени продукта не несёт (#6806).
- Половина «канал»: `channel.ts` — кадры стояния в сессию промптом, пачки дела; `tacts.ts` — такт внимания ждёт конца занятого хода последним (#6569); `lifecheck.ts` — побудка о живости: отдельным промптом в очередь корня, текст платформы и строка хода ответа; место дочерней сессии ребёнка не будит — корню строка о нём с вызовом revoke (дело №1046); `cuts.ts` — прерывание хода остановленной сессии с повторами и его исход, который мост ждёт для ответа на приказ останова (`iskron/halted`); `cutwait.ts` — исходы прерываний и родословные экземпляров в реестре процесса: подтверждение ждёт сессию и всех её потомков, кто бы их ни прерывал, и перечитывает их, пока набор не устоится (#7510); потолок подтверждения и остановка экземпляра снимают его ожидания из реестра; `halts.ts` — остановленная снятием места сессия и все её потомки (по цепочке родителей) не получают слов канала до явного занятия места, их ходы прерваны (#7439, #7440); место, погашенное за молчание (`revoked:silent`), останавливает только свою сессию — живой потомок отвечает за себя сам (дело №1046); остановка лежит на диске рядом с маркерами (`opencode-stopped.*`) вместе со словом стопа для контекста её ходов (#7585) — её читают все экземпляры и следующий после перезагрузки, места-спутники потомков снимает экземпляр, где они стоят.
- `compaction.ts` — возврат роли после сжатия контекста: хук `compaction` кладёт в system наказ сводке сохранить роль, место, живые дела и перечитать дверь и метит поколение сжатия. `context` сначала ждёт личные правила, затем заново проверяет поколение, место и остановку и синхронно вкладывает полный блок в system и снимает метку — одна выдача даже при одновременных context, без слова в inbox. Временно отсутствующее место сохраняет метку; отказ чтения не оставляет частичного system и позволяет свежую попытку. `session.compaction.failed`, удаление и наблюдённая остановка отменяют поколение, включая ожидающие context (#10112). Это свидетельство вложения system, не доставки провайдеру, чтения или исполнения моделью. Хук `compaction` начинает чтение правил человека мостом сессии служебным ходом (`mindslice.ts`, #9817); те же правила — рядом со словом посадки корня по обложке (её stand служебный, ответ модель не читает) и в слове запуска ребёнка из ответа его stand (`../shared/launch.ts`). Пробы — `opencode-compaction.test.mjs` (в том числе фабрика из собранного бандла с подставными дверями), `opencode-mindslice.test.mjs`; настоящий serve со сценарным провайдером — `scripts/compaction-run-opencode.mjs` (`--negative` — для сборки без возврата роли).
- `commands.ts` — скиллы поставки в палитре «/»; `usage.ts` — расход сессии в attrs места; `models.ts` — модель сессии от харнесса для места-спутника (#7591); `pulse.ts` — слово сессии о ходе мосту для кадра живости места (act_at — события тулов, текста, reasoning, shell и конца шага своей сессии, delta тоже; линия — `../shared/pulseword.ts`), `inbox.ts` — какие inbox-элементы сессии он ждёт для read_at.

Пробы — `js/tests/opencode.test.mjs`, `opencode-siblings.test.mjs` (соседние спутники) и `opencode-lineage-stop.test.mjs` (останов рода), `opencode-compaction.test.mjs` (возврат роли после сжатия) — все `make test-opencode`; наводка на старую сборку — `ISKRON_OPENCODE_PLUGIN`.

`stopped.order` отличает полный приказ от снятия места (#9256): снятие прерывает ход и запрещает возврат, но не архивирует сессию и не завершает клиент. Прямой PID-путь ждёт архивирования, наблюдённого через `session.get`, и выхода однозначно связанного клиента. Только для своего Run/Orca bridge может после подтверждённого interrupt/drop завершить точный handle без успешного archive, явно назвав этот потолок. `host.ts` сериализует archive/unarchive, `client.ts` перепроверяет PID с временем рождения и наблюдает выход; SIGTERM без выхода не подтверждается. Явное занятие отменяет лишь устаревшее поколение останова. Ручной bare-TUI без привязки остаётся открытым, история сохраняется. `scoped stop` в `opencode.test.mjs` проверяет отказы и гонку stand/archive; `scripts/probe-stop-lifecycle.mjs`, `check-stop-scoped.mjs` (строгая архивная заявка) и `check-stop-orca.mjs` (отдельная цель своего Run) — LOCAL-носители с настоящим клиентом. Исходный критерий bare-TUI ими не заменяется.

Архивная очередь и отметка начатого archive общие для экземпляров процесса: новое явное занятие в другом каталоге не позволяет старому update переархивировать сессию или старому pending close завершить клиент. Отказ наблюдателя PID не считается наблюдённым выходом. Пробы — `scoped stop: stand in another instance` и `bound client unreadable`.

Автопосадка подчиняется стопу владельца (`halts.ts`, в том числе записи на диске и стопу предка): ни stand, ни слова посадки; слово стопа даёт context-хук. `forget` и выгрузка отменяют очередь и подавляют позднее слово. `rootseat-tools.ts` держит срок жизни её моста: уже отправленный connect не обрывается, после ответа место снимается штатным `channel revoke`, затем мост закрывается. Отказ/таймаут снятия — явная ошибка; при недостижимом сервере место может дожить до серверного простоя. Остановленный экземпляр и удалённая сессия не создают новых слотов. Служебный held не снимает стоп. Пробы: `rootseat-safety.test.mjs` и P1/P2 в `rootseat.test.mjs`.

Предварительность для слова — только положительный признак `provisional` от обслуживающего моста: `held`, структурированный ответ stand или resume/check. Запись на диске не доказывает, что старый демон понимает правило замены. Нет признака — слово своего места с take. Реальное написание графа при отсутствии held.place читается из записи той же сессии/ключа; нет записи — граф неизвестен, санированный ключ графом не становится. При несовпадении с обложкой или несличённом rN слово всё равно называет удерживаемое место, роль/граф и take либо revoke, не говорит «не посажена». Сличение — точный полный адрес либо полный slug-компонент, без суффиксов внутри имени. Неизвестный каталог сессии не подменяется домом экземпляра: посадки нет. Пробы — `rootseat-review.test.mjs`; смешанный живой прогон — `ISKRON_BRIDGE_PATH=<старый мост без признака> node scripts/rootseat-run-opencode.mjs --legacy-bridge --keep`.

Автопосадка начинается только из первого prompt-хука, не из `session.created`. `ISKRON_ROOT_SEAT=0` отключает её для служебного headless run; окружение должно дойти до процесса сервера (для `opencode run` — с `--standalone`). Происхождение отдельного корня без parentID надёжно не определяется, по TTY/имени/модели оно не угадывается. После свежего успешного stand разрешённый мостом граф — из его ответа; вернувшееся с диска место само по себе соответствия rN/слага не доказывает. Пробы — `rootseat.test.mjs`, `cover.test.mjs`; настоящий serve с локальным сценарным провайдером — `scripts/rootseat-run-opencode.mjs`.
