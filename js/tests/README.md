# js/tests — нижние поведенческие пробы

Общий запуск — `make test`, сборка и полный гейт — в корневом `AGENTS.md`.
`built.mjs` называет dev-выходы; переменная `ISKRON_BRIDGE_PATH` выбирает другой
носитель там, где это поддерживает конкретная проба. Исходные `.ts` импорты
проверяют модуль, а не автоматически весь собранный вход.

`opencode-real-bridges.test.mjs` — пять проб настоящих мостов: снятие спутника,
подтверждение снятия, модель дочерней сессии и одно имя в двух графах.
Они используют `opencode-kit.mjs` и `fake-nks.mjs`, но отдельный процесс и каталог
набора; вынесены из `opencode.test.mjs`, чтобы не исчерпывать его бюджет coverage.

`opencode-package-bridge.test.mjs` — выбор файла моста env → рядом с плагином → home, пропуск отсутствующих файлов и каталогов, отказ без кандидатов. Носитель — собранный плагин; `ISKRON_OPENCODE_PLUGIN` выбирает прежний плагин для отрицательного контроля. Контекст OpenCode и мост подставные: загрузку настоящим харнесом эта проба не удостоверяет.
`opencode-package.test.mjs` — настоящий `npm pack`, ровно три файла, побайтная сверка после распаковки, версия/тег и запрет перезаписи. `node scripts/probe-opencode-package.mjs <свежий-каталог> [--directory | --url <[@scope/name@]http(s) specifier>]` — настоящий OpenCode со своим HOME/XDG/PATH без Node и домашнего моста, подставной PAT/MCP и сценарный провайдер; по умолчанию fixture HTTP tgz, `--url` берёт спецификатор дословно (после тега — HTTPS-ссылка релиза, качает загрузчик). Журналы и outcome сохраняются в заданном каталоге. Это не приёмка живого графа или публикации GitHub asset.

Новый exec-путь:

- `orchestra-exec.test.mjs` — явная схема и занятые лимиты, непрозрачные model-token.
- `orchestra-exec-path.test.mjs` — API-create/бриф → helper из dev-сборки → exec
  с тем же session → сохранённый exit → обычный stop, плюс отказы и неизвестность.
  `exec-fixture.mjs`, `exec-fake-orca.mjs`, `exec-test-env.mjs` — собственные fake Orca/OpenCode/API и их частное окружение;
  никаких пользовательских терминалов, моделей или credentials.
- `exec-receipt.test.mjs`, `exec-prepare.test.mjs` — защищённый файл, фазы до
  внешних действий, запрет второго prepare и неоднозначный исход без повторения.
  `exec-receipt-fixture.mjs` — частный каталог каждой пробы.
- `orchestra-exec-watch.test.mjs` — настоящий планировщик сервиса продолжает наблюдать своего клиента при выключенном автоматическом подъёме; внешние поверхности остаются подставными.
- `orchestra-exec-state.test.mjs` и `orchestra-runs-delta.test.mjs` — reload,
  лимиты, stale merge и замена identity без наследования чужого выхода.

Потолок: подставные поверхности проверяют нижнюю механику. Живые claim/join,
авторизацию окружения Orca и quiet quit они не принимают.

`exec-raised.test.mjs` проверяет отдельный raised-only курсор наблюдателя:
привязка до продвижения, следующий since и отказ при испорченном файле.
