# Подготовительный прибор трёх плеч

Постановка: граф `@nks/nks-dev`, #10139 v8 → `derived_from` #7616 и #6712;
#10136 `contains` #10139. Флаги: #10087 и #10134. Предел расхода: #7685.
Это **подготовка**, без запуска моделей, входов, посева в API и самоприёмки.

```sh
node --test scripts/three-arms/instrument.test.mjs
node --test scripts/three-arms/score.test.mjs
node scripts/three-arms/preflight.mjs inspect
node scripts/three-arms/preflight.mjs freeze scripts/three-arms/frozen-score-v8.json
```

`freeze` создаёт файл исключительно (`wx`): существующий не заменяет. Хеш SHA-256
считает точные байты перечисленных файлов с длинами имён и содержимого, не сериализацию
разобранного JSON. Перед первым модельным вызовом родитель сопоставляет свежий `inspect`
с зафиксированным хешем и предъявляет его #2270. Изменение после фиксации требует новой
сверки, не тихой замены. Команды `run`/`live` отсутствуют намеренно.
Прежний `frozen.json` сохранён как прежняя фиксация: его хеш недействует для запуска.
`frozen-score-v8.json` — промежуточная фиксация счёта, **не пусковая**: родитель
собирает новую после интеграции ограды.

## Разделение входов

- `scene.json`: посев четырёх предметов и двенадцать последовательных событий. По одному
  ответу основного агента до следующего события; D05/D06 — отдельный спутник со своим
  мостом и возвратом ссылки, не скриптовый ответ от его имени. Подача собеседников и
  человека — скриптовая, с пометкой scripted и настоящим principal, не поддельным user.
- `oracle.json`: двенадцать вопросов и независимые эталоны/правила суда. Не монтировать
  испытуемому и читателю. Для двух самостоятельных решений спутника заранее фиксируется
  **правило и допустимые варианты**: состоявшийся выбор и его основание извлекаются
  только из **журнала дела**, до суда над ответами читателя, не из графа и не из
  отчёта агента. Выбор за спутника не сделан; варианты не изменены. Эталон не принимает
  произвольный ответ основного агента как правильный.
- Читатель получает только вопросы и свой доступ к графу. Судья получает эталон,
  ответ читателя и полный обезличенный след; не получает флаг/имя плеча, ревизию,
  путь или временные метки, раскрывающие плечо. Карта нейтральных меток вне пакета.

Модель испытуемого: `anthropic/claude-opus-5-5`; читатель/судья:
`openai/gpt-6.1-sol`. Три плеча × три процесса = ровно девять, без trial/запасных.
Старт фиксируется до создания процесса, любой исход тратит слот; сорванный прогон
не eligible/scored и автоматически не повторяется. На процесс испытуемого 3 млн
входных с cache read/creation и 80 тыс. выходных; на всю пробу 30 млн входных,
включая вспомогательные процессы. Будущий адаптер должен учитывать их явно.

## Что переиспользовано и что проверяется

`reader.mjs` использует HTTP-путь и отмену существующего `stand-mcp-ledger.mjs`.
Единственное расширение того прибора — необязательное правило доступа **до** forwarding.
Оно отказывает всем `iskron_case`, пишущим вызовам и чужому realm; пропускает четыре
читающих тула графа. Это настоящий HTTP-отказ в немодельной пробе, а не запрет в брифе.
**Это не изоляция модели:** прямой API, файловый доступ к ключам и иные сетевые пути
должны закрываться отдельными правами/процессной границей. Пока этого нет — стоп.

`guard.mjs` резервирует совокупный расход до запроса. Проба убивает собственный
IPC-child с синтетическим loopback-провайдером до третьего POST; отсутствующий usage
не освобождает резерв, ошибка/повтор не дают новый бюджет. Реальный Opus отвергается
с `no upper-bound basis`: синтетическое равенство байтов и токенов не переносится
на модель. Нет запускающего кода, который мог бы превратить этот макет в разрешение.

`controls.json` — положительные и отрицательные образцы флагов, не результаты.
Точная форма запроса/схемы заимствуется из наблюдаемой API 0.180.0; адаптера вызовов
здесь пока нет. Не угадывать серверные маршруты по названиям образцов.

## Остаток до первого вызова — всё ещё стоп

1. Отдельный LAB/собственный run, bearer-only граница, свой scoped PAT после сверки;
   никаких домашних конфигов, Orca или учёток другого человека.
2. Посев одним атомарным batch с символическими ключами → настоящие ссылки; connect,
   register, затем дело; одинаковая поставка и сценарий во всех плечах. В этом репо
   прежний `run-cell` не найден. Существующие frames-consumer/stand приборы не заменяют его.
3. Сырые образцы обоих флагов на том же сервере, включая получение адресного кадра.
   Успех API-записи сам по себе не доказывает доставку.
4. Настоящий отказ дела читателю с невозможностью обхода. Имеющийся HTTP-policy
   проверен только против подставного upstream; LAB/API-права ещё не проверены.
5. Строгая ограда реального модельного расхода и включение в супервизор всех дочерних
   процессов. Сейчас есть только синтетическая проба и надёжный отказ реальному basis.
6. Необработанные журналы сервера и моста и наблюдаемая схема для счёта: вызовы/решение,
   пустые версии, no_node, короткие цепочки, ложные отказы. Старый ledger пишет только
   initialize/delete, proxy — метаданные, frames-consumer — кадры: ни один не даёт весь
   этот счёт. Не извлекать недостающее из report. Секреты вырезать **до** файла/вывода.
7. Принятое правило — `outcome-rule.json`, реализация — `score.mjs`, оба входят в хеш.
   Границы №4375 [9] исправлены по #10139 v8 и №4375 [11]: при двух вторичные — худшие.
   Окончательной интегрированной заморозки ещё нет.
   Родитель явно разрешает девять запусков отдельным поручением; эта поставка
   разрешением не является.

## Холодный счёт — только явный пакет, не сборщик

`node scripts/three-arms/score.mjs PACKET.json` печатает JSON, exit 0 при корректной
схеме (в том числе «не различено»), exit 1 при отказе схемы/чтения. Чистый экспорт:
`score(packet)`. Не импортирует oracle, не обращается к API, не судит ответы модели.
Сборщик этих первичных данных **ещё не реализован**. Пакет предназначен только для
холодного счёта; не отдавать его, oracle или полный каталог испытуемому/читателю.

Схема 1 (неизвестные поля отвергаются, карта меток плеч остаётся вне пакета):
- Корень `{schema:1, arms:[{label,runs}]}`: три нейтральные метки, ровно три слота
  на метку, уникальные id прогонов; никаких запасных/повторных слотов.
- Прогон `{id,status,decisions,calls,traversals}`; status — `completed`,
  `guard-stopped` или `infrastructure-invalid`. Всегда 12 решений D01–D12,
  включая явно несостоявшиеся, а не только успешные.
- Решение `{id,occurrence,judgement}`: occurrence — ссылка на первичную запись
  `{source:"case-journal",entry,version}` либо `null`, если решения не было.
  Для спутника именно эта запись несёт извлечённый выбор, не граф.
- judgement — `{label,evidence,node}`; label — `found-with-node`,
  `found-without-node`, `not-found`; evidence — `{source:"cold-judgement",entry,version}`.
  node — `{id,version}` для `found-with-node`, иначе `null`.
  judgement допускает `null` при несостоявшемся решении или исключённом прогоне,
  где холодное чтение не состоялось: фиктивного суда не требуется.
- calls — **все** записи вызовов `{source,entry,version,decision}`, с D01–D12;
  traversals — **все** записи обходов `{source,entry,version}`. Источник — `server`
  или `bridge`, entry — уникальный идентификатор события внутри списка, version —
  положительное целое. Нельзя выдать один вызов дважды как server и bridge:
  дедупликация между источниками — обязанность будущего сборщика.
  Нулевой счёт — явный пустой список, не пропущенные данные.
  Все идентификаторы обезличены (`A-Za-z0-9_.:-`, до 128 знаков), версии положительны.

Мера k — медиана целых, при двух — меньшее; разброс max−min. При r>Δ пара
не различена, при Δ≥3 и r≤1 решает большее k. Иначе вторичные медианы целых:
calls/12 (порог выигрыша 20% от большего), общее число обходов (меньше хотя бы
на один). При двух вторичные — худшие (большее). Выигрыш одной без повышения
другой, при k не ниже; равенство/конфликт — без выбора. 0/0 вызовов — равенство,
0 против положительного — выигрыш 100%, сравнение без деления на ноль.
Несостоявшееся решение не выжило; >2 делают прогон нецелым. При <2 целых
плечо не сравнивается. Общий победитель обязан выиграть обе пары.

Ссылки на первичные записи и версии обязательны; их подлинность, полнота журналов,
правильность холодного суда и независимость доступа здесь **не удостоверяются**.
Пустые версии, no_node, короткие цепочки и ложные отказы этим модулем не собираются.

Немодельные тесты — нижняя ступень, не свидетельство поведения живого API/модели.
`make check`, full/live не запускались. Всё оставшееся предъявляется родителю,
не подменяется `PASS`/нулём/самостоятельным принятием.
